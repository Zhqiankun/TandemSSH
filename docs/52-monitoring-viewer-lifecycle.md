# 监控查看者与等待连接的生命周期

本阶段继续 B02/B12/A35：每个窗口持有自己的查看会话 ID，关闭只释放该查看者；心跳/注销核对用户与主机；最后一个可用查看者退出后停止采集。等待指纹、代理、DNS 或二次认证期间的监控连接也必须能取消。

主智能体独立实施。`metrics/pending-connections.ts` 只拥有尚未交给监控会话的连接资源和取消信号；`sessions.ts` 负责已建立 SSH 会话与待二次认证状态；`index.ts` 与 Proxmox 轮询器负责查看者引用计数和采样用户选择；`viewer-routes.ts` 传递认证用户并映射权限错误；UI 的每次连接尝试有独立查看 ID，关闭/隐藏/重试释放这一 ID。连接等待资源不能进入通用共享模块，监控不会取得交互终端的控制权。

验证重点：同一用户两个窗口、不同用户共享主机、伪造心跳/注销、首个查看者退出后剩余查看者继续、等待连接时取消及迟到结果回收。真实 SSH/HTTP 和中文桌面验证，继续原始全部 F/B/R/A 范围。

## 已实施边界与验证

窗口先生成查看 ID，再发起启动请求；等待期间关闭也能按 ID 取消。已建立连接复用时仍登记新的查看者；心跳和注销检查当前请求用户，错误的主机或用户不能删除查看者。同用户另一窗口还在查看时不会关闭共享监控连接；最后查看者离开后停止采样。轮询从剩余未暂停查看者中选择实际用户，并在迟到连接进入采集前再次核对配置与查看者。

等待连接的注册表区分窗口与后台采样，取消后台等待不取消其他窗口。没有现成监控会话的后台单批连接在批次结束后关闭，不进入其他管理功能/Proxmox 使用的连接池。初次连接、DNS/代理、跳板和指纹阶段使用同一取消信号；OTP 阶段保留原有 180 秒输入窗口，取消后旧挑战不能继续提交。跳板参数增加可选 AbortSignal，未传信号的既有调用保留原调用契约；同时修正异步 Promise executor 错误不能正常结束的路径。

已建立会话的清理记录其预期 Client，旧采样或旧超时不能关闭新建的同名会话。关闭通知也不会把失效客户端继续标为可复用。
