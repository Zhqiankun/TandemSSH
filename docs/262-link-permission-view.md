# 链接自身属性中的权限位不再隐式修改目标

2026-09-13，A34 检查中的界面修复。

## 问题

PermissionsDialog 可对 type=link 的列表项编辑权限；列表显示的是链接自身 mode（常见 lrwxrwxrwx），而既有后端 chmod 调用会跟随最终链接修改目标。界面值与实际作用对象不一致，可能把链接的 0777 当作目标当前权限。

新增中文组件测试在修复前确认“保存”仍可点击。

## 本轮修改

链接自身属性框的普通权限位、特殊位和权限保存只读，提交处理也拒绝该 UI 操作。新增中英文及繁体中文说明：此处显示链接自身属性；目标权限应打开目标所在目录后修改；所有者/组修改作用于链接自身。

独立 OwnershipEditor 仍可使用，后端既有 chown -h 语义不变。普通文件与目录权限编辑不变。

生产责任限于 PermissionsDialog 的显示和提交编排；没有新增后端接口、共享抽象或依赖变化。其他语言使用新增英文回退文案。

## 验证及限制

权限与所有者编辑器 2 文件、10 项通过，覆盖链接保存禁止、全部权限控件只读、所有者保存仍可用，以及既有目录特殊位和未知权限保护。TypeScript、ESLint 通过，静态翻译键缺失 0。

这是 UI 防止误操作修复，不声称后端 changePermissions API 已禁止跟随链接，也不声称解决外部进程在检查后替换链接的竞争。后端目标约束及最新桌面交互仍需继续核对，A34 保持未完全验证。

当前桌面包尚未包含本轮 UI 修改。未提交、推送或发布。
