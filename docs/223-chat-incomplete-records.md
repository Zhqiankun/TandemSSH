# 普通聊天失败与中断记录

## 行为

聊天模型报错或 HTTP 客户端在接收过程中断开时，已收到的文字和已完成的内部消息保留为未完成记录。历史界面显示“本轮回复失败/已中断，以下内容未完成，不会自动重放”。成功回复继续按原保存顺序完成。

未完成记录不会展开为后续模型历史，避免把部分回复当成成功结果，或自动重放没有对应结果的工具调用。记录不自动重试操作。用户消息和失败片段仍可在历史中查看。

## 模块责任

- `backend/ai/chat-history.ts` 扩展现有 version=1 信封的可选 outcome（failed/interrupted），统一解析、界面状态投影和模型历史排除。
- `backend/ai/index.ts` 记录实际已流出的文字，在模型错误或生成器退出的 finally 中保存一次；保存尝试前置一次性标记，不在写入结果不确定时盲目重复插入。完成模型回复的正常写入保持独立。
- 历史 API 增加可选 outcome；前端 AiPanel 只传递状态，AiMessage 渲染提示。原有文本与旧工具数组记录默认没有该状态。
- 英文、简体中文、繁体中文提示已提供，其他语言键使用英文兜底。没有数据库列迁移、通用共享抽象或工具权限变更。

仍应用既有 React 技能约束：不在渲染中请求历史，不引入额外全局订阅，显示组件不解析后端私有信封。

## 验证

真实 Express HTTP/SSE：模型错误保存 failed 记录且不发送 done；客户端读取到中文 token 后实际中断 fetch，等待生成器停止，恰好保存一个 interrupted 记录，文字一致。两个记录均不被 restoreChatHistory 回放。

中文组件测试：失败/中断提示与正文并存，成功回复无未完成提示。历史列表普通分支与末条回复分支均传递 outcome。

AI 前后端全组 **29 文件、190 项通过**；TypeScript、修改文件 ESLint 通过；字面翻译调用缺键为 0。

## 限制

本轮 HTTP 仓储使用测试替身，尚未以实际 SQLite 和打包桌面重启证明完整链路。窗口关闭后的历史刷新与跨请求并发仍需继续验证；进程被直接终止、机器断电不能靠 finally 保证保存。普通聊天仍有全局资源上限等未完项，R06/F05/F06/A23 不标为完成。

空内容且没有内部消息的失败目前不新增空白助手记录。新状态记录不保证旧版降级读取；当前版本兼容既有记录。此改动尚未发布安装包。
