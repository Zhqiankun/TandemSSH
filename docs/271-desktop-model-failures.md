# A23：模型故障与人工 SSH 桌面验收

2026-09-13。

原始 A23：模型 Key 错误/无工具能力/限流，明确报错，保留人工 SSH 功能。

## 环境与八场景

重新 build/打包当前本地 Windows 目录包，包含 270 的安全错误分类；连接隔离 Alpine OpenSSH。模型为本机 HTTP 服务夹具，不调用商业模型或使用真实付费 Key。

报告 .cache/desktop-observation-report-3b60a547-7e17-4aeb-bb5f-9f90252a776a。

自动与协作模式分别运行：401、403、429、仅返回文字不产生工具调用，共八场景。HTTP 错误正文故意包含 PROVIDER_PRIVATE_DETAIL 与虚构测试 Key，用于验证不透传。

- 401/403：MODEL_AUTH_FAILED，中文说明检查认证/访问和模型权限，不把 403 武断当成拼写错误。
- 429：MODEL_RATE_LIMITED，中文限流/额度提示。
- 只有文字：先展示计划，人工授权后模型仍仅返回文字，MODEL_NO_ACTION 明确说明未执行远端命令，而非把说明当执行成功。

全部场景进入 paused-error，操作列表为空，界面不包含测试私密错误正文或 Key。模型请求共 10 次：六个 HTTP 故障各一次，两个无工具场景各两次；观察窗口内没有自动重试。

每个场景之后，在原 SSH 终端通过真实键盘输入 printf 构造独立 MANUAL_CHECK 标记，并从同一会话 read_terminal 读取实际输出，证明人工 SSH 仍可执行。随后仅为清理测试任务显式调用 stop，不把清理描述为产品自动取消。

## 可见性与结果

model-errors-result.json 已读取，八项结果均通过；model-calls.jsonl 请求次数为 10。实际查看 401-automatic、429-collaborative、no-tools-collaborative 三张代表截图：中文原因、暂停状态和人工控制权可见，无弹窗遮挡。

客户端正常退出，后台端口释放，本机模型服务关闭。独立 Linux 实例随后由工具关闭。

## 归并边界

结合 270 的生产适配端口分类/隐私测试和既有 provider HTTP 与任务循环测试，A23 标记 verified。无工具场景验证的是“服务只返回文字且没有执行动作”的可观察处理，不声称能从一次回复证明某个商业模型永远没有工具能力。

普通聊天容量/并发、模型配置完整功能及 R06/F05/F06 等要求继续由各自原始项目验收，不能因 A23 收尾而一起标记完成。
