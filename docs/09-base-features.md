# 基础 SSH 与文件工作台

状态：v0.2 首版需求细化。用户要求上传、下载、在线编辑及完整基础能力，并结合 FinalShell、XTerminal。

## 2. 工作台组织

```text
左侧：连接分组 / 收藏 / 最近 / 快捷命令
中间上部：终端标签与分屏
中间下部：本地文件 ⇄ 远端文件 / 在线编辑器
右侧：AI 任务 / 服务器状态（可切换和折叠）
底部：传输队列 / 执行时间线 / 规则命中 / 连接诊断
```

文件工作区绑定确定的主机、用户和活跃连接。关闭终端标签不等于关闭共享 SSH 连接；文件编辑、传输和隧道仍有各自生命周期。最后一个消费者关闭后，才按连接策略释放连接。

界面固定显示当前文件所在服务器与完整路径，尤其是在两台服务器上打开同名配置文件时。

## 3. 上传与下载

选择文件或拖拽后，先固定来源、目标、目录映射和冲突策略，再建立传输清单。递归目录按文件和子目录逐项记录；单个失败不会被总进度掩盖。

文件/目录名作为路径数据处理，不拼接为未经编码的 Shell 字符串。本地 Windows 路径与远端 POSIX 路径分别规范化；远端文件名若不能在 Windows 上表示，提示改名或跳过，不静默覆盖同名文件。

上传优先写同目录临时文件，完整写入并检查后再提交；下载也先写本地临时文件。提交前再次检查覆盖前置条件。只在服务器支持的能力范围内称为原子替换；不能先删除原文件后仍宣称“安全保存”。

成功至少意味着全部计划字节写入、句柄正常关闭、目标检查符合预期。若没有进行内容校验，只显示“传输完成/校验未执行”，不宣称校验通过。用户可选择内容校验，远端不支持相关能力时明确展示成本或降级方式。

## 4. 暂停、恢复与重试

暂停在块边界停止后续发送/接收并保留检查点。检查点含两端路径、已传字节、源文件版本信息和连接身份；密码不进入检查点。

恢复前核实源文件、目标部分内容和主机身份未改变。大小相同不意味着内容相同；无法验证时要求从头重传或另存，不盲目追加。重连后的恢复需要重新授权，不能复用旧 generation 的批准。

取消后明确指出临时文件/部分文件是否仍存在，可清理的内容只限本次任务确实创建的路径。失败重试只处理用户选择的项，已经成功的项不重复覆盖。

## 5. 在线编辑

打开文件时读取内容及基线信息，建立绑定目标的 EditorDocument。编辑发生在本地草稿中，不把每次按键立即写入服务器。

保存流程：

1. 展示当前主机、路径、编码、换行和与基线的差异。
2. 经过路径/写入权限检查，检查是否存在冲突的 AI/流程写操作。
3. 重新读取远端版本信息，检测打开后是否被其他程序修改。
4. 写临时文件，保留应保留的权限/元数据，再执行支持的提交操作。
5. 返回实际结果和新基线；失败保留草稿，不显示“已保存”。

发现外部修改时提供三方差异（原始、远端最新、本地草稿）、重新加载、合并后保存和另存。强制覆盖是明确选择，不默认采用“最后写入获胜”。

mtime/size 与保存前摘要检查不能保证对外部并发写入具有原子 compare-and-swap。没有服务器端支持时，说明剩余竞态，不声称绝对不会覆盖外部改动。

保留原编码、BOM 和 LF/CRLF；无法无损编码时阻止静默保存并提示选择编码。UTF-8 为基本支持，GBK/UTF-16 等具体范围由 M0 确认。二进制、超大文件、正在快速增长的日志采用预览/下载或只读模式，不把整个文件无上限载入编辑器。

草稿恢复为本机能力，恢复后仍需重新确认远端基线。草稿可能含密码等配置内容：默认内存保存，持久化恢复必须加密；系统加密不可用时禁用落盘草稿而不写明文。

## 6. 删除、权限与特殊文件

删除前显示目标和影响项，递归删除与普通删除分开。没有已实现且验证的回收站时，标记为永久删除；不能承诺一定可撤销。

远端复制可能使用服务器扩展或 SFTP 读写。若需借助 cp/tar 等命令，必须显示为独立动作并经过命令规则，不从文件管理入口秘密绕过。

编辑符号链接时明确显示链接和实际目标，权限检查基于解析后的目标及其父目录；不能为保存方便直接把链接替换成普通文件。

权限修改显示旧值、新值和递归范围。SFTP 权限不足时返回明确错误，不自动执行 sudo、chmod 777 或修改所有者。高权限编辑另行预览授权，首版不要求无条件支持任意 sudo 文件操作。

## 7. 与 AI、流程和接管一致

- 人可以随时浏览和编辑本地草稿；远端保存才产生副作用。
- AI、MCP、流程和人工文件操作走相同文件用例，应用内对相同目标的提交需要互斥与版本检查。
- 冲突的自动写入存在时，人工保存先接管/暂停相关任务，不能相互覆盖。
- 接管阻止同一协作授权下新的自动文件操作；在途传输和已送出提交仍需取消或核实。
- AI 修改以差异预览呈现，不能因拥有终端权限就自动获得全部本地文件权限。
- 流程可组合“上传产物 → 执行命令 → 检查状态 → 下载结果”；每一步有独立操作 ID 和策略结果。

SFTP 使用 SSH 连接中的独立通道，不伪装成 PTY 输入；界面时间线仍完整显示文件操作。命令黑白名单与文件动作/路径规则分别判断。

## 8. 监控、隧道与基础连接

监控使用可查看的有限只读采集动作，显示采集时间、权限不足和不可用指标；不要求自动向服务器安装常驻 Agent。采集不会插入正在交互的终端，可使用同一认证连接的独立通道，并在活动记录中聚合显示。

进程结束、服务重启等有副作用的动作不属于“监控只读”，需单独授权和记录。定期只读采样可以聚合记录以避免刷屏，但命令模板和执行周期必须可检查。

隧道有独立启停授权、监听地址、目标地址与端口范围。默认本机回环监听；扩大监听范围需要明确选择，不能由 AI 默默创建面向所有网卡的端口。重连时显示隧道是否恢复，不能只显示 SSH 已连接。

SSH 配置导入只接受支持字段，不自动执行 ProxyCommand、LocalCommand 或任意启动脚本；不支持字段需列出。基础单跳与交互式认证列为首版，复杂多跳/厂商堡垒机兼容单独验证。

## 9. 首版验收

| 场景 | 通过条件 |
| --- | --- |
| 单文件、批量和递归目录双向传输 | 目标映射正确，成功/失败逐项可见 |
| 中文、空格、特殊字符、Windows 不可表示文件名 | 不产生额外命令或静默重名覆盖 |
| 中途断网再恢复 | 验证检查点，源或目标变化时拒绝盲目续传 |
| 多文件部分失败 | 整批结果准确，重试不会覆盖已成功项 |
| 保存时远端被修改 | 显示冲突并保留本地草稿 |
| 保存失败、磁盘满、权限不足 | 原文件保护状态明确，不能假成功 |
| 编码/BOM/LF/CRLF | 无损往返或明确要求转换，不静默损坏 |
| AI 改文件时人工接管 | 新自动写入停止，人工保存没有应用内竞态 |
| 关闭终端但仍有传输/编辑 | 连接不被提前释放，草稿不静默丢失 |
| 监控和隧道 | 只读/副作用分开、资源占用有界、关闭后资源释放 |

完整基础能力是公开 alpha 的门槛。底座已有实现也要复测，不能仅凭 README 宣布验收通过。
