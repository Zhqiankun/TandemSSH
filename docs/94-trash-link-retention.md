# 回收站保留与删除断链

2026-09-12，核对上轮跳过用例时发现：回收站使用 stat 判断对象存在，会跟随链接。相对链接移入回收站后目标可能暂时无法解析；旧逻辑会误判对象消失，在列出/永久删除时清理元数据却留下链接，影响恢复。恢复目标处的断链也不能被当成空路径。

修复只在 trash-service 的存在性判断使用 lstat，检查链接本身；仅 SFTP 的无此文件代码 2 或本机 ENOENT 视为不存在，权限及其他错误继续抛出，不据此覆盖或创建。递归删除仍由原有 lstat 区分目录与链接，不改回收站格式和路径命名。

Windows 测试改用目录联接验证目录链接语义，不依赖开发者模式；当前机器 11 项全部通过，无跳过。覆盖原有目标不被递归删除、断链可列出并恢复、永久删除确实移除链接实体、恢复不覆盖已有断链、权限错误不视为目标空缺。证据 .cache/trash-links-tests.log。类型及修改文件 ESLint 通过。

真实 Alpine/OpenSSH/SFTP 集成场景通过，869 毫秒：相对链接进入回收站后仍列出，恢复后解析到原目录；再次永久删除后只移除链接，目标 keep.txt 内容不变；原本就指向 missing 的链接也能列出并彻底删除。测试仅把 realpath(".") 定位到本次专属测试目录，其余操作使用真实 SFTP；不访问业务服务器或其他回收站。证据 .cache/trash-links-linux-results.json、.cache/trash-links-linux-tests.log。VM 40d80740-aa75-4ea0-b1d5-2f7d651ae385 正常关闭，管理进程退出 0。

这验证回收站服务与实际文件系统行为，不代替全部文件操作/批量失败界面验收。修复发生在 alpha.4 标签之后，不包含于本次 alpha.4 构建。
