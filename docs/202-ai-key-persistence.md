# 模型 API Key 首次持久化前加密

2026-09-12，核对 A16 时发现 AiRepository.createProvider 先将 input.apiKey 插入，再按生成的行 ID 加密更新；encryptApiKey 在缺少用户加密密钥时还直接返回明文。真实 SQLite BEFORE INSERT 触发器复现首次明文写入，另复现加密不可用/抛错时仍创建或更新，以及加密失败留下部分记录。

## 修复与边界

AiRepository 在首次 INSERT 前完成加密，使用现有 FieldCrypto 信封自带的唯一上下文（randomUUID），不再为取得自增 ID 先写明文。该信封本来就存储 recordId 并由解密器读取；更新继续支持数字行 ID 上下文，不改变底层加密算法和表结构，不新增事务或通用存储层。

缺少加密密钥时拒绝；加密抛错或返回非加密信封时拒绝。更新失败保持原记录。短于等于 6 字符的 Key 使用掩码，不把完整 Key 放入可见前缀。读取缺少加密访问或密文解密失败时明确拒绝，不把密文当 Key 发给提供方。

创建/更新 API 将加密失败映射为稳定 503 错误码，客户端保留该码并选择中文错误提示，失败保留编辑。其他错误沿用原路径。历史遗留明文行在有加密访问时仍兼容读取，以便明确轮换；本次不声称已清理历史明文或数据库日志残留，也未操作用户真实密钥数据。

## 实际验证

新建真实 SQLite 测试含拒绝明文首次 INSERT 的触发器。修复前 6 项中 5 项失败，修复后仓储 9 项、API 2 项、模型设置 4 项，共 15 项通过。覆盖首次密文、加密不可用/抛错、更新不变、加密失败无部分记录、无 Key 提供方、短 Key 掩码、解密失败、数字上下文轮换和跨用户读取拒绝。

API 测试确认两种写入保留加密错误码且不自动重试；设置测试使用翻译键模拟，证明选择正确错误键且保留编辑，不冒充真实中文桌面截图。ESLint、TypeScript、中文缺失键 0 的检查已通过；新增最终轮换用例的针对性回归通过。尚须重新完成 alpha.12 发布门禁。
