# 操作日志位置与按留存规则清理

2026-09-14。F14/B15核对发现已有脱敏导出与写入时自动留存，但没有明确目录展示和不依赖新日志写入的主动清理入口。本轮补齐，不将全部设置条目提前关闭。

## 功能与责任

AuditJournal统一拥有生成日志分片的扫描、留存删除、位置/占用信息查询。原写入流程复用同一prune算法；手动清理使用reserveBytes=0。三者都进入既有串行队列，不与写入交错修改当前分片状态。删除当前分片时清空缓存，后续写入重新生成文件。

仅匹配本程序生成名称的常规文件参与统计和清理；其他文件、符号链接保留。检查真实日志目录在当前数据根的预期用户目录，重定向目录拒绝。用户身份由既有可信UI路由解析，不接受请求传入用户、目录或文件路径；API Key客户端仍被整个路由的守卫拒绝。

历史窗口新增独立AuditStorage组件，展示当前用户日志位置（只读可复制）、文件数、占用与留存规则。“按留存规则清理”先显示范围说明，再经“确认清理”调用接口。只清过期/超量文件，不是清空所有审计。结果显示删除文件数和释放大小，清理后历史分页与选择清空并重新查询。请求失败显示无法确认，不假报成功。中英文同步。

组件只编排API和用户确认；Journal拥有文件策略；HTTP只鉴权、校验confirmed与返回。没有新增通用存储抽象，没有让界面选择任意待删除目录。
