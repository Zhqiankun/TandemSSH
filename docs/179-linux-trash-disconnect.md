## 故障注入边界

测试代理只在目标操作已经由服务器执行并确认后，主动 destroy 本次 SSH Client、向应用抑制成功应答并报告 SSH_CONNECTION_LOST；等待实际连接 close 后，建立全新的 SSH 连接进行恢复。这是精确应答边界的连接故障注入，不声称测试了物理断网、断电或任意丢包时序。

分别验证：
1. intent：恢复意图写入后切断，应用没有移动原文件；新连接列举不显示未发生的删除，独立连接读取原文件，65536 字节完全一致。
2. source：源文件移动完成后切断，记录仍为 pending；新连接列出该项、恢复原路径，内容完全一致。
3. publication：记录确认完成后切断，应用未收到成功；新连接从正常记录恢复，内容完全一致。

文件名包含中文、引号和换行。每个场景使用独立测试根目录；通过另一个独立 SSH/SFTP 连接核对内容，避免只依赖被测操作的返回值。
