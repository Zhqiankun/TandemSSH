# 文件批量撤销保留未确认项

2026-09-12。

问题：FileManager 的复制/移动撤销只要有一项成功，就使用 prev.slice(0, -1) 丢弃整批记录。部分失败时，失败项丢失；异步期间若加入另一批操作，还可能移除错误的最后一项。

实现：FileManager 只记录 API 已确认成功的回执，finally 使用文件管理领域内的 settleFileUndo 更新历史。该函数按原操作对象身份定位记录，只删除已确认回执，保留其余项及后来加入的记录。同步 ref 阻止重复点击同时启动撤销。没有引入通用共享层或反向依赖，UI 编排依赖文件历史模块，文件历史模块不依赖 UI/API。

验收：file-operation-history 与 file-batch 共 7 项测试通过，包括中间项失败保留、后续重试移除、后来加入的操作保留、等值但不同身份的回执不能冒充已完成、旧输入不可变。tsc -b 通过；ESLint 0 错误，FileManager 已有 windowId 未使用警告 1 项。

范围：这些是历史状态回归测试，并非完整 Windows 桌面文件撤销实机验收。撤销记录的会话生命周期、目录类型及远端文件在操作后被他人修改的处理还需要继续检查；不据本次测试将 B09 标记完成。公开 alpha.5 安装包尚不包含本次修改。
