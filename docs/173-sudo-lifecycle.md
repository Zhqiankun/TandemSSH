# sudo 通道有界等待与迟到回调保护

2026-09-12。文件管理 sudo 辅助执行原先没有等待上限，也没有在通道队列放行和密码发送前重新检查连接。已在 session.ts 的既有公开入口补齐生命周期。

execWithSudo/execWithSudoBuffer 增加可选的会话检查回调，旧调用者无需修改；删除路由传入原会话对象身份检查。辅助执行默认在队列放行及 SSH 通道协商完成后检查连接状态，调用者检查也在这两个阶段执行。任一阶段失败都不发送密码。

每次调用最多等待 60 秒，覆盖排队、通道协商和命令执行。排队中到期返回 SUDO_NOT_DISPATCHED；命令已派发后到期返回 SUDO_RESULT_UNKNOWN、空退出码，关闭本次通道。迟到回调只关闭通道，迟到成功不覆盖已结束结果；正常完成或失败清理定时器。stdout/stderr 分离和标准输入发送密码的契约保持。

超时关闭通道不能证明远端操作回滚或停止，调用者必须核对结果后再操作。原有删除失败凭据清理与不自动重试行为保持。此变更对使用该辅助入口的手工文件 sudo 操作施加 60 秒上限，不改变 AI/MCP 的权限网关。

## 验证

三个文件 37 项通过。sudo-lifecycle 使用实际 ChannelOpenSerializer、可控时间和延迟 SSH 回调，验证：
- 排队超时且稍后放行时 exec 和密码发送均为零。
- 协商迟到、活动通道超时分别关闭通道；迟到关闭成功仍为未知结果。
- 队列中断线或原会话被替换，不派发命令。
- 协商过程中连接变化，不发送密码。
- 正常完成清理定时器，不在之后误关闭通道。
