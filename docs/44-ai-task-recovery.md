# 内置 AI 任务跨重启恢复

2026-09-09，本阶段在已有独立任务恢复上接入内置 AI 的对话、模型预算、问题与工具轮次。父流程及目录/部分传输资源仍需各自游标恢复，不把普通 AI 重新建任务视为全部实现。

## 模块责任与依赖

主智能体负责设计、实现和验证。AiTaskCoordinator 拥有对话、模型请求、工具轮次、等待回答和模型预算；TaskRuntime 继续拥有任务、执行结果、控制与授权。恢复 Service 只协调一次性领取和落盘，存储只调用格式校验和原有系统加密。

复用已有 ChatMessage/ToolCall 的规范化格式，将定义放到 types/ai-conversation 并从旧 provider 类型入口重导出，保持适配器兼容。它属于 AI 领域，供模型适配器和恢复格式使用；不是通用 common。AI 恢复 schema 校验规范化对话、工具调用及预算，旧任务记录保持可读。

依赖方向：中文任务界面 → 可信人工恢复 HTTP → RecoveryService 的 AI 端口 → AiTaskCoordinator / TaskRuntime → 模型或执行器。TaskRuntime 通过已绑定的捕获回调获得 AI 附加状态，不依赖具体模型协调器。MCP 不领取内置 AI 的身份。

## 行为契约

保存先暂停新模型/工具调度、撤销原执行控制，再等待执行动作收敛。检查点包含已完成历史、被中断的模型响应、尚未返回的调用标记、问题/已收到的回答和累计模型轮次。保存失败保留暂停任务和用户回答，成功才停止旧协调器。

恢复重新核验同一用户/主机/公钥和原模型配置，创建新 AI run 与新任务，并先等待授权。保留 maxTurns 与已消耗 turns；不自动换模型、增加预算或复用旧批准。原工具调用仅作上下文，不重新派发；未知操作在桌面核对后才能继续。问题使用新 ID，旧回答请求不能命中新问题。

已恢复任务在请求模型前先持久化本轮用量，在每个工具结果和对话组完成后同步状态。用户回答与增加预算成功落盘后才交给运行循环。系统加密失败不回退明文，持久化失败不启动新的模型请求或派发。保存/恢复事务未完成前禁止提前授权或新模型调度。

## 验收

自动与协作模式在实际操作后保存、重启和重新授权，只执行剩余意图；原结果进入新模型上下文。等待问题可恢复并保留回答；工具轮次被打断不重放未发调用。模型预算不重置，错误模型配置/系统加密失败/未知结果/越权用户明确拒绝。类型、lint、AI/任务/MCP/文件回归及 Windows 真实桌面分别取得证据，失败与未覆盖边界单列。

## 已实现与使用

内置 AI 任务现在复用任务面板的“暂停并保存任务进度”和“查看可恢复任务”。恢复详情显示原模型、已用/最大模型轮次、保存时的问题、对话和此前操作结果。恢复创建新的 AI run 和任务 ID；原问题使用新 ID，旧问题回复被拒绝。回答成功保存后关闭对应输入；保存失败保留原输入和问题。不同任务的回答组件按 run ID 隔离。

本轮恢复独立 AI 任务：已完成历史和规范化工具调用保留，providerSignature 原样保存。尚未完成的工具组会补齐“未知／未执行／问题已保留”结果标记，使上下文不会带着孤立工具响应恢复；保存的 toolCalls 仅作为历史，不重新加入执行队列。新模型根据历史和任务实际结果决定后续动作，仍经过当前授权与策略。被中断的响应在界面标记为中断，原请求迟到时不能派发工具。

模型轮次在请求前持久化，预算不因重启归零。持久化失败不会发送该模型请求；持久化期间接管也会阻止新请求。已持久化但尚未明确发出的请求轮次保守计入已用预算。增加预算必须由用户明确操作，成功落盘后才更新运行循环。等待回答的任务可跨重启恢复，已确认回答再次保存后仍保留，不重复索要。

恢复绑定同一用户、服务器身份/公钥，以及原模型配置的类型、地址和模型名称摘要。配置 ID 相同但接口已改变时拒绝恢复；请求适配器在读取实际配置后再次核对摘要。API Key 不进入摘要，正常密钥轮换不会因此失效；不把配置中的密钥写入恢复格式。对话或命令本身仍可能包含用户提供的敏感数据，检查点按敏感数据系统加密，不假定能识别所有硬编码秘密。

## 责任文件与容量

- types/ai-conversation.ts 拥有原规范化消息/工具调用类型，旧 ai/providers/types.ts 重导出并新增内部 expectedProviderIdentity；模型 HTTP 正文不发送此内部字段。
- types/ai-task-recovery.ts 与 ai/tasks/recovery-state.ts 拥有 AI 版本 1 附加状态；系统角色消息、孤立工具响应、重复调用 ID 和不一致预算被拒绝。对话组最多 128 组、规范化历史最多 256000 字节，界面消息最多 80 条；原模型上下文限制继续生效。
- AiTaskCoordinator 负责捕获/冻结/恢复、问题回答、模型预算、迟到响应、工具组补齐和取消后的清理。恢复不再执行初始规划请求，先等待新授权。
- TaskRuntime 只接受已绑定 AI 身份的捕获回调，继续拥有 SSH、授权及操作结果；恢复服务通过 agent-port 调用协调器，不反向依赖具体模型请求实现。
- TaskRecoveryService/Store 复用既有 TTR1 系统加密记录和独占领取。旧工作流/MCP 记录保持可读，AI 元数据必须匹配所属任务、目标模式和目标描述。没有明文回退或新的通用存储抽象。
