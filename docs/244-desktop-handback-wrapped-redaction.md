## 运行与缺陷

本轮从当前本地源码构建 Windows win-unpacked 目录包；版本号仍为 alpha.14，但包含尚未提交的本地修改，不等同于 GitHub 已发布 alpha.14。未创建安装程序、上传资产、推送或触发 Actions。

通过专用 MCP 配对（38 个工具、实际 stdio）、校验指纹的独立 Alpine SSH 会话，在中文桌面执行自动与协作两种交还场景。模型为 127.0.0.1 测试服务，无收费模型调用。

修复前运行三次，均在交还后的模型请求中发现已知虚构值残留，记录分别为：

- .cache/desktop-observation-report-bf18984e-d0a9-4124-95d6-fad738c23bbd
- .cache/desktop-observation-report-b261e7a5-519d-449d-8264-c3606835b283
- .cache/desktop-observation-report-422adb99-8777-4f70-a569-6fdb8c1dc3b4

诊断确认人工输出标记和 untrusted-terminal-output 标记均存在，但终端将敏感字段名显示为 a + CR CR LF + pi_key，导致原连续字段名正则失效。失败进程均已终止后再开始下一次，不把失败清理算正常退出。

## 修改责任与约束

privacy/redaction.ts 仍负责现有文本和结构化数据出口的共用脱敏，AI 兼容入口继续转发该模块；没有新读取接口或执行通道。

已识别敏感字段名允许字符之间出现一至两个 CR 后接 LF 的终端折行；无引号值也覆盖该折行。保留普通文本换行，不预先把整个终端合并为单行。遇到秘密值后紧邻的 CRLF 行可能被保守扩大遮盖，不声称任意 Shell 语法、ANSI 重绘、编码或其他秘密表达均可识别。

新增六个 api_key 字段名折行位置回归，修复前全部失败；另验证折行值和非秘密换行保留。

## 通过证据

最终报告：.cache/desktop-observation-report-c1c6ef8d-638d-4031-8f8b-89d36e028523。

ai-handback-desktop-result.json 两种模式均记录 realWindowsDesktop/realLinux、人工终端输入、生产上下文、脱敏及完成。协作模式另验证逐条批准。两种模式各发生四轮本机模型请求，其中第二轮挂起以触发人工接管，第三轮检查重新交还的上下文，第四轮完成。

实际流程：MCP 打开 SSH → 中文身份信任 → 任务授权 → 模型请求挂起期间立即接管 → xterm 输入并实际执行标记命令 → 重新授权 → 模型确认标记存在且虚构秘密不存在 → pwd 实际成功 → 协作模式经过单条批准 → 任务完成。最终客户端正常退出，后台监听端口释放。

已实际查看 ai-handback-collaborative.png，中文完成状态可见、无欢迎弹窗遮挡。人工终端本身保留手工输入与输出（包含虚构测试值），脱敏断言针对发送模型的数据，不声称人工终端隐藏用户输入。当前终端可见较多命令包装代码，仍需改善可读性。
