# 隧道身份信任与连接生命周期

按原始 B02/B13、A02/A35 补齐隧道边界。检查发现终端、监控和跳板已接入 SSHHostKeyVerifier，而 S2S 源/端点、C2S relay 和旧清理连接没有统一调用。该阶段复用现有信任服务和中文信任面板，不创建第二套 known-hosts 或自动接受新密钥。

主智能体负责：tunnel/connection-trust 提供隧道身份到信任目标的唯一映射；ssh-primitives 负责带验证的连接与流生命周期；manager/c2s-relay 组装受认证用户约束的配置；现有 HostTrustService 负责首次确认、变化阻断、记录与取消。源主机使用其保存的 ID；没有保存主机 ID 的端点按发起用户、地址和 SSH 端口单独确认。配置中的凭据所有者不能代替实际发起用户。

允许依赖为隧道编排 → SSH 连接/信任适配 → 现有 HostTrustService，信任核心不依赖隧道页面。握手未确认前不发送认证信息或建立转发；连接失败/关闭要释放待处理转发通道。指纹拒绝归类为不可自动重试的连接失败，并显示中文核对提示。已有人工 SSH 接管规则、AI/MCP 命令网关不变。

验证使用真实回环 SSH 握手与转发数据，覆盖首次确认前零认证、相同信任复连、变化拒绝、来源/端点用户归属、连接取消以及迟到转发流回收。此阶段不代替完整监控动作可见性、所有认证方式及全部转发模式的总验收。

## 实施范围与替代方案

已为 C2S relay、S2S 源/端点以及保留的旧清理连接接入同一 SSHHostKeyVerifier；发起用户优先于配置中的来源/端点凭据所有者。端点凭据按发起用户查询，不用客户端提供的 endpointUserId 读取其他用户凭据。信任拒绝的错误类型/原因保留至界面，显示中文核对提示，关闭事件不会再次触发该失败的重试。

自动审批拒绝了删除整个旧清理函数并批量改写断开/活动归属的方案，理由是范围可能影响既有清理和重试。已改用较小方案：保留旧函数和一般重试行为，仅在持有旧本地 SSH 子进程句柄时才调用旧远端清理；握手失败没有该句柄，不会再连服务器扫描进程。活动记录沿用底座归属规则，仍需专项审查；没有静默改变共享隧道的事件归属。

转发原语现在在等待出站连接时就处理入站错误；入站已关闭后到达的出站通道会立即关闭，双方关闭/错误互相回收。该变化不创建第二条 SSH 执行入口。

## 已获得的验证

真实回环 SSH 源/端点测试验证：发起用户确认前服务器认证计数与转发计数均为 0；确认后发送实际 TCP 回显字节；相同密钥复连不再询问；变化密钥拒绝前仍为 0 次认证。配置中的其他凭据所有者不会收到信任请求。真实隧道管理器集成进一步验证确认前没有本地监听，连接后真实字节转发，手动停止后 socket 与监听端口释放；拒绝握手后没有重试或额外清理连接。迟到通道与等待期间错误回收也已覆盖。

最初新增测试误读 HostTrustRequest.kind，已按实际 scenario 字段修正，保留变化密钥零认证断言。随后发现无重试的失败清理会覆盖具体错误类型/原因，已补齐失败状态保留并通过复测。隧道与既有信任组合目前 14 项通过，完整回归和后续证据继续记录。

当前阶段未证明所有 local/remote/dynamic × S2S/C2S 的桌面组合、待确认时取消、监控采集动作展示、全部认证/跳板兼容或完整 B02/B12/B13 已验收。继续原始 F/B/R/A 范围，不因这组身份与转发测试通过而缩减目标。
