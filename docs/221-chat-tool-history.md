# 普通聊天完整工具历史

## 实际缺口

原路由每次 assistant_message 都覆盖同一变量，最后只保存最后一轮助手回复。工具结果没有保存，因此下一次请求缺少此前的调用、结果及关联 ID；单纯保留最后一段 toolCalls 无法重建多轮模型上下文。

## 责任与实现

- `ai/engine.ts` 为实际放入模型上下文的工具消息产生内部 tool_message 事件，保留 toolCallId、toolName 和已脱敏结果。提议结果仍是 awaiting_user_approval，不伪装已执行。
- `ai/index.ts` 收集各轮助手及工具消息，助手可见正文按流式顺序连接。内部事件不发往 SSE；保存完成后才发 done。
- 新 `ai/chat-history.ts` 仅属于普通聊天持久化，使用既有 ai_messages.toolCalls 文本字段保存 `{version:1,messages:[...]}`，严格解析角色、字段和最多 80 条消息。读取时展开完整历史；兼容旧工具调用数组及没有工具字段的文本记录，保留 providerSignature。

没有数据库列迁移、工具执行权限变化或通用共享模块。依赖方向为 HTTP 编排 → 聊天格式模块 → 模型消息类型；引擎不依赖仓储。旧版本软件不理解新的对象格式，不能承诺降级后继续读取这些新记录；新版本继续读取旧格式。

## 验证

- 实际 runAgent 测试验证新增工具历史事件包含正确结果及调用 ID。
- 编解码测试验证多轮助手/工具往返、旧数组及模型签名兼容，拒绝不支持版本和在助手历史内插入 system 角色。
- 实际 Express HTTP 路由测试输入两轮助手及工具结果，核对仓储接收到完整历史；再次请求同一会话，模型引擎实际获得原历史加新用户消息。内部 tool_message 不作为 SSE 输出。
- AI 后端全目录 **24 文件、158 项通过**。追加第二次 HTTP 请求断言后，针对性 **3 文件、17 项通过**。TypeScript 通过；ESLint 无错误，既有 engine.test.ts 的两处 any 警告保留。

## 证据限制

HTTP 测试采用仓储与模型替身，实际引擎的独立测试采用受控工具。没有付费模型调用，也不构成本轮实际 SQLite/桌面重启验收。旧数据已丢失的工具结果无法追溯恢复；本改动防止新聊天继续丢失。

中断时的部分消息、模型错误后的完成状态、实际桌面历史刷新与全局资源限制仍需继续处理。R06/F05/F06/A23 保持未完成。此改动未进入 alpha.12 安装包。
