# 覆盖导入读取失败时停止

2026-09-12，旧 JSON/SSH 配置导入读取已有主机列表的 catch 原本清空匹配表并继续，导致用户选择覆盖但查询失败时变成新增。用真实 HTTP + SQLite 故障注入已复现：两个接口返回 200，而预期是停止。

## 修复契约

两类接口在覆盖查询抛错时返回 HTTP 409、code=HOST_IMPORT_LOOKUP_FAILED，不继续导入。JSON 的已有主机查询移到凭据占位创建之前，因此这一失败发生时主机与凭据均未写入。不返回数据库异常细节。正常新增/覆盖路径保持原行为。

通用 handleApiError 原本把所有 409 改为 CONFLICT；本次在 ssh-host-management-api 的模块内错误适配中仅保留此专用错误码，其他错误继续走原通用入口。HostsPanel 两个导入入口据此显示中文“无法读取已有主机，导入尚未开始。请在连接或数据库恢复后重试。”未引入重试或新的共享模块。

## 实际验证

- 两个新增故障用例修复前失败（返回 200），修复后通过（409）；现有主机记录逐字段不变，凭据占位表为空。
- HTTP/SQLite、停用激活状态、SSH 配置解析三文件共 20 项通过。
- UI API 两种导入保留错误码、无重试/无缓存失效及其他错误走原路径共 3 项通过。
- ESLint、TypeScript、中文键和 diff 检查通过。

本轮是受控数据库读取故障注入，不是物理数据库损坏测试，也未重新做打包桌面错误提示截图。不会把该修复泛化为导入的整体事务保证：后续逐项写入失败仍可产生部分成功；本次严格停止的边界仅为覆盖前主机列表读取失败。A22 的其他高级配置审查和覆盖差异展示仍未完成。
