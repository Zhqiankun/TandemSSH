# 本地与远端文件双面板

状态：双面板已实现并通过实机专项；完整回归与提交状态见下文。来源为原始 B04、B05、B11。2026-09-10 对 `178fa6a` 源码核对后，确定这是下一项基础功能缺口。

## 当前证据与交付目标

`FileManagerApp.tsx` 只根据远端 hostConfig 创建文件管理器。`FileManager.tsx` 的主体是远端收藏/目录侧栏及一个 `FileManagerGrid`，没有本机目录列表。现有原生选择器、拖拽与上传/下载队列已经实现文件传输；它们不能代替 B04 要求的“本地/远端双面板”。上传和下载队列已有并发配置、速度、预计剩余时间等界面，后续需按原清单做完整实机验证，不能因本轮发现双面板缺失就重新实现传输核心。

目标：在 Windows 文件工作台同时看见“本机”和确定服务器的目录，分别导航、刷新、筛选、排序、选择文件并查看属性；选择本地项上传到当前远端目录，选择远端项下载到当前本机目录。上传、下载仍先进入既有预览/冲突处理和队列。服务器、两端绝对路径和传输方向必须清楚。重新选择本地目录、切服务器或关闭面板不能把在途传输悄悄改到新目标。

## 模块责任与依赖

由主智能体实施和验收，不增加角色委派。

| 文件/模块                                                       | 责任与公开边界                                                                               |
| --------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| `app/electron/local-file-browser.cjs`                           | 人工选择的本机根目录能力、目录身份/路径校验、分页元数据、资源释放；只有主进程访问文件系统    |
| `app/electron/local-file-browser-ipc.cjs`                       | 验证当前可信主窗口及主 frame，原生目录选择、输入转换、错误映射；不包含远端策略               |
| `app/src/types/local-file-browser.ts`                           | 原生与界面共享 DTO；不依赖 UI 或 Node 实现                                                   |
| `app/electron/preload.js`、`app/src/types/electron.d.ts`        | 暴露有限方法，不能暴露 fs、任意 IPC 或任意路径文件读取                                       |
| `app/src/ui/features/file-manager/local/`                       | 本地面板、加载/取消状态、选择与排序；通过公开 preload API 工作                               |
| `FileManager.tsx`                                               | 两端布局及传输发起的编排；继续调用 uploads/downloads 的公开入口                              |
| 现有 `UploadSourceStore`、`DownloadDirectoryTargets` 与传输队列 | 接收经过本地目录能力校验的选中项，创建各自独立传输授权；继续承担完整性、冲突、恢复与提交语义 |

依赖方向：页面 → 本地面板/API 契约 → preload/IPC → 本地目录用例；IPC 的传输适配器 → 已有上传来源/下载目标公开入口。业务后端、AI、MCP 不反向依赖页面或本地目录能力。相似的窗口校验逻辑不因重复而强行抽成新的通用框架。

## 契约与生命周期

已实现操作：`choose()` 返回用户原生选择的根目录 token、路径与身份；`list(token, relativePath, cursor, options)` 返回有限条目的名称、类型、大小、修改时间、隐藏/链接标识和下一页；`release(token)` 释放浏览能力。响应统一为 `{ok:true,value}` 或 `{ok:false,error}`。上传来源和下载目录通过主进程适配器校验同一窗口的 token 与选中项后，交给各自已有 store，禁止由 renderer 提供未经校验的任意绝对路径。

token 只在当前主窗口/导航生命周期内有效，不持久化、不进入任务授权。父级和路径栏导航限定在已选目录内；需要其他根目录时可重新选择，包括选择磁盘根目录。元数据枚举不读取文件内容，按明确上限分页；超限提示不能伪装成目录完整加载。显示符号链接但不凭链接跳出所选目录，重新定位须由人明确选择。每次 I/O 前后核对能力仍有效及路径/目录身份未变。

本地浏览权限不自动成为 AI/MCP 的本机文件权限。任务原生授权仍由现有入口负责。关闭本地面板只释放浏览能力；已确认传输继续由上传来源、下载目标和队列各自持有生命周期，符合 A33 的连接/任务保留要求。取消选择、权限不足、根目录删除/替换、窗口退出或迟到列表响应均有明确结果，不能把错误显示为空目录或复用过期条目。

### 仍需注意的边界

本阶段最初只识别点文件；后续 Windows Hidden/System/ReadOnly 支持及实机证据见 [Windows 文件属性](59-windows-file-attributes.md)。分页上限、过期能力及路径错误有中文提示；链接必须由人重新选择根目录，不能静默跟随出界。通用文件系统没有应用可用的原子“验证整条路径并保持后续目录操作身份”接口，因此外部程序在检查和 I/O 之间极短窗口内改名/替换仍有剩余竞态；当前逐层拒绝链接并在读取/交接后复核身份，不宣称完全防御有本机写权限的攻击者。
