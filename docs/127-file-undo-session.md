# 撤销会话归属与目录类型

2026-09-12。沿用文档 126 的失败回执保留修复。

问题：旧撤销记录未保存 SSH 会话，handleUndo 使用页面当前会话；重连/切换可能将旧路径提交给替换连接。复制撤销还从当前目录列表查找类型，离开复制目标目录后会把目录当文件。

实现与边界：UndoAction 在复制、剪切粘贴、拖动成功时保存原 sessionId；成功回执保存 isDirectory。撤销只调用原会话，在 ensureSSHConnection 前后、每个远端动作前后和刷新前检查原会话与组件存活状态。切换或卸载停止后续派发；已确认成功的回执仍按文档 126 从历史移除。已发出的请求无法据此保证取消或回滚。连接变化提示中文明确说明可能已有操作完成。FileManager 仅负责编排，回执与校验留在 file-operation-history，不新增跨业务共享依赖。

验证：两个文件共 9 项测试通过，覆盖回执保留、会话相同/不同/断连/卸载以及目录类型保存；ESLint 0 错误、1 项已有 windowId 警告；汉化检查缺失键 0；tsc -b 通过。检查三个 UndoAction 构造点均记录实际请求闭包中的会话。此为领域逻辑测试及调用点检查，实际 Windows UI 中途重连和撤销目录还需集成验收。远端文件之后被外部修改的处理仍不由这些检查解决；B09 不标记完成。
