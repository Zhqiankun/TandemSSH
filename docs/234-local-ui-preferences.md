# 本地界面偏好启动保护

检查此前欢迎页重现时发现一个独立可复现缺陷：UiPreferencesProvider 在 local 模式只保存本机缓存，但启动时无条件从服务端读取并覆盖缓存。本地已完成的 onboarding 和预设因此恢复为默认值。

## 实现

启动先读取 storageMode。本地模式已有缓存时保留本机值；本地无缓存时允许从既有服务端设置初始化，云端模式继续加载远端值。读取失败保留缓存/默认值并结束加载状态。

新增本地修改版本计数，启动请求发起后发生的编辑或缓存同步会使旧响应失效，避免迟到的云端读取覆盖用户刚完成的修改。

修改只在 UiPreferencesContext 的状态编排，API、存储字段和全局共享模块不变。保持本地写入不发往云端的原约定。

## 复现与验证

修复前：本地完成欢迎页并设 advanced，重新挂载后被远端 balanced、completedVersion=0 覆盖；云端延迟返回 simple 也会覆盖已经设好的 advanced。两项测试均失败。

修复后：这两项通过，另加云端正常读取仍以服务端为准的测试。偏好上下文、偏好类型和 onboarding 共 3 文件、42 项通过；TypeScript、ESLint 通过。

## 范围

本轮证明 local 模式及迟到读取缺陷，不将其直接作为此前每个桌面欢迎页重现的完整根因：那些报告未记录实际 storageMode，尚需新打包桌面复验。云端写入失败的可见反馈及退出前未完成的防抖写入仍需独立检查。

该修复晚于 v0.1.0-alpha.14 标签，不在正在构建的 alpha.14 内。它不会改变当前发布标签，也不宣称新包已发布。
