# 内置 AI 与共享终端

更新日期：2026-09-08。当前已接入内置模型规划、受控命令/流程、文件读写与目录属性查询，以及中文任务界面；完整产品仍在开发。

## 使用流程

1. 连接 SSH 主机，打开终端旁的“协作执行”，选择“AI 任务”。
2. 在“模型设置”配置自己的接口、API Key 与模型 ID。支持现有 OpenAI、OpenAI 兼容、Ollama、Anthropic、Gemini 适配；本轮实际端到端验证使用本机 OpenAI 兼容模拟接口。
3. 填写执行目标、模式和模型调用预算。默认 20 次（包括规划），范围 2—64。
4. AI 先生成计划，不执行远端命令。你确认程序范围、工作目录、操作数量、有效期和 Shell 已回到提示符后，才交出控制权。
5. 自动模式在本次授权范围内推进；协作模式逐条等待确认。缺少事实信息时可在面板回复 AI 的问题；回复不是授予权限。
6. 直接在终端输入或点击接管即可收回控制权。正在等待的模型请求会中断，迟到响应里的旧命令不会发送。重新授权后，AI 根据新上下文继续。

任务和模型的预算分别控制远端操作与模型调用。达到模型预算会暂停，可增加预算后重新授权。当前模型历史上限为 60000 字符，超过时明确暂停，不会悄悄丢弃执行历史后继续操作。

## 执行与数据边界

内置 AI 使用独立 agent 身份，绑定 agentRunId；不能访问其他 agent 的任务，也不能调用人工授权接口。执行阶段提供 run_command、ask_user、finish_task、五个保存流程工具和六个文件工具，全部启用时共十四个；模型不能保存模板或签署人工批准。目录/属性、分页和文件工具的实际执行链见[文件查询说明](21-file-inspection.md)。run_command 进入与 MCP、命令流程相同的 TaskRuntime 和 OperationGateway，使用同一 SSH stream。

模型等待命令批准或用户答复时，没有新的模型请求。人工接管会中断 HTTP 请求，并检查控制权版本；即使模型服务忽略取消并返回旧响应，也不能在新授权下发送旧计划。

失败或未知结果会暂停。恢复需要人工明确核对，记录核对选择，原操作仍保留 failed/unknown，不被改写为成功。审计缺口仍不能被当成完整成功结果。

模型收到的是任务目标、所选主机信息、当前目录及脱敏结果，不会收到 SSH 密码、私钥或 MCP 配对秘密。模型 Key 沿用现有提供商仓库的字段加密存储，只在请求时解密；这与 MCP 配对使用 OS 凭据库是不同实现，不能声称所有秘密都已统一迁入 OS 库。已增加对模型接口回显当前 API Key 的跨分片脱敏，包含该 Key 的工具参数会被拒绝。

桌面在没有显式设置时显示 AI 能力，但不自动发起模型请求；用户选择 AI 功能后才启用个人偏好，实际规划由点击“让 AI 规划”触发。显式全局关闭和个人关闭仍生效，并停止当前模型/任务。

## 改造位置

- ai/tasks/runner.ts：规划、模型工具循环、预算、问答、等待与中断，不持有 SSH 连接或授权签名器。
- ai/tasks/production.ts：复用提供商适配、用户权限、密钥读取与审计；禁止输出配置秘密。
- ai/tasks/http-routes.ts：可信桌面创建、查看、回复、停止和增加预算接口。
- ai/access-events.ts：同步传递 AI 停用，避免模型等待期间继续消费请求或保留控制权。
- collaboration/tasks/runtime.ts：独立 agent 身份、轻量状态读取、任务取消观察、人工核对与共享执行。
- ui/features/ai/tasks：中文执行表单、模型设置、计划和结果、补充信息与预算操作。

旧聊天的 propose_run_command 不再进入独立 SSH 连接池，旧提案明确返回 SHARED_SESSION_REQUIRED；相关行为测试改为证明该路径不会解析主机或执行 SSH。聊天中的其他配置功能未因此声称已经全部迁入统一动作网关。

## 实际验证

- 打包后的 Windows 桌面使用隔离配置，连接真实回环 SSH 服务（Git Bash）与本机 HTTP/SSE 模拟模型；未调用用户的真实模型或使用真实 API Key。
- 自动流程：规划后等待授权，pwd 和 printf 均真实执行成功，退出码为 0；模型收到结果后结束任务，控制权回到人工。
- 协作流程：第一条命令等待批准。随后模型响应被故意挂起；人工输入触发接管，HTTP 服务观察到请求被中断。重新授权后，printenv 读到“人工协作验证”，旧命令 STALE_AI_MUST_NOT_RUN 未发送。
- 模拟接口故意把测试 Key 拆成两个文本分片回显。界面只显示 [redacted]；所有后续模型消息均不含该 Key。
- 全局关闭实测返回 200，等待中的 AI 与任务均为 cancelled，远端操作数为 0。

证据：.cache/ai-live-evidence.json、.cache/ai-model-progress.json、.cache/ai-disable-evidence.json。

本轮发现了真正的 HTTP 兼容问题：项目 Undici dispatcher 被传入 Node 内置 fetch，导致 invalid onRequestStart method。已改用同一 Undici 实现的 fetch 与 dispatcher，真实 HTTP/SSE 回归及桌面复测通过。
