# 文件重新读取编码跟随当前版本

2026-09-13，A31 界面修复。

FileWindow 原先将“重新打开使用的编码”固定初始化为 UTF-8，与后端识别出的格式无关。UTF-16 文件可以正常打开，但默认重新读取却发送 UTF-8；加载新文档版本也可能保留旧的手动选择。

修复前新增三项组件测试中的两项失败：识别 UTF-16 LE 时仍显示 UTF-8，新版本 UTF-16 BE 仍显示旧选择 GBK。

现在 FileWindow 的临时编码选择绑定当前 document.version。未主动选择时展示当前已识别 charset，缺少识别结果时才回退 UTF-8；同一版本普通重渲染保留人工选择，新版本使用其实际编码。派生当前值直接用于 select 和 reload，不通过延迟 effect 修正显示。

文件责任仍为编辑窗口的 UI 状态编排；后端编码器、API 与保存语义不变。没有新增共享抽象或依赖。

组件测试使用实际 FileWindow 中文渲染和受控文档 Hook，验证默认编码、主动选择保持、发送的 reload 参数及版本变化。与文档/草稿 Hook 测试共 3 文件、15 项通过；TypeScript、ESLint 通过。

尚未在最新实际桌面包复测，本地目录包未包含这次 UI 修改。A31 的桌面编码转换与特殊文件名组合验收继续保留。未提交、推送或发布。
