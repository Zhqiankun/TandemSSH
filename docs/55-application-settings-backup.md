# 应用外观与快捷键的备份恢复

本阶段扩展配置备份到桌面实际使用的主题、字号、强调色、语言和界面偏好，以及当前用户的自定义快捷键。此前备份只有数据库中的 UiPreferences，不能代表全部本地界面设置；本次以实际桌面预览和重新加载后的显示为验收依据。

备份输出升级为格式 2，继续接受格式 1；旧文件中没有的字段不覆盖当前设置。`types/desktop-preferences.ts` 定义外观白名单、规范化与公开类型，供前后端使用，不依赖页面；`configuration-backup/keyboard.ts` 负责快捷键文件格式、秘密排除和恢复投影；`ui/settings/desktop-configuration.ts` 只负责白名单 localStorage 字段的捕获与写入。

导出时桌面 API 传入当前本地外观和 UiPreferences；服务器校验并冻结预览，快捷键从当前用户数据库读取。导入预览含完整 JSON 和快捷键数量；界面设置与快捷键分别勾选恢复，默认均不勾选。主机、流程、可选界面设置、可选快捷键和收据在同一 SQLite 事务中提交。重复确认包含两个选项，不会重复导入。

快捷键恢复采用新增 ID、禁用、待审阅状态，导入时不激活默认快捷键覆盖，也不继承源命令片段数字 ID。保留源快捷键的内置覆盖标识，编辑确认后才采用该映射；已有快捷键不删除，组合冲突有提示。内置标识由键盘类型模块维护，默认快捷键清单与备份校验引用同一个注册表。运行片段的快捷键需要重新选择当前工作区片段；编辑保存后才启用。导入本身不发终端输入、不执行片段。

本地界面写入与 SQLite 无法组成同一个事务：数据库确认成功后再写入本地白名单设置，失败时显示数据库恢复已完成、本地设置待重试；重试只重写本地设置，不重复导入。写入前记录旧值并尽力回滚，保留明确失败状态；成功后用户手动重新加载应用设置，不强制关闭连接或丢弃草稿。预览后本地设置改变时，确认前要求重新预览。

验证：格式 1/2 兼容、恶意字段/秘密排除、待审阅快捷键无法派发、片段引用不误绑定、追加不覆盖、两种选项幂等、SQLite 回滚、本地存储失败重试，以及真实桌面主题/字号/强调色恢复后的画面与快捷键审阅行为。原始 F/B/R/A 验收范围不变；隧道、跳板和其余尚未覆盖的配置仍需继续补齐。
