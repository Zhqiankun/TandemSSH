# 磁盘监控路径与样本匹配

## 复现的缺陷

parseDfLines 将整行按空白拆分，带空格的文件系统源和挂载点会错位；例如 server:/shared data 会把 data 当成类型，挂载点甚至读成 40%。另外，字节行和可读单位行数量相同时按索引匹配，顺序不同会显示另一块磁盘的容量；同挂载点换设备时也会混用旧显示值。

## 实现

采集器按容量/百分比字段识别列边界，保留完整文件系统源和挂载路径（含内部连续空格）。匹配可读单位样本时使用文件系统源、类型、挂载点三项身份，不再使用行数相同即按序配对的快捷路径。

可读单位采样失败时允许保留独立字节数据及使用率，缺失的可读字符串为 null；默认和自定义挂载点均采用这一规则。字节采样失败时仍不能推算真实容量，不伪造数值。

公开磁盘结果字段未改变，固定采样权限与命令目录未新增动态输入，无跨业务共享抽象。

## 验证

新增测试先后复现：带空格路径错位、同长度反序样本串盘、同挂载点更换设备混入旧字符串、可读样本失败丢弃全部磁盘结果。四项在修复前失败，修复后通过。

监控目录 19 文件、140 项全部通过；TypeScript、ESLint 通过。本轮使用真实解析器与受控采样端口，不声称已完成真实服务器磁盘矩阵。换行等含控制字符的 df 文本歧义，以及两次 df 之间的容量变化不由这次修复消除。
