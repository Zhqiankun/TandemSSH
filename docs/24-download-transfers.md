# 下载、原生落盘与传输队列

2026-09-08，实施中。按原始 B05—B07、B11 和协同文件要求继续下载链路，不缩减递归、多文件、跨重启恢复与 AI/MCP 传输的最终范围。

本轮责任由主智能体独立承担：types/file-download.ts 定义远端来源与本地目标契约；backend/files/download-service.ts 负责来源快照、用户/主机/连接身份与分块读取；SftpFileIO 提供有界读取；HTTP 只做人工身份校验和协议转换；electron/download-sink.cjs 负责用户选定目标、临时文件、内容校验、提交与清理；UI 下载队列负责顺序编排、并发、暂停恢复和中文结果。

依赖为界面队列 → 远端 HTTP 用例 / 原生受限 IPC；文件领域不依赖页面或 Electron。IPC 仅接受当前主窗口顶层可信页面，返回绑定窗口的随机能力 ID，后续不能由渲染器指定任意写入路径。覆盖要核对本地目标基线；提交失败不虚报完成或自动重复覆盖。

验收使用实际本机 SSH/SFTP、真实临时目录和原生 IPC 边界测试，检查多块/空文件、校验、同名冲突、取消/重复块、改变源或部分文件、主机变化与跨用户请求。内存按块和并发上限约束，不能合并整份远端文件为 Blob/Base64。

## 本轮实现与验证

文件管理器的手工文件下载入口已进入下载队列。远端先计算完整 SHA-256 与分块摘要；HTTP 每次最多返回 4 MiB，原生端只允许向用户通过保存窗口选定的目标写入。先写独占临时文件、同步句柄、核对源与目标、再提交并读取本地结果校验。实际本地写入量决定进度。当前支持逐项目标选择、覆盖确认、并发 1—4、块边界暂停、重新核对后恢复、取消及打开目标目录。

新服务不调用 cat 或 sudo；现有预览/拖出等旧接口仍需继续收敛，不以此次文件管理器入口替换宣称全链路迁移完成。源清单、原生能力和队列均有数量与容量限制，凭据不进入检查点。窗口切换用户时清除能力；暂停连接的保留与恢复校验由文件用例处理。

专项测试覆盖真实 SFTP 多块/空文件、同大小内容变化、跨用户、连接和主机身份变化、HTTP 二进制响应、真实本地覆盖/冲突/部分文件变化、重复块、取消、IPC 非主窗口拒绝和队列未知提交。新增相关测试 14 项通过，并纳入本次完整回归。第一次多块断言超时源于通用逐元素比较，改用 Buffer.equals 保持完整字节比较后，专项 12 项在 1.45 秒内通过，没有增大超时掩盖传输挂起。
