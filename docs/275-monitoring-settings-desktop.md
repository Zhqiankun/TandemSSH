# 主机监控周期与停用设置的桌面验收

2026-09-13，B12。本轮使用当前 Windows 目录包及独立测试配置，不修改生产代码，不推送或触发 Actions。

从主机条目的“编辑主机”按钮进入 SSH / 主机指标，操作实际数字输入及开关，通过“更新主机”保存：

1. 将指标间隔从 5 改为 7 秒，持久化主机查询返回 metricsInterval=7，监控面板显示“每 7 秒”，随后 SSH 测试端继续收到至少两批采样命令。
2. 在相同编辑入口关闭“启用指标”并保存，查询返回 metricsEnabled=false。等待 1.5 秒清理后开始观察，15.5 秒内测试 SSH 服务端没有收到新命令。
3. 重新打开编辑器，开关仍关闭且自定义间隔输入隐藏。重新启用、保存，查询返回 true，SSH 服务端重新收到采样命令。
4. 桌面正常退出、端口释放，观察器报告 cleanExit=true。

实际证据：`.cache/desktop-observation-report-0ec45e43-5c3f-44c6-be65-63ba055d1aab/metrics-settings-result.json`，截图 `metrics-disabled.png` 已查看，显示“已在主机设置中停用”、每 7 秒、禁用的暂停按钮及保留的最后指标。无 PTY 请求。

本轮 SSH 服务端通过真实 ssh2 通道返回固定内存/运行时间样本，用于准确观测命令派发；它不是 Linux 内核。七组真实 Alpine 数据显示的证据见 274。本轮未证明定时器精确到毫秒；证明保存后的周期配置被运行中的面板采用并继续采集，以及永久停用/再次启用的实际执行效果。未单独执行跨重启设置测试，不将重新打开编辑器称为重启。

失败现场：首轮 f9ae8286-6678-49b7-a9df-6dacd64fc79f 中脚本通过 API 创建主机，只刷新侧栏，编辑器尚无该主机；第二轮 183e738b-51bc-4e15-acd9-2323d14907a4 只刷新编辑器但未使共享主机缓存失效。核对正常 UI 保存流程后，测试准备改为先使 ssh-hosts:changed 缓存失效，再发送 termix:hosts-changed 刷新编辑器。最终报告实际通过，未绕过编辑、保存与开关的 UI 行为。

B12 原始要求“CPU/内存/磁盘/网络/运行时间/系统信息/进程查看、采样间隔和停用入口”结合 274 与本记录闭环，标记 verified。当前总计 35/79 verified；其余条目保持原始范围。
