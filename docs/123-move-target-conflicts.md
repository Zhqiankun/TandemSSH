# 移动目标冲突处理（仍在集成）

2026-09-12。moveItem 原 Shell mv 可覆盖既有目标。现和重命名复用同一标准 SFTP RENAME 实现，目标存在返回 409；连接失联或超时在移动路由映射 MOVE_RESULT_UNKNOWN，中文提示刷新源/目标核对。粘贴及拖动入口显示目标冲突说明。认证仍复用原 SSH 连接和会话所有权。

rename-item.ts 的 moveFileItem 承担显式源/目标迁移，renameFileItem 只校验同目录新名称并委托；两者共享预检、无覆盖协议和未知结果处理，不新增通用基础层。原成功文字流测试不再用于移动，替换为实际路由的 SFTP 冲突响应测试。文件服务 14 文件 / 128 项通过，.cache/move-conflict-results.json；翻译缺失键 0，后端修改文件 ESLint 通过。

明确未完成项：标准 SFTP 重命名可能拒绝跨文件系统移动，原 mv 可执行部分此类移动。因此本次存在兼容范围收窄，不能将其当成最终移动功能交付。需补齐在目标不覆盖、复制完整性确认及源未变化前提下的跨文件系统移动，或取得明确范围决定；当前不自动复制再删除，拒绝时源保留。公开 alpha.5 不受本次开发分支修改影响。

另需真实 OpenSSH 跨目录移动及 UI 冲突验收。此前真实 OpenSSH 结果只证明 renameFileItem 路径；不得直接扩成全部移动矩阵。
