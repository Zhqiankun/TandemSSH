# 目录批次的任务执行与 AI/MCP 接入

2026-09-09，本记录保留接线阶段的设计和验证。中文工作台与后续实际桌面验收已完成，最新结果见 [第 35 份文档](35-directory-workbench.md)。

接线阶段状态：本记录承接 [原生目录授权](33-task-directory-transfers.md)。目录批次已接入任务执行和模型工具；中文任务目录入口、完整审核界面以及打包桌面双模式验收仍待完成，不将这部分计为已交付。

## 已接入的行为

- 目录预览、清单确认和每个文件/目录分别成为任务操作，分别检查范围、规则、控制权、审批和预算。预览不写入目标，空目录保留，黑名单与越界子项标为不可执行。
- 批次运行时占用父任务的自动执行入口，阻止命令或保存流程插入；人工仍可接管。接管后停止后续自动操作，重新授权后继续剩余项，已成功条目不重复执行。
- 每个文件复用现有分块上传/下载、版本检查和 SHA-256 校验。目录模块只负责编排固定映射和逐项能力，不复制文件传输状态机。
- 新增 5 个 MCP 工具：preview_directory_transfer、get_directory_transfer、run_directory_transfer、get_directory_run、release_directory_transfer。MCP 清单由 29 项变为 34 项，Codex 发现验证脚本同步检查这些名称；本轮尚未重跑打包后的 Codex 发现。
- 内置 AI 提供同名目录工具。只使用本任务已授权的目录 ID/版本，不接受本地绝对路径或调用方自行传入身份。目录名、清单和错误文本按不可信内容处理。
- AI 等待预览或整批结果，再进行下一轮推理。与 run_directory_transfer 一起预先给出的命令标为未执行，必须先读取实际批次结果再决定。
- 每页清单最多 100 项，完整选择与预览 revision 绑定。重复执行请求返回同一批次，复用请求 ID 但改变选择时拒绝。进行中和接管暂停的批次不能释放预览；已结束记录释放后保留文件和任务操作结果。

## 模块责任与依赖

以上模块由主智能体负责实现和验证。types/directory-transfer.ts 只定义动作与结果；files/directory-transfer-schema.ts 定义对外参数校验；files/directory-transfers.ts 持有固定清单并复用原生目录授权和文件服务；collaboration/files/directories.ts 驱动父任务中的逐项操作；TaskRuntime 和 OperationGateway 继续拥有授权、规则和执行状态；MCP 与 ai/tasks/directory-tools.ts、runner.ts 只负责适配和等待。

依赖方向为 MCP/AI → 目录批次用例 → 任务网关 → 目录执行器 → 原生/SFTP 文件能力。没有新增通用共享层。普通命令与目录动作仍共享父任务控制权，目录预览不能成为绕过网关的执行接口。

为容纳最多 4096 个条目的逐项预算，明确授权的操作数上限改为 5000，默认值不变；普通操作记录仍限 512 条，包含目录动作的总记录上限为 8192，单个目录动作 JSON 不超过 512000 字节，累计目录动作不超过 8 MiB。此变更仍需补充容量与大量条目验证，不能据此宣称大目录性能已验收。
