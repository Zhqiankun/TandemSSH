## 本轮实际桌面与 HTTP

重新构建本地 Windows 目录包，包含 268 固定 Ctrl+C 入口。连接专属 Alpine OpenSSH，报告 .cache/desktop-observation-report-42a2f31d-f131-4830-8c3d-4c03d82e5451。

自动与协作模式分别执行“中断后跳过未知步骤继续”“中断后取消未来动作”，共四个组合。实际点击独立“发送 Ctrl+C”按钮，没有额外模拟键盘 Ctrl+C。当前 sleep 10 操作进入 running 后中断，随后终端实际执行构造标记的 printf；点击到证明输出出现为 299—316 ms，远小于测试等待命令的持续时间。这证明本次测试前台进程响应了中断，不承诺所有远端程序都响应。

继续分支保留原 workflowRunId、首步只执行一次、未知记录保留，协作继续须逐条批准；取消分支只保留成功首步与未知第二步，第三步 pwd 未派发。客户端正常退出、后台端口释放。

生产 HTTP 实测：多余 data 字段、缺少版本字段、非法会话 ID 返回 INVALID_REQUEST；错误会话拒绝；匿名拒绝；错误 generation 与中断前旧 epoch 重放返回 STALE_CONTROL。拒绝请求不会改变控制 epoch。

已读取 task-interrupt-result.json，查看 cancelled-collaborative-cancel.png：独立中断按钮、原成功与未知记录可见。截图中还发现取消后未知结果提示仍建议重新授权，已在本轮 UI 修复为“任务已取消，不会继续派发。已发送动作的实际结果仍需人工核对。”，避免将取消误导为暂停。
