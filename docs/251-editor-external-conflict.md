# A30：外部修改冲突的真实桌面验收

2026-09-13。A30 原始标准：在线编辑保存时外部修改，冲突可见、草稿保留，不静默覆盖。

## 主证据

当前本地 Windows 目录包 + 隔离 Alpine OpenSSH 实例 e37057cc-1274-415e-946a-3f3a2377b75d。报告 .cache/desktop-observation-report-63448e01-609e-480f-bd54-e0fa22798bd0。

1. 打开 draft-test.txt（original text），在实际 CodeMirror 中输入带随机标识的中文草稿。
2. 另一条校验指纹的 SSH 连接将远端改成 external text，并通过 SFTP utimes 恢复原 atime/mtime。再次 stat 确认大小和秒级 mtime 均一致。
3. 在中文客户端点击保存及确认保存，出现“远端文件已变化”。实际读取三方对照框，分别等于打开时内容、外部修改内容、用户草稿；独立 SFTP 读取证实原远端修改未被覆盖。
4. 点击“保留草稿，按最新版本继续合并”，草稿仍在，远端仍为 external text。这一步没有自动保存。
5. 再次点击保存，审阅框以 external text 为基准，以用户草稿为待写内容。再次明确确认后，独立 SFTP 读取远端等于草稿。
6. 客户端正常退出，后台端口释放；脚本清理自身 UUID 远端目录。

editor-conflict-result.json 已读取；external-conflict.png 已实际查看，中文冲突信息与三方内容可见，无遮挡。实际 remote read 是最终写入结果证据，不仅凭 UI 状态判成功。

## 失败和能力限制

最初脚本 c9edf414-2f82-4027-a6fd-bc18011831d8 因缺少中文标签变量提前失败，不作验收证据。

随后受控 SFTP 运行 65434d6b-a223-4ed7-871d-9035e7f66be2 已验证冲突可见/草稿保留，但该测试服务器没有声明原子覆盖扩展，因此明确保存被拒绝。中文界面说明原文件未覆盖并报告暂存文件路径，没有假成功。此记录不替代真实 Linux 正常保存证据。

本轮 Linux 场景完成后才认定正常路径通过。原子替换不等于跨进程条件写入：另一个程序仍可能在最后检查与提交之间修改文件，产品审阅页已有说明，本记录不宣称 SFTP 提供跨任意进程的比较交换事务。
