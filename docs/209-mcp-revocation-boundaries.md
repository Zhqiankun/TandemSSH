# MCP 撤销的排队与迟到结果边界

2026-09-12，继续 F10 的活动连接撤销验证。现有 PairingRegistry 会同步撤销身份并断开连接；本轮检查桥接层在异步调度前后的边界。

## 复现与修复

LocalBridgeServer 在收到请求时检查 isAllowed，随后用 Promise 微任务调用核心服务。测试在前一次检查后排入撤销微任务，确定性复现：连接虽撤销，核心回调仍被调用一次。该测试的回调只是受控 status 返回，不能据此断言实际远端命令已越权执行。

修复是在微任务真正调用核心前再次检查 abort、socket.destroyed 和配对是否仍允许。检查到撤销就停止，不进入核心回调。只修改桥接层调度边界，不改变 MCP 工具协议、权限来源或共享模块依赖。

## 验证

- 排队后、核心调用前撤销：客户端断开，核心回调零次。
- 两个请求已经等待结果时撤销：两个客户端 Promise 均拒绝为 MCP_DISCONNECTED，工作收到 AbortSignal，迟到结果不能返回，旧连接不能再调用，重新连接不被接受。
- 原连接的失联回调只出现一次。失败重连有自己的连接 ID 和关闭事件，最初测试误把该事件计为原连接重复通知，已改为按原连接 ID 核对。

桥接、注册表、控制契约共 19 项通过；随后全 MCP 目录 12 文件、44 项全部通过，包含真实 stdio 与系统配对测试，报告 `.cache/mcp-revocation-regression.json`。前述 19 项包含于 44 项，不能相加。ESLint、TypeScript 通过。

桥接时序测试使用真实 OS 管道与签名协议，核心工作为可控 Promise，配对秘密由测试内存端口提供；不冒充本轮所有场景都经过 OS 凭据库。未更改用户日常 Codex 配置。

## 剩余范围

F10 仍需所有工具权限及其他既定矩阵归并。本次不承诺撤回撤销前已经发往远端的操作，既有 unknown 与人工核实语义不变。修复尚未进入公开 alpha.12，后续版本再发布。
