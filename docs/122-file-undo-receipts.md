# 批量文件操作的撤销目标

2026-09-12。检查移动冲突前发现粘贴复制/剪切及拖动移动均按 files.slice(0,successCount) 生成撤销记录。如果前面的文件失败、后面的文件成功，会把失败源路径与成功目标配对，撤销时可能操作错误文件。

现在每个 API 成功返回后才添加具体 originalPath/targetPath/targetName 记录；复制使用服务返回的 uniqueName，剪切及拖动使用实际目标。撤销直接使用这些成功记录，不再从数量反推文件身份。原有逐项继续、成功数量和权限规则不变。

file-operation-history.ts 属于文件管理撤销领域，只构造路径记录，供三个成功分支复用，不持有外部资源。5 项记录/批量测试及 tsc -b 通过；lint 无错误，FileManager 保留原 windowId 警告。测试覆盖前项失败后项成功、自动改名目标及根目录拼接，但尚未执行真实桌面撤销整链。

本轮尚未替换 moveItem 的覆盖行为；先修复部分成功记录是后续增加冲突拒绝的前置条件。公开 alpha.5 未包含此修复。
