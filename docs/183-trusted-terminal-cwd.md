# 同一终端的确认式可信目录查询

2026-09-12。B11 核对发现 get_cwd 原先在独立 SSH exec 通道运行 pwd，结果属于新进程的默认目录，不能代表用户已经 cd 的交互终端；失败还会返回虚假的 /。

## 最终行为与契约

终端工具栏和快捷入口统一调用确认式目录读取：用户确认处于空闲 POSIX Shell 提示符后，get_cwd 携带 shellReady=true 和 requestId。只读查询使用同一已认证 PTY 的现有随机标记帧解析器，15 秒上限，不建立第二条 SSH 连接，不将任意 OSC 输出当成可信目录。

working-directory.ts 负责读取边界：连接就绪、明确确认、人工持有控制权、同一控制对象仅一条查询。准备后、写入前再次检查控制权；自动任务持有控制权时拒绝，不隐式接管。

SessionControl 增加内部人工输入版本计数及只读 getter，不改变已有快照 schema。查询响应仅在 generation/epoch 与输入版本未改变时有效；路径必须是无终端控制字符的绝对 POSIX 路径。超时、解析失败和未知目录不回退到根目录。

WebSocket 入口继续使用既有所有者权限检查。界面按 requestId、主机身份和当前 WebSocket 匹配响应，过期响应不会打开其他主机或连接的目录。只支持明确确认的 POSIX Shell 查询；其他 Shell 或无法确认提示符时用文件浏览器手动选目录，不能声称已获得其当前目录。

## 模块边界

终端组合入口创建既有 PtyCommandExecutor 并传入只读准备端口；working-directory.ts 管理目录读取生命周期，SessionControl 管理输入/控制权，页面管理确认与响应匹配。没有通用命令执行参数或新增模型权限，也没有新增外部依赖。目录值是查询时刻的观察结果，不承诺远端之后永远不改变。

## 验证

工作目录逻辑 9 项、原有控制权 12 项、真实 Linux SSH 1 项，共 22 项通过。真实测试手工 cd 到包含中文与单引号的目录，再从同一 PTY 读取并匹配；独立 exec 的 pwd 与它不同，直接复现旧方法问题。自动控制期间读取被拒绝且不改变所有者；读取期间人工再次 cd，旧结果被拒绝，下一次查询得到新目录。
