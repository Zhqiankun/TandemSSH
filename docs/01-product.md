# 产品需求

状态：v0.2 设计草案。产品：TandemSSH（同舟 SSH）。

## 1. 目标与使用者

面向独立开发者和管理少量服务器的运维人员，解决部署时在 SSH 工具、日志、文件管理和 AI 对话间反复切换的问题。

主要使用环境为 Windows 本机连接远程 Linux 服务器。用户希望保留直接操作终端的能力，同时让 AI 读取获准的上下文、提出方案并执行授权任务。

成功的体验：用户能回答“在哪台服务器、谁执行了什么、结果是什么、下一步是什么”，并能在 AI 工作中收回控制权。

## 2. 用户已经明确的要求

| 编号 | 要求 | 对设计的约束 |
| --- | --- | --- |
| R01 | 项目开源 | 核心 SSH、协同和自定义模型功能不依赖本软件会员 |
| R02 | Windows 桌面优先 | 第一版必须在干净 Windows 环境安装、打开和使用 |
| R03 | 人机协同 | 人和 AI 操作同一 SSH 会话，输出和上下文可衔接 |
| R04 | 随时接管 | 接管确认后旧 AI 写入不得进入会话；交还必须是明确操作 |
| R05 | 执行可见 | 命令、文件操作、执行者、状态、输出与失败原因可追踪 |
| R06 | 可全部交给 AI | 授权范围内连续执行；不自动扩大服务器、权限或预算 |
| R07 | 自带 API | 自定义接口地址、模型和 Key，直接使用用户选择的服务商 |
| R08 | 可配置黑白名单 | 全局、服务器组、服务器和任务规则可管理，冲突可解释 |
| R09 | 自定义命令流程 | 多条命令打包为配置，按顺序执行，可手动或由 AI 调用 |
| R10 | 完整基础 SSH/SFTP 功能 | 用户明确要求上传、下载、在线编辑；常规基础项按专门清单补齐，不以 AI 功能代替 |
| R11 | 结合 FinalShell、XTerminal，评估开源改造 | 功能结合与代码来源分开；先核对许可、构建、功能和接管改造边界 |

用户“命令黑白名单可以陪孩子”在本稿中按“命令黑白名单可以配置”理解。如含义不同，修订 R08 后再实施对应功能。

## 3. 工作方式与控制权分开

| 工作方式 | AI 的行为 | 谁可以向终端输入 |
| --- | --- | --- |
| 人工 | 可聊天、解释用户提供的上下文；不执行操作 | 人工 |
| 协同 | 提出动作，允许后执行；首版默认逐项确认 | 拥有本次会话控制权的一方 |
| 自动 | 在已授权的服务器、动作、规则和预算内连续执行 | AI；人工可随时收回 |

“自动”不是取消黑名单、凭据保护或服务器权限。工作方式和输入控制权是不同状态：用户接管后，原自动任务进入暂停状态，而不是偷偷在后台继续写入。

用户可通过配置减少普通动作确认。显式拒绝规则不能被“本次全部允许”覆盖。未知或无法可靠判断的操作应暂停，说明原因和所需选择。

用户已确认自动模式允许在本任务内预先授权重启服务、覆盖文件等动作；批准仅对当前范围有效。人工保留自由终端接管，黑白名单硬限制 AI、MCP、流程及受控命令入口。

## 4. 第一版功能清单

R01—R11 来自用户要求。首版必须覆盖完整 SSH/SFTP 基础能力与协作核心；下表把常规基础能力具体化，详细实现边界在实施前冻结。

| 编号 | 功能 | 首版边界 |
| --- | --- | --- |
| F01 | 服务器管理 | 新增/编辑/复制/删除、分组、收藏、搜索、最近连接、配置导入导出 |
| F02 | SSH 连接 | 密码、带口令私钥、SSH agent、交互认证、基础跳板连接、主机指纹核验、保活与重连 |
| F03 | 终端工作区 | 多标签、分屏、搜索、复制粘贴、快捷键、编码、字体主题、历史与连接状态 |
| F04 | 协作控制 | 接管、交还、暂停任务、取消队列、发送中断分别呈现 |
| F05 | 模型配置 | OpenAI 兼容工具调用接口、流式响应、自定义 URL/模型/Key、连接测试 |
| F06 | AI 任务 | 目标、步骤、操作建议、执行结果、有限轮次工具循环 |
| F07 | 规则管理 | 命令允许/拒绝/确认、服务器范围、文件路径范围、规则试算 |
| F08 | 执行时间线 | 人/AI/MCP 来源、目标、操作、状态、输出片段、审批及策略版本 |
| F09 | 完整文件工作台 | 文件/目录上传下载、拖拽、队列、暂停/恢复、在线编辑、目录操作、权限和冲突处理，见 B04—B11 |
| F10 | 外部 MCP | 本机接入，共用策略和会话控制；首版仅开放有限工具 |
| F11 | 自定义命令流程 | 串行步骤、参数、工作目录、失败停止、进度、暂停/接管/恢复和无凭据导入导出 |
| F12 | SSH 隧道 | 本地、远程和动态转发，启停、状态、端口冲突和作用范围 |
| F13 | 服务器状态 | CPU、内存、磁盘、网络、系统和进程查看；采样状态可见 |
| F14 | 设置与数据 | 本地配置备份/恢复、日志位置与清理、界面偏好、导入预览 |
| F15 | 本地终端 | Windows PowerShell / 可选已安装 Shell，用于本机命令与上传前检查 |

先交付服务器、人工终端和文件工作台的内部验证版，再接协作与模型；F01—F15 和[基础清单](09-base-features.md)必须一起验收。基础文件功能不能仅以“以后接插件”代替首版交付。

文件操作不一定表现为一条终端命令。例如 SFTP 上传以文件操作卡片呈现，不能在时间线中隐藏。对于写入、目录、身份或配置变化，AI 获得结果后必须重新判断后续步骤。

## 5. 首版暂不承诺

- 云端账号系统、云同步、多人远程协作和跨设备接管。
- 多个 AI 同时执行、批量生产发布或无人值守后台调度。
- Windows 远程 Shell 全兼容、RDP/VNC、插件市场和完整 IDE。
- GUI 关闭后自动继续、网络断开后无损恢复任意进程。
- 自动数据库迁移回滚、任意命令回滚、对所有 Shell 语法的准确安全识别。
- macOS/Linux 正式安装包、复杂多跳堡垒机的全兼容；基础单跳与交互认证属于首版。

这些是范围提案，不是用户放弃的需求。需要时可调整交付顺序。

## 6. 关键验收故事

### S01：人工连接

用户保存测试服务器，核对主机指纹，连接后运行普通命令。用户能看到真实输出；重启应用后连接配置仍在，凭据没有出现在导出的配置文件中。

### S02：AI 协同排查

用户选择当前会话，让 AI 分析部署失败。AI 展示将执行的目标、命令、目录与理由；用户批准后执行，结果加入时间线和模型上下文。切换标签不会使已经批准的动作改到另一台服务器。

### S03：接管与交还

AI 执行多步骤任务期间，用户接管。系统确认接管后，排队动作、迟到的模型响应、外部 MCP 写入都不能越权落入终端。用户执行修正命令，再交还；AI 能看到被允许保留的新增记录，并重新生成后续动作。

### S04：自动部署

用户选择一台测试机和已审核的部署脚本，设置本次允许范围与执行上限。AI 执行并检查服务状态。超时、输出缺失或网络断开时显示“结果未知/需要检查”，不能把连接中断当成执行成功。

### S05：规则冲突

服务器规则允许某脚本，但全局规则拒绝该操作。系统阻止执行，并显示全局拒绝规则的来源。用户编辑规则前可试算命令，保存后新规则使旧审批失效。

### S06：自定义命令流程

用户把“检查目录 → 拉取镜像 → 更新服务 → 检查状态”保存成流程，运行时选择服务器和目录参数。系统逐步检查和执行；某一步失败默认停止后续步骤。中途接管后不重复已完成步骤，重新运行失败步骤必须是用户明确选择。流程可导出为不带密码和 API Key 的配置文件。

### S07：完整文件管理

用户将文件夹拖入远端目录，查看总进度与逐项结果；暂停后可在验证两端文件未变化后恢复。打开远端配置文件修改并保存，系统保留编码和换行，发现远端被其他程序修改时显示冲突。关闭终端标签不会擅自取消仍活跃的文件工作区和传输。

## 7. 开源与费用原则

- 软件核心功能可自行构建和运行，不需要 TandemSSH 账号。
- 模型请求直接连接用户配置的端点；模型服务商可能按量收费。
- 本地兼容模型服务可作为端点候选，但能否执行工具必须经过能力检测。
- 不内置商业中转商 Key，不默认切换到收费备用模型。
- 许可证随选定底座评估：Termix 的 Apache-2.0 或 Tabby 的 MIT 需保留；自有扩展许可与署名在发布前确认，不把上游代码统一改标为 MIT。

## 8. 实施前仍需确认

1. 是否采用开源底座，以及 Termix 独立桌面模式的原型是否满足本机运行和协作改造要求。
2. 具体支持的复杂堡垒机和首次真实 SSH 验证环境；人工自由接管的规则边界已确认。
3. F01—F15 的详细兼容性、支持的文件编码/大小及基础跳板配置范围。
4. 公开发布时的版权署名。日志默认值已确认：本机脱敏记录 7 天/100 MB，完整录制手动开启。

这些待定项不阻碍完成文档，但会阻碍相应行为被当作最终实现要求。
