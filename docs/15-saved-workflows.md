# 已保存流程：当前实现与验证

更新日期：2026-09-07。本页说明已实现的流程核心与中文桌面界面；完整目标与验收仍以第 8 份文档为准。

## 当前可以复用的核心

- 每用户保存流程名称、版本、分类、参数定义、步骤和可用主机；配置修订号用于拒绝并发覆盖。
- 参数以独立 argv 值绑定，支持字符串、整数、枚举、布尔开关和远端目录。布尔参数需要明确给出两种参数列表。
- 运行预览固定定义修订号、参数结果、目标会话、策略修订号与控制权版本。导入和预览不执行命令；开始只建立待人工授权的任务。
- 预览后的模板修改、策略修改、主机身份变化或控制权变化使旧预览失效。同一个开始请求不重复创建任务，更改模式需重新预览。
- 已保存流程通过既有 TaskRuntime 和 OperationGateway 执行，继续共用人工终端。普通临时命令计划仍保留共享 Shell 的行为；保存的流程默认每步使用明确目录，也可声明 stateful-shell。
- 首次授权确定未指定的默认目录后，同一流程保留该目录基线；交还后的新授权仍检查目录范围。若人工切到其他部署目录，需核对旧流程是否仍适用，不静默改写定义。
- 默认失败停止、没有自动重试。明确配置 continue 时仅继续已知退出失败；未知结果、审计缺口或接管均不会由该选项绕过。
- 失败后继续，以及人工核对后跳过未知/失败步骤，最终显示“已结束（含失败步骤）”；原始操作结果保持不变。
- 单步超时只在旧授权仍有效时请求 Ctrl-C；记录为结果未知和“已请求中断”，不声称远端副作用已撤销。人工接管后迟到的超时不会向新操作者发送 Ctrl-C。
- 多行脚本作为明确的 sh/bash -c 动作展示，受解释器规则和审批约束。多行 argv 在发送前编码，避免终端行编辑把参数中的换行当成另一条输入。

## 模块边界

| 位置 | 职责 |
| --- | --- |
| types/workflow.ts | 流程定义、保存项与预览数据契约 |
| collaboration/workflows/definition.ts | 严格格式校验与类型化参数编译，无数据库或终端依赖 |
| collaboration/workflows/library.ts | 保存、修订冲突、导入检查、导出、不可变预览与创建任务，通过端口访问外部能力 |
| collaboration/workflows/production.ts | 连接现有设置仓库、主机所有权、SessionManager、TaskRuntime 和审计 |
| collaboration/workflows/http-routes.ts | 可信人工接口的输入校验与响应映射 |
| collaboration/policies/schema.ts | 共用规则格式校验；读取损坏配置时拒绝执行，不降级为默认放行 |

规则试算使用真实会话的主机/分组信息和提交的草稿规则，不保存规则、不授权、不执行命令。保存策略会先撤销旧任务授权，并记录保存意图。

## 已接线的本机接口

以下路由继承现有登录认证和人工入口限制，旧 API Key/MCP 身份不能调用人工授权接口。

| 方法与路径 | 行为 |
| --- | --- |
| GET /tandem/workflows | 读取本用户流程库 |
| POST /tandem/workflows | 新建或按 expectedRevision 保存 |
| DELETE /tandem/workflows/:id | 按修订号删除定义 |
| POST /tandem/workflows/inspect-import | 严格检查导入定义，返回检查提醒 |
| GET /tandem/workflows/:id/export | 返回定义及硬编码秘密检查提醒，不包含运行实参与主机绑定 |
| POST /tandem/workflows/:id/preview | 固定参数结果、目标和版本，返回规则试算 |
| POST /tandem/workflows/start | 从有效预览建立待人工授权任务 |
| POST /tandem/policy/trial | 只读试算草稿规则；不会修改现有权限 |

## 中文桌面界面与实际操作验证（2026-09-07）

在终端的“协作执行”面板底部打开“流程库”或“命令黑白名单”。两个窗口都提供接管入口。

流程库可以图形化编辑名称、版本、分类、说明、参数及默认值、服务器范围、顺序步骤、参数引用、目录、超时、失败行为、环境变量和多行脚本。无需编写 JavaScript。参数或运行方式变化会清除旧预览；明确拒绝的步骤禁止创建执行任务。取消勾选最后一台主机不会自动扩大为全部主机。

导入 JSON 后展示完整可编辑定义，勾选审阅确认后才保存；导出先展示 JSON 和秘密检查提示，勾选检查确认后才能下载。运行预览只读，创建任务后仍需进入既有任务授权流程。

黑白名单可编辑全局、分组、主机、任务四种作用范围；按程序名或完整参数列表配置拒绝、确认、允许规则。规则试算使用真实会话与草稿，不修改现有策略，不执行命令。保存前明确提示旧任务授权失效；版本冲突会保留当前草稿并报错。

新增界面责任：WorkflowLibrary 编排流程库、导入导出与运行预览；WorkflowDefinitionEditor 只编辑定义；initial-definition 提供初始草稿；PolicySettings 管规则编辑与试算。workflow-api / policy-api 各自负责 HTTP；collaboration-api 的 targets 入口提供本用户主机元数据，服务端只投影名称、地址、端口和分组，不返回凭据。前端不导入后端私有实现。

### 桌面与真实 SSH 证据

使用独立 .cache/tandem-workflow-profile-3aa2a7b7 启动 Windows 验证包，连接仅监听回环地址的 SSH 测试服务器，其远端 Shell 是本机 Git Bash。

- 完全通过图形界面创建参数化流程。保存后模板修订号为 1，任务数为 0。
- 自动模式依次运行 pwd、printf，真实退出码均为 0。含中文、分号和命令替换字符的参数作为原值输出，没有成为额外命令。
- 修改模板增加 printenv 后修订号为 2，先前任务仍保留修订号 1 的两步快照。
- 协作模式在第一步审批前等待。接管后旧操作成为 cancelled-before-send；人工在终端设置环境变量，重新授权并逐条批准后，流程读到了“人工接管成功”。
- 在另一待审批任务运行期间，规则草稿试算 printf 显示拒绝，但已保存策略仍为修订 1，任务仍在等待。保存规则后策略升到修订 2，任务交还人工，旧操作未发送。
- 新流程预览命中已保存的拒绝规则，创建按钮禁用。
- 实际导出 JSON 为 1268 字节；Electron 下载完成事件的已接收字节与总字节相等。将这份磁盘文件通过实际文件输入重新导入，审阅前不能保存，保存后定义数从 1 增到 2，任务数保持 0，三个步骤与导出文件一致。

主要证据：.cache/workflow-live-evidence.json、.cache/workflow-download-evidence.json、.cache/workflow-import-evidence.json、.cache/workflow-roundtrip-verify.cjs。导出测试主进程观察器仅为当前隔离应用选择工作区下载路径，不加入产品代码，不修改用户的常用下载设置。

下载联调中，浏览器下载路径控制不适用于 Electron 的独立持久会话；主进程观察器使用未规范化的 Windows 路径时也收到 interrupted/0 字节。测试脚本改用系统绝对路径后实际下载完成。没有把“已发起下载”的界面提示作为完成证据。
