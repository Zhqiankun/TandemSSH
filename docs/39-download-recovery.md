# 下载跨重启检查点与恢复

2026-09-09，单文件下载的加密检查点、中文恢复入口与实际 Windows 重启/中断验收已实现。对应 B05/B06、A28/A29/A32：最终需要已暂停或异常中断的下载在重启后可发现，重新授权并核对两端后继续；同时保留后续上传、目录批次及 AI/MCP/流程恢复的完整范围。

## 本轮责任与依赖

- DownloadService 拥有远端来源检查点。只从已暂停、无并发读取的可信来源导出用户、目标身份、已接受公钥、规范路径、属性、整文件和分块摘要；不保存密码、旧连接 ID 或批准。恢复使用新连接重新检查身份和完整来源，返回新的预览 ID。
- DownloadSink 拥有本地部分文件检查点。持久化回调成功后才放开原能力和句柄，失败保留当前可恢复记录；只允许可信主进程调用恢复核心，不增加接受任意本地路径的渲染层入口。
- 原生恢复重新核对父目录、原有目标、临时文件身份、链接/硬链接、已确认块内容；目标发生变化或已确认块损坏时拒绝。返回暂停状态和新的能力 ID，不能自动继续或复用旧能力。
- 重启后未完成块尾部可以保留到恢复审阅阶段；只有确认续传后才沿用已有 resume 的已验证前缀截断逻辑。恢复预览本身不截断或提交文件。
- 密文检查点保管、用户身份/窗口私有通道、恢复清单 UI、任务重建与审批属于后续组合入口；仅核心通过不等于产品的重启续传已经交付。

实现前先固定源/目标检查点 schema，禁止把历史日志或客户端任意 JSON 当作新的授权。业务依赖方向为恢复协调器 → 来源/原生能力 → SFTP 或选定文件；加密持久化适配负责存取，不能反向调用执行流程。

## 验收与验证

1. 在本机真实 SSH/SFTP 下载第一块，导出检查点并结束旧来源/原生实例；新实例重新连接后验证来源和本地前缀，继续剩余内容并校验最终字节。
2. 原连接 ID、原生能力 ID 不能继续调用；恢复没有恢复旧授权。
3. 主机公钥、源文件内容/属性、规范路径、父目录、原目标或已确认块改变时拒绝恢复，不删除相关文件。
4. 持久化失败保留当前记录和部分文件；并发重复恢复、过大/畸形检查点和错误身份被拒绝。
5. 未知提交不能作为安全暂停重新执行；自动与协作继续沿用任务网关、人工接管和重新授权。

相关测试采用真实文件及回环 SFTP、失败注入和既有下载/自动协作回归。完整 UI 与实际应用重启证据另行记录，不能用对象重建测试替代整应用验收。

## 本轮已实现

新增 backend/files/download-checkpoint.ts 和 electron/download-checkpoint.cjs，分别约束服务端来源与原生部分文件的持久化数据。DownloadService.checkpoint 只导出已暂停来源，restore 用新请求与新连接完整校验，再建立新的预览。来源检查包含当前用户、实际目标身份、公钥、规范路径、文件属性、整文件和全部块摘要。

DownloadSink.suspend 在已暂停的已校验前缀上调用持久化适配，成功后才关闭并移除旧能力。持久化失败时当前记录和字节仍在；成功后即使句柄关闭异常，旧能力也不能再写，随后释放仍保留检查点部分文件。重启恢复要求新的授权守卫和重新核验的远端来源摘要，本地/远端检查点不匹配直接拒绝；覆盖已有目标必须重新确认。

恢复检查父目录与目标基线、生成临时文件名称/身份、链接和硬链接、已确认块；同一进程重复恢复同一个部分文件被拒绝。返回新能力并保持 paused，不自动派发剩余块；多出的未确认尾部仅报告长度，确认 resume 后才截断到已验证边界。Unknown 提交不能导出为安全暂停。

本轮没有新增渲染层/HTTP 的任意检查点导入接口；这些方法仅供后续可信协调器调用。检查点 schema 校验本身不构成授权，必须在加密存储和当前用户/窗口校验完成后使用。没有新建 common/shared 模块，来源规则仍属于 DownloadService，本地文件规则仍属于 DownloadSink。

## 2026-09-09 产品接入方案

主进程新增 DownloadRecoveryVault，使用 Electron safeStorage 加密整个恢复记录，拒绝不可用/basic_text 后端；记录按真实应用用户隔离，文件为生成 ID，采用临时文件同步后替换。来源和原生检查点同份保存。已有草稿存储保持独立业务归属，本轮不把文件草稿 API 当作下载授权。

后端 DownloadRecoveryTickets 只向已认证人工请求发一次性票据，绑定主进程注册的窗口、用户、动作及新连接；私有父子进程桥接提供 claim/restore/release，渲染层不能提交原生检查点或任意本地路径。票据最大数量、有效期和并发均有上限，窗口关闭和账号重置撤销未完成请求。

恢复记录包含 available/claimed/committing/unknown/completed/cancelled 状态。恢复先持久化占用，再核对来源和部分文件；新的源与原生能力均归当前队列。已保存检查点的恢复任务在窗口重置时保留部分文件，应用重启后从已保存的、重新校验的前缀继续，未确认尾部需要重新下载。提交前先记 committing；不明确的完成结果只允许核对并清理，不自动重试覆盖。占用绑定启动标识和进程 ID，旧进程仍存活时不能重复恢复。

中文入口设在下载队列：暂停后“保存进度供重启恢复”；文件管理器中可打开恢复清单，显示来源、目标、保存进度与状态，使用当前已连接服务器核对后恢复到暂停队列，再由用户继续。首个组合入口先接单文件下载，目录批次、上传、AI/MCP/流程仍保留在最终范围。

## 产品入口已实现与验证

下载队列现在可在单文件暂停后选择“保存进度供重启恢复”。确认加密保存成功后，该行变为已保存状态，旧来源与原生能力释放；清理队列行不会删除恢复记录。恢复任务再次暂停保存时更新原记录，不创建指向同一部分文件的重复记录。

文件管理器即使队列为空也可打开“查看可恢复下载”。清单按当前认证用户读取，展示服务器、路径、目标、进度和状态。使用当前连接核对来源后，恢复回暂停队列，确认继续才派发剩余块；已有目标必须再次确认覆盖。异步恢复前预留队列容量，账号切换使旧结果失效。用户可以明确确认放弃并删除本任务的部分文件；最终目标不因此被删除。结束记录可单独清除。

主进程通过 safeStorage 加密记录；不可用时拒绝保存，Linux basic_text 不作加密后端。票据从受人工认证保护的 HTTP 入口发出，绑定主进程注册的窗口和真实用户；原生路径及检查点不由渲染层提交。恢复来源的后台记录在窗口重置或结束后释放。

占用与提交状态在文件 I/O 前持久化。仍存活的旧进程占用不能再次恢复；提交中断保留待核对状态，不直接重试。核对会验证最终文件并仅清理身份仍匹配的本任务临时文件；提交仍在进行时禁止核对清理。每条记录读写有 4 MiB 上限，每用户最多 128 个生成文件/64 MiB；达到限制明确拒绝，不自动丢弃活动检查点。
