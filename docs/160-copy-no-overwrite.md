# 远端复制不覆盖与独占临时目录

2026-09-12。修复 copyItem 使用时间戳副本名和直接 cp -R 导致已有文件被覆盖、目录被合并的风险。

## 边界与实现

新增 hosts/file-manager/copy-plan.ts，属于文件管理模块，负责随机副本名、路径引用和远端命令计划。action-routes.ts 依赖该公开函数，继续负责用户/会话权限、通道、60 秒超时和 HTTP 生命周期；没有新增共享层或外部依赖。

副本名使用 UUID；源名称部分按 UTF-8 字节截短，最终名称不超过 255 字节且不截断字符。先以独占 mkdir 创建同目录临时目录，只有创建成功才登记清理。目录自身权限为 700，umask 限制在 mkdir 子 Shell 内，不改变正常副本权限规则。cp -RP 完成文件、目录或链接副本后，使用 mv -n -T 发布；发布前拒绝已有目标，发布后检查临时副本是否仍存在，识别 mv -n 跳过却退出 0 的情况。任何已有目标均不会作为目录容器合并。没有覆盖式 fallback。

冲突退出码 73 映射 HTTP 409/FILE_TARGET_EXISTS，复用已有前端 API 错误保留与中文提示。超时/断连契约保留：已派发操作结果可能未知，必须刷新核对。退出时清理已拥有的临时目录；连接中断或进程被强杀时不能保证远端 trap 执行，可能留下 .tandem-copy-*，不能据此认定复制成功。
