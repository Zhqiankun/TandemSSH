# 监控采集动作与暂停控制

本阶段按 B12/F13/A35 实施服务器 CPU、内存、磁盘、网络、运行时间、系统和进程采集的可检查动作、周期、停止和权限边界。主智能体独立实施；原始完整验收目标保持不变。

文件责任与依赖：`types/monitoring.ts` 定义公开采集快照，不带主机凭据或原始命令输出；`hosts/metrics/collection-catalog.ts` 管理有限只读命令与磁盘路径参数；`collection-runtime.ts` 管理每个实际请求用户/主机的采集批次、输出和时间上限、取消与聚合记录；`collection-production.ts` 适配现有权限和本机脱敏审计；`collection-routes.ts` 只负责认证后的请求与响应；现有 `metrics/index.ts` 编排采集器/调度并释放资源；UI API 与监控动作面板负责展示和暂停/恢复。

依赖方向为页面 → API → 路由 → 采集用例 → 有限只读命令/SSH 独立 exec 通道/权限与审计适配。采集器通过命令 ID 调用，不向监控接口开放自由 Shell 字符串。既有进程结束、服务重启等操作不迁入监控只读通道。没有增加通用 `common` 模块或改变共享交互 PTY。

验收使用真实回环 SSH exec 通道及 HTTP/UI 测试，检查固定模板、路径转义、权限拒绝、采集中暂停、迟到通道回收、输出/时间上限、结果记录和中文操作。按采集批次聚合记录，原始输出不进入审计；本机记录继续使用既有 7 天/100 MB 留存服务。

## 实施与专项验证

已迁移 11 类常规主机采集器到 26 个固定只读模板。磁盘自定义路径仅作为转义参数；监控接口不接受自由命令。每批最多 64 个命令、同时最多 4 个通道、每命令最多 1 MiB 输出、整批最多 4 MiB 与 45 秒；输出超限会结束整批。原始输出只供指标解析，不进入聚合审计。

每个批次及命令派发前检查实际请求用户的主机查看权限；监控缓存读取和启动/停止也增加相同权限门禁。已有管理动作、交互 PTY 和 Proxmox 专用采集未迁入本目录，不把它们声称为已纳入此只读目录。

新增中文采集面板显示实际周期、命令模板、最近批次、命令结果/退出码/耗时，以及暂停和恢复按钮。暂停当前采集并阻止后续采样；面板保留最后数据。永久停用和周期修改继续使用已有主机设置。最近批次列表保留在本次应用进程内（每用户/主机最多 20 批，面板显示最近 5 批），审计继续使用本机 7 天/100 MB 的既有持久化服务。监控事件尚未加入通用任务历史分组视图，不将内存列表称为跨重启历史。

真实 SSH 专项证明：固定内存命令解析为 1 GiB / 50%；监控不申请 PTY；暂停正在运行的采集通道后，同一连接上的人工 shell 仍能回显中文输入；恢复需要显式操作；输出上限、迟到通道、再次权限核对、审计写入失败、禁用采集器及 4 通道并发上限均验证。HTTP 和中文组件测试覆盖权限拒绝、暂停/恢复、切换主机后迟到响应不会覆盖新主机，以及停用时不能恢复。最终组合 **3 文件 / 11 项通过**，日志 `monitoring-final-targeted.log`。

首次 SSH 夹具在结束通道后才发退出状态，以及未读取 stdin，导致“退出状态未知”和关闭事件观察失败；已改成先发退出状态，并消费 stdin。保留 `monitoring-collection-tests.log` 首次失败，后续 `monitoring-collection-recheck.log` 通过。最初从仓库根目录执行测试未匹配应用测试目录，记录在 `monitoring-first-tests.log`，不计作测试通过。

## 真实桌面发现与修正

首轮桌面成功显示中文采集面板、实际模板与 1 GiB/50% 内存、86400 秒运行时间，但等待下一次 5 秒采样时超时。现场 `.cache/desktop-observation-report-1fbb6eeb-759a-4cc3-8b03-fc5d63ffdb87`，`desktop-failure.json` 的阶段为 `monitoring-pause-running-sample`。这是实际调度问题：原 MetricsCache 固定缓存 30 秒，覆盖较短的主机采样周期；没有通过延长测试等待掩盖。

缓存读取现在限制在配置周期内，停止时清空本主机缓存；默认缓存上限仍为 30 秒。新增时间边界测试证明 5 秒设置下第 4999 ms 可读、第 5000 ms 过期，清理后不可读。桌面还发现运行时间的 `1d 0h 0m`/`N/A`，已改为客户端按数值和语言格式化。缓存/采集/HTTP/中文面板组合 **4 文件 / 30 项通过**，日志 `monitoring-cache-recheck.log`。实际桌面修复后的结果继续追加，原失败保留。
