# 引号与 CLI 参数的折行脱敏收尾

## 复现与修复

在第 244 号记录的真实终端折行缺陷基础上，检查同一出口中的带引号值和 CLI 参数。新增四项测试修复前全部失败：配置赋值的带空格折行值、CLI 的带空格折行值、折行 CLI 参数名和转义双引号后的残留。

privacy/redaction.ts 现在在模块内部复用一个值模式：支持闭合单引号、闭合双引号中的转义字符及折行，也保留先前无引号折行支持。配置赋值和敏感 CLI 参数均使用该规则。CLI 参数名复用敏感名称的折行模式。

该模块本身即负责 AI/MCP 等出口脱敏，新增常量均为私有实现；没有新通用模块、对外 API 或依赖方向变化。人工终端原始显示不经过本次替换。

## 证据

- 修复前日志 .cache/quoted-redaction-before.log：4 失败、18 通过。
- 修复后脱敏专项：22 项通过；包括双/单引号值、CR LF/CR CR LF 两种折行、转义双引号和非秘密文本换行保留。
- AI、MCP、文件三个测试目录：67 文件、457 项通过，日志 .cache/quoted-redaction-regression.log。专项包含在目录结果中，不相加。
- TypeScript 通过；ESLint 0 错误，保留测试文件原有两处 any 警告；git diff --check 通过。

这些是受控字符串与现有调用方回归，不是新一轮完整桌面验证。第 244 号成功桌面报告仍准确描述当时包的内容，不宣称其包含这次修改。

## 限制

仍是基于已识别敏感名称和常见格式的脱敏，不是任意 Shell 源码解析器，不声称覆盖未闭合引号、任意拼接、所有控制字符或未知秘密。未知格式不能依靠本规则获得绝对保密保证。跨行秘密后的相邻文本可能被保守多遮盖。
