# 网络监控计数与采样间隔修复

## 实际缺陷

network-collector 原本按空白拆分整行。当 /proc/net/dev 的接口冒号与较大计数紧贴（例如 eth0:123456789）时，计数被拼入接口名，真实 eth0 查询不到数据。直接将完整计数转为 Number 还会在超过安全整数后丢失小增量。

另外，速率分母从第一次请求发出前开始，额外包含第一次 SSH 请求耗时。100ms 读取、500ms 间隔、100ms 读取的场景中，1000 字节增量被显示为 1429 B/s，而两个样本间隔对应 1667 B/s。

## 实现边界

仅修改网络采集器：先分开接口名和冒号后的 16 个字段；累计计数验证为 uint64 十进制字符串并保留原文；差值用 BigInt，再将安全差值换成数值速率。计数倒退、缺失、非法格式、无效时间及无法安全表示的速率返回 null，不显示成零或 NaN。

测量间隔从首个读取完成后开始，累计字节返回第二个最新样本。公开接口字段不变，不影响 SSH 执行权限，也不增加共享工具模块。

## 验证

新增紧贴冒号、2^53 以上的 1 字节增量、非法时间/计数边界，以及模拟 SSH 延迟的采集测试。修复前计数/边界测试 8 项失败；计时测试独立复现 1429 而非 1667。修复后监控目录 17 文件、122 项全部通过，TypeScript、ESLint 通过。

本轮使用真实解析器与受控命令端口，不声称已跑真实 Linux 网络负载。SSH 时延变化仍会影响客户端采样时刻估算，不是内核精确速率测量。F13/B12 的其他 CPU、磁盘、进程及完整服务器矩阵仍需继续验收。
