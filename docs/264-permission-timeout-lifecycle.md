# 权限请求超时后的派发与通道清理

2026-09-13，A34 生命周期修复。

## 复现

原 changePermissions 的 10 秒计时器只回复超时，既没有使排队命令失效，也没有关闭已打开的 SSH 通道。新增两项受控队列/虚拟时钟测试在修复前均失败：超时后仍派发一次 chmod；超时通道关闭次数为 0。

## 修改

该路由新增请求结束标记及当前通道引用。超时先标记结束、关闭已有通道，再回复 408。通过既有 execChannel 的 beforeOpen 回调，在真实通道排队结束、调用 SSH exec 前检查请求状态、响应状态、会话对象和会话归属。

迟到的通道回调会关闭通道并返回；结束后的输出、close/error 不再覆盖已结束响应。正常完成和错误仍清理计时器。

责任限于既有权限路由，不修改共用 execChannel 契约，不新增共享抽象、数据库或依赖方向。此次并发行为变更已对已排队/已打开两阶段分别验证。
