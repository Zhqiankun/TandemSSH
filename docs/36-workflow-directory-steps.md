# 保存流程中的目录步骤设计

2026-09-09，已完成基础实现、中文编辑器与本机桌面双模式验收。目标是在同一父任务中保存并运行“上传目录 → 命令 → 下载目录”，继续遵循任务级授权、逐项预算、自动/协作模式和人工接管。

## 契约与职责

- 保存格式升级为 schemaVersion=3，保留 v1 命令和 v2 单文件定义的读取。文件槽位以 kind=directory 区分目录授权；模板只保存槽位名，不保存机器路径、授权 ID 或版本。
- 新增 upload-directory / download-directory 动作，远端路径仍支持参数。目录目标已存在时可配置 fail、skip 或 overwrite，默认 fail；目录本身允许合并，链接/特殊文件仍排除。覆盖同时需要动作和本地授权许可。
- 编译为目录任务步骤，步骤数仍对应用户保存的流程。一个目录步骤内部驱动预览、清单确认和逐项动作，每项都有独立 operationId、审批、规则和预算。
- TaskRuntime 持有步骤游标，通过目录步骤端口获得下一个动作和接收已验证结果。端口实现复用 DirectoryTransfers，不创建另一份任务、租约或模拟流程。
- 目录步骤未结束时，后续命令不执行。接管后保留游标，重新授权前先吸收已成功的当前项；已完成项不重复。确认前失败可重新预览；进入逐项传输后不能暗中更换本地目录绑定。
- 目录预览在流程使用期间保留占用状态，手工释放不能破坏尚未完成或暂停的步骤。步骤完成/取消后解除占用，未知结果仍遵守既有清理限制。

主智能体负责这些变更。types/workflow.ts 与 types/task-plan.ts 定义持久化/编译契约；workflows/definition.ts 解析和编译；tasks/directory-plan-port.ts 定义执行端口；collaboration/files/directory-workflow.ts 负责目录步骤游标和冲突选择；TaskRuntime 负责编排、授权、审批和重新授权；UI 只处理编辑和绑定展示。

依赖方向为流程编辑/AI/MCP → 流程库与编译 → TaskRuntime → 目录步骤端口 → DirectoryTransfers → 原生/SFTP。文件步骤端口不反向调用 TaskRuntime 的私有方法。

## 验收场景

1. v1/v2 兼容；v3 目录动作和槽位类型严格匹配，非法本地路径/绑定字段不能进入模板。
2. 自动及协作均完成目录上传 → 共享 Shell 命令 → 目录下载，内容和空目录正确，父任务和 SSH 会话不变。
3. 协作模式预览和清单确认仍可审阅，每项批准前无对应写入；后续命令必须等待目录整个步骤结束。
4. 在预览、确认和条目边界接管，重新授权后不重复成功项目；预算耗尽、规则/目录授权失效停止推进。
5. 冲突策略、黑名单、来源变化、未知写入、明确失败继续策略和手工跳过留下真实结果，不能把失败算作成功。
6. 中文编辑器、文件槽位绑定、步骤进度、MCP 与内置 AI 可运行保存的目录流程，导出不含本地授权。

本轮不缩减完整产品目标。独立目录批次的先前验证见第 35 份文档；下面记录目录保存流程的实际实现与证据。


## 已实现的运行与编辑行为

- 中文流程编辑器新增“上传目录 / 下载目录”和目录槽位，修改普通文件槽位不会把 v3 定义降回 v2。任务绑定按文件/目录类型、方向、版本和覆盖权限筛选；目录下载授权可被多个目录步骤顺序使用，单文件下载目标保持一次性。
- 冲突策略默认“停止并核对”，也可选择跳过冲突文件或覆盖。覆盖同时需要动作许可和本地授权，并继续受原有传输器的原子替换能力限制；没有新增不受约束的覆盖路径。
- 目录依然是一个逻辑步骤，内部预览、确认和每个条目各有操作记录。游标只接收任务网关已经确认成功的结果，后续命令等待整个目录步骤完成。
- 首次目录流程授权表单默认显示 100 次操作额度，用户可修改，上限仍为 5000；既有任务默认行为不变。已验证预算耗尽后停止、重新授权后继续剩余条目。
- 接管后先核对当前项结果，成功条目不会重做；确认前的冲突解决后重试会生成新预览；已经开始逐项传输时，拒绝更换本地目录绑定。
- 明确配置“失败后继续”时，可继续已知且无不确定写入的普通失败，整个任务报告 completed-with-errors。规则禁止、授权失效、未知写入和待清理结果不会被该选项绕过。
- 独立批次和保存流程共享一次性清单分配。暂停中的清单保留占用，结束或取消后解除；已经使用的旧清单不能再交给另一个批次运行。界面显示流程占用，并根据父任务操作状态刷新条目结果。

可导入示例见 [directory-workflow.json](examples/directory-workflow.json)。示例包含上传目录、SHA-256 检查和下载副本；只保存远端参数及目录槽位，不含本地路径或运行期授权。示例已通过解析与编译验证。

## 验证证据

- 实际 Windows 桌面通过 MCP 创建保存流程，分别运行自动和协作模式。每个任务保持 3 个逻辑步骤，完成 13 次实际操作；共享 SSH 中的 sha256sum 命令读到了刚上传的文件，并与客户端来源的 SHA-256 相同，随后下载的目录内容、空文件和空目录一致。
- 协作模式的清单确认在核对前禁用，每项从中文界面批准；创建首个目录后人工接管，未继续写入后续文件，重新授权后从剩余条目继续，没有重复成功项。
- Shell 与 SFTP 使用同一隔离测试文件系统，任务未新建 SSH 认证连接；导出定义不含本地授权，应用与脚本正常退出。首次证据目录为 .cache/desktop-observation-report-674d542c-978f-4c6a-a0c8-28895d1fc74e，执行日志 .cache/workflow-directory-desktop.log。原生选择框固定为本次生成的测试目录，没有连接业务服务器或调用付费模型。
- 内置 AI 与 MCP 在已有父任务内运行目录流程的自动/协作测试通过，保持原租约，并拒绝重用旧目录清单；AI 预先给出的后续命令被标为未执行，等待真实流程结果后再决定。
- 完整相关回归 **74 文件 / 520 项通过**，.cache/workflow-directory-full-regression.log。后续新增目录授权复用与最终中文文案专项 **2 文件 / 16 项通过**，.cache/workflow-directory-reuse-tests.log；这些集合有重叠，不累加为新总数。
- 恢复专项覆盖冲突重试、中途更换绑定被拒、失败继续、黑名单优先和预算耗尽。最初的冲突检查抛出异常，被网关保守归为不确定执行；现已改为预检查直接返回明确 failed，保留未知写入保护，修复后专项通过。
- 类型、改动模块 lint、中文静态键检查及前后端构建通过。日志为 .cache/workflow-directory-final-types.log、workflow-directory-final-lint.log、workflow-directory-final-build.log。上一提交 e282173 的 CI 34270374498 已成功；本轮推送的 Windows 门禁另行核对。

## 剩余范围

当前游标属于本次进程和任务，尚未实现跨重启持久化恢复。长期预览回收、任务历史传输分页、大目录压力、完整 Linux/OpenSSH 权限/断线/覆盖矩阵和真实跨版本在线升级仍需继续完成；完整 F/B/R/A 验收范围保持不变。此轮实际桌面验证使用 Windows 回环 SSH/SFTP 夹具，不能替代真实 Linux 服务器矩阵。

最终构建与解包包日志为 .cache/workflow-directory-final-build.log、workflow-directory-final-package.log；打包 MCP stdio 与真实 Codex 发现复核 2 文件 / 3 项通过，.cache/workflow-directory-packaged-mcp.log，工具数保持 34。最终源码类型检查通过，.cache/workflow-directory-delivery-types.log。

后续上传目录的完整条目边界已接入任务恢复，并通过真实 Windows 自动/协作重启验证；下载目录及部分传输资源仍需继续，见 [第 47 份文档](47-task-directory-recovery.md)。
