# 本机加密文件草稿

2026-09-09，已实现并完成隔离 Windows 桌面重启验证。对应 B08/B15、A16/A30/A33：默认编辑仍在内存中；用户可以显式“保存本机加密草稿”或“保存草稿并关闭”，重启后重新打开同一服务器文件时可审阅并恢复。恢复只改变本地编辑内容，远端保存仍走已有版本审阅和接管流程。

## 契约与文件责任

- types/file-draft.ts 定义草稿快照及乐观版本；只含必要的文件身份、原文、草稿和编码，不额外收集连接密码、SSH 私钥或控制租约；文件原文和草稿自身可能含秘密，因此整个快照加密。
- DocumentService 从当前人工文档版本提供稳定绑定：应用用户、实际 SSH 身份、已接受主机公钥、请求路径、规范目标及原始内容摘要。客户端不能自行指定存储身份，恢复不得把旧文件版本当成新批准。
- files/drafts/store.ts 拥有生成文件、AES-256-GCM、容量及 compare-and-swap；files/drafts/system-key.ts 只拥有操作系统凭据库中的随机加密密钥。依赖方向为路由 → 文档身份/草稿用例 → 加密文件和系统凭据库，不依赖页面、AI/MCP 私有实现或上游磁盘明文密钥。
- 草稿 HTTP 仅限已认证人工入口，API Key/AI/MCP 无权读取。请求和响应禁止缓存；文件名为绑定摘要，整个敏感记录在落盘前加密。系统凭据库不可用或旧密钥缺失时返回明确错误，不能改用明文或重新生成密钥掩盖原草稿。
- UI 独立草稿面板负责显式保存、查看恢复差异及删除。恢复比较打开时原文、当前远端内容与本机草稿；用户确认后才替换本地编辑内容，之后仍需重新审阅远端保存。保存过程中到达的新编辑不显示为已备份。

同一文档多窗口写草稿使用 revision 比较；并发旧版本不能覆盖新草稿。每份草稿最多包含 8 MiB 原文和 8 MiB 编辑内容，每个用户最多 64 份/128 MiB 加密数据，达到上限明确报错，不自动删除未恢复草稿。删除只针对当前用户确定的生成文件，不删除远端文件。

## 验收与验证

1. 真实文件落盘不含原文、路径或测试秘密；重建 Store/重启应用后可解密读取；密文修改、密钥缺失和不可用被拒绝。
2. 切换用户、服务器身份、主机密钥、规范路径或连接代次不复用旧文档权限；API Key 无权查询草稿。
3. 两个编辑窗口更新同一草稿时旧 revision 被拒绝，写入失败保留原快照。
4. 中文保存/恢复/删除可操作；恢复前能核对原文、当前内容和草稿，恢复本身不会调用 SSH 保存。
5. 自动/协作正在执行时本地草稿可以编辑；远端提交仍要求原网关接管/审阅，不新增直接写入入口。

验证采用草稿真实文件/模拟凭据库测试、文档身份与 HTTP 隔离测试、编辑器交互测试、已有文件和自动/协作回归，以及隔离 Windows 包的实际加密/重启检查。没有跨重启执行检查点的实现声明。

## 使用边界与后续范围

- 保存是用户明确发起的本机快照；没有自动保存每次按键。保存过程中继续输入时，页面说明当前编辑尚未保存到快照。
- 恢复要求重新连接并打开相同的可信服务器/文件目标，使用新文档版本；文件丢失、身份/路径改变时的离线草稿管理和迁移仍需后续补齐。
- 密钥绑定系统账号、应用用户和数据目录；复制密文到另一台机器或另一数据目录不能当作完成备份迁移。跨设备密钥迁移和统一凭据/备份仍在总目标内。
- 过期临时加密文件计入容量限制，不自动删除未知快照。单桌面进程内串行写入与 revision 拒绝旧窗口覆盖；不承诺多个独立后台进程同时修改同一个数据目录的跨进程事务。
- 本机包复用已验证的原生模块，npmRebuild=false；云端继续原有标准原生构建。上一历史提交 99d890e 的 CI 34291115701 已成功，本次提交云端结果另行核对。
