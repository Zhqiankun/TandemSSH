# 本地隧道恢复记录的持久化接续

2026-09-14。补齐465指出的数据库提交后应用关闭导致页面待恢复状态丢失问题。

## 实现

使用既有SQLite导入收据保存的localTunnels结果作为待恢复来源。新增受信UI查询和完成确认API，仅查询当前用户收据；API Key客户端不能访问。查询只返回本地恢复结果及原导入数量，不返回旧外观、管理员默认值或其他恢复副作用。

备份页面在桌面环境打开时查询待完成记录，展示时间、隧道数量、可展开配置详情和“保留当前配置并继续”。只读取不会写入或启动。用户明确继续后捕获当前文件版本，调用464本地原子导入，成功后才向后端确认完成。不会调用数据库导入API，不会重新创建主机。

文件写入成功、确认失败时，记录继续显示待恢复；重试通过本地持久化收据返回已写入结果，再确认数据库记录。即使手动删除过已导入条目，本地收据仍阻止复活。完成确认具有幂等性，记录对应审计事件。

普通收据仍保留32条，但未完成本地恢复不进入淘汰集合；最多128条待恢复，达到上限则在创建主机前拒绝新本地恢复导入。UI有中文上限、查询/确认错误提示。

## 责任与依赖

Repository负责用户隔离、收据生命周期和持久化完成状态；service/production/http负责调用契约、可信UI鉴别与审计；页面只编排详情查看、用户继续和本地IPC。复用464文件收据，没有另建浏览器内存队列或通用存储抽象。没有改变SSH执行或监听逻辑。
