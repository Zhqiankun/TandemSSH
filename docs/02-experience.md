# 界面与协作流程

状态：v0.2 交互草案。布局原创，结合 FinalShell 的终端/文件/监控工作台和 XTerminal 的连接与 AI 协作方式。

## 1. 工作区布局

```text
┌ 服务器 / 当前用户 / 连接状态 ─ 工作方式 ─ 当前控制者 ─ [接管] ┐
│ 服务器列表  │ 终端标签与实时输出              │ AI 任务        │
│ 分组/搜索   │                                │ 目标/计划      │
│ 开发/测试   │                                │ 待执行操作     │
│             │                                │ 对话与结果     │
├─────────────┴────────────────────────────────┴────────────────┤
│ 操作时间线 / 文件传输 / 规则命中 / 连接诊断                     │
└───────────────────────────────────────────────────────────────┘
```

服务器标签必须显示可识别的别名、主机和用户名，不能只靠颜色区分生产与测试。侧栏可收起，但当前目标和接管入口不能被隐藏。

当前控制者可显示“人工”“AI 任务”“命令流程”或已配对的“MCP 客户端”；命令流程同样具有接管入口，不能在人仍可随意输入时偷偷自动发送下一步。

文件管理与终端并列切换，AI 操作卡片引用的是稳定会话 ID，不是“当前标签”。用户切换标签后，后台任务仍显示原目标。

支持终端与远端文件同屏，文件区域可与终端关联也可独立浏览。监控区域可折叠，避免占满终端；目录跟随只在 cwd 信息可信且用户开启时生效，不从任意提示符文本猜目录。详细交互见[基础工作台](09-base-features.md)。

## 2. 连接页

保存名称、分组、主机、端口、用户名和认证方式。密码、Key、私钥口令分别进入凭据存储，不混入连接 JSON。

首次连接显示服务器指纹、算法及来源；用户确认后记入主机信任库。已记录的指纹发生变化时终止连接，展示差异；不能自动接受新指纹。

错误分开呈现：DNS/网络不可达、主机指纹冲突、认证失败、远端不支持请求的能力。失败时保留可重试输入，不重复打印凭据。

## 3. AI 接入与授权

用户选择端点、模型并输入 Key，点击连接测试。测试提示可能产生一次模型请求费用，并明确结果是“连通”“支持流式”“支持工具调用”中的哪些；仅返回 HTTP 200 不算 Agent 可用。

用户开启协作前能看到将发送的内容：当前会话选定输出、相关命令、人工新增记录和指定文件片段。其他标签、全部历史和整个环境变量不会自动进入上下文。

开始任务时展示授权摘要：目标服务器、会话、可执行动作、规则版本、最大步骤/时长、文件范围。授权范围变化应重新展示。

## 4. 操作卡片

| 字段 | 呈现要求 |
| --- | --- |
| 目标 | 主机别名、地址、用户名、工作目录可信状态 |
| 执行者 | 人工 / 内置 AI / 外部 MCP 客户端名称 |
| 动作 | 完整命令或文件变更；凭据以明确占位符显示 |
| 原因 | AI 提供的操作理由，与系统规则判断分开 |
| 策略结果 | 允许、需确认、拒绝或无法判断，列出命中规则 |
| 结果 | 未开始、已发送、运行中、成功、失败、未知 |

支持“批准这一次”“拒绝并反馈”“修改后重新检查”。修改命令、目标、目录、会话身份或规则后，不能复用旧批准。

“本任务内允许”必须列出具体允许范围，不能转换成对全部服务器与全部命令永久放行。

## 5. 接管流程

1. 用户点击始终可见的“接管”。
2. 界面立即显示“正在收回控制权”，暂不把用户排队输入发送给远端。
3. 会话服务增加控制权版本，撤销 AI 写权限，清空尚未发送的自动动作。
4. 收到成功响应后显示“人工控制”，用户才可继续输入。
5. AI 任务显示“因人工接管暂停”，不自动重新获取控制权。

如果接管请求失败或服务失联，界面不能宣称已经接管；应显示无法确认的状态和断开入口。已经送到服务器的命令可能继续运行。

用户在 AI 控制期间直接键入时，候选行为是先请求接管，再发送这次输入；输入法组合阶段不触发远端发送。此行为应有明确提示，并在实现前确认。

## 6. 停止操作不能混为一个按钮

| 操作 | 明确语义 |
| --- | --- |
| 暂停 AI | 停止产生/派发后续动作，不自动中断当前远端进程 |
| 接管 | 转移会话控制权；不等于终止或回滚远端命令 |
| 发送 Ctrl+C | 向当前会话发送中断字符，程序是否响应由远端决定 |
| 取消任务 | 取消未来动作；当前动作可能需中断或人工核实 |
| 断开连接 | 关闭连接；后台进程是否存活不能一概保证 |

已启动的 SFTP 上传属于在途操作。接管后不得开启新的 AI 文件操作；在途传输继续可见，用户可另行取消。取消不能保证目标文件完全没被写入。

## 7. 交还流程

用户点击“交还 AI”，界面展示人工介入期间的命令与文件变化摘要。待确认项包括当前程序是否仍在交互、输出是否有缺口、服务器是否重连、上下文是否包含敏感片段。

交还会创建新的控制权版本。AI 先读取最新获准上下文并更新计划；接管前批准但未执行的动作不能自动恢复。上下文缺失时，提示重新检查，不假装保留全部历史。

## 8. 规则管理页

- 页签：全局、服务器组、服务器、任务授权；显示继承路径和只读上级规则。
- 规则类型：拒绝、需确认、允许；匹配方式：固定命令、结构化命令参数、受限正则、文件目录范围。
- 编辑器显示示例、语法错误和匹配范围，保存前可预览影响。
- 规则试算输入服务器、执行者、命令及目录，输出最终判断、匹配规则和失效审批。
- “允许规则”与“自动批准”分别设置；允许执行不代表无需用户确认。
- 导入时展示新增、修改、移除的规则；不能自动把外部规则应用为更宽权限。

## 9. 时间线与记录

终端保留实时交互，时间线保留结构化事实。命令回显与工具结果必须关联同一 operationId，避免重复显示为两次执行。

人工输入普通 Shell 时可展示输入片段及输出。对于 vim、密码提示和复杂 TUI，不能伪造精确“命令完成”或退出码；记录为交互输入、控制事件或状态未知。

默认落盘记录脱敏；原始终端录制是单独的显式开关。用户应能看到录制是否开启、保存位置和清理入口。模型实际收到的上下文片段可检查，模型内部未返回的推理不在“全程可见”的承诺范围内。

## 10. 首版交互验收

- 不依赖颜色即可识别当前主机、执行者、控制者和操作状态。
- 终端大量输出时仍能触达接管按钮，服务端也不会把控制请求排在普通输出后面。
- 接管成功后显示人工控制，旧 AI 命令不出现新的远端写入。
- 被拒绝的命令显示具体规则和来源，而不是笼统“权限不足”。
- 断网/模型超时后没有虚假的完成提示，也不会反复重发部署命令。
- 上传下载显示源/目标、逐项状态、速度和剩余量；混合失败不能显示整批成功。
- 编辑器持续显示主机、路径、未保存标记和编码；保存冲突提供比较、另存和重新加载。
- 关闭标签、断开连接或退出应用前能识别未保存草稿和在途传输，不静默丢失内容。
