# 实施顺序与验收计划

状态：v0.2。下述为实施计划，不是已经完成的产品功能。已完成文档、[关键源码选型评估](10-open-source-base.md)及部分[M0 Windows 实测](11-m0-validation.md)；完整 M0 门槛仍未通过。

## 1. 阶段与交付物

| 阶段 | 交付内容 | 进入下一阶段的条件 |
| --- | --- | --- |
| M0 文档和底座原型 | 验证 Termix 独立桌面、现有功能与派发边界；必要时比较 Tabby | 锁定底座/发布版本，完成干净构建与许可检查 |
| M1 基础 SSH 与文件工作台 | 主机、认证、人工终端、SFTP、内置编辑、目录操作和传输管理 | 真实基础操作可用，保存/传输错误不损坏目标 |
| M2 会话与协作控制 | 单写入者、接管/交还、事件流、动作网关和规则试算 | 接管竞态、过期输入、目标错发测试通过 |
| M3 自定义命令流程 | 串行流程、参数、逐步结果、暂停/恢复、导入导出 | 参数与重试不会导致额外或重复操作 |
| M4 内置 AI | BYOK、上下文选择、工具循环、模式和预算 | 同一会话协作成功；模型异常不破坏人工控制 |
| M5 基础功能补齐与 MCP | 隧道、监控、本地终端、设置备份，以及文件/外部 MCP 的完整网关接入 | B01—B16 完成，两类入口不能绕过规则或接管 |
| M6 公开 alpha | 安装包、许可证、来源清单、安全文档和演示 | 完成下述 P0 场景与可复现构建 |

M1/M2 是内部验证版，不提前宣传完整 Agent 产品。公开 alpha 必须覆盖 F01—F15 和 B01—B16，不能省略文件功能。首版不设置未经评估的工期或费用承诺。

## 3. 自动化测试层次

| 层次 | 验证内容 | 环境 |
| --- | --- | --- |
| 单元 | 策略合并、参数校验、状态迁移、预算、脱敏 | 无网络、假时钟 |
| 契约 | IPC/MCP schema、事件版本、错误、身份不可伪造 | 本地核心与适配器替身 |
| 并发 | 接管与派发、重复请求、规则变更、断线重连 | 可控调度的假 SSH transport |
| 集成 | SSH/PTY/SFTP、指纹变化、退出码和文件结果 | 一次性 Linux 测试服务器 |
| Windows 平台 | 系统凭据库、进程生命周期、IPC ACL | Windows 实机或 CI VM |
| UI E2E | 连接、操作卡、接管、流程与时间线 | 真实桌面壳 + 测试服务器 |

不以“函数被调用”代替远端副作用验证。测试服务器上的文件、进程或输出应与本地记录相符。

## 4. P0 验收清单

| 编号 | 场景 | 必须成立的结果 |
| --- | --- | --- |
| A01 | 密码和私钥连接 | 正确认证能连接，失败不泄露秘密、不循环尝试 |
| A02 | 主机指纹变化 | 阻断连接；不会自动改写信任记录 |
| A03 | 切标签时 AI 派发 | 动作仍绑定原会话，不能落到新活动标签 |
| A04 | 排队命令中接管 | 接管成功后旧队列无 remote.write |
| A05 | 派发瞬间接管 | 已发送动作可见；未发送动作取消；状态与事实一致 |
| A06 | 模型迟到响应 | 旧 epoch/generation 的请求被拒绝 |
| A07 | 外部 MCP 抢写 | 不具控制权时返回 CONTROL_BUSY/STALE_CONTROL |
| A08 | 交还 AI | 读取人工新增记录，旧批准不复用 |
| A09 | 全局拒绝与服务器允许冲突 | 最终拒绝，显示规则来源 |
| A10 | 策略变更与审批竞态 | 派发前重新判断，旧审批失效 |
| A11 | 参数包含引号、换行、替换语法 | 保持单个参数或明确拒绝，不生成额外命令 |
| A12 | Shell/解释器/TUI 无法判定 | 不声称通过安全校验，严格模式拒绝 |
| A13 | requestId 重复/客户端重试 | 返回原操作，不重复触发副作用 |
| A14 | 命令执行后断线 | 标为 unknown，检查后才允许重试 |
| A15 | 审计不可写/输出有缺口 | 暂停自动副作用；人工可接管，记录缺口可见 |
| A16 | 系统加密不可用 | 不写明文 Key；可选择当前会话内存使用 |
| A17 | 文件路径 .. / 符号链接 / 目标被替换 | 正确拒绝或检测冲突；记录不能防御的远端竞态 |
| A18 | 恶意终端输出要求读取本机私钥 | 不改变策略、身份或访问范围 |
| A19 | 流程第二步失败 | 第三步不发送，显示失败原因 |
| A20 | 流程途中接管再交还 | 选择恢复点，不重跑已完成步骤 |
| A21 | 流程模板运行中被编辑 | 本次继续使用快照，下一次才采用新版 |
| A22 | 恶意流程/连接/规则导入 | 只预览、不自动执行、不自动放宽权限 |
| A23 | 模型 Key 错误/无工具能力/限流 | 明确报错，保留人工 SSH 功能 |
| A24 | 自动任务超预算 | 暂停，不自动切端点、扩权限或继续收费 |
| A25 | MCP 撤销和日志导出 | 撤销后不接受新操作，导出不含已知秘密 |
| A26 | 人工点击运行被拒绝命令的流程 | workflow 入口仍受硬规则限制，不伪装为自由人工输入 |
| A27 | 流程执行时人工输入或父 AI 派发 | 人工先接管，父 AI 等待；不会混入两套命令 |
| A28 | 文件/目录/批量双向传输 | 路径映射正确、逐项进度与结果、完整性检查状态准确 |
| A29 | 传输暂停后源或目标改变 | 不盲目续传，提供重新传输/另存或核实入口 |
| A30 | 在线编辑保存时外部修改 | 冲突可见、草稿保留，不静默覆盖 |
| A31 | 编码、换行、BOM、特殊文件名 | 无损或明确提示转换；不触发命令注入/重名覆盖 |
| A32 | 磁盘满、权限不足、传输部分失败 | 不假成功，已完成项与残留目标准确 |
| A33 | 关闭终端仍有编辑/传输 | 不提前释放连接、不丢未保存草稿 |
| A34 | 文件删除/权限/符号链接 | 明确作用目标，拒绝路径逃逸和静默提权 |
| A35 | 隧道与监控 | 端口范围正确、不混入 PTY、采样可关闭、资源可释放 |
| A36 | 基础认证与配置导入 | 私钥口令/agent/交互认证/单跳可用，导入不执行隐藏命令 |
| A37 | 备份恢复与本地终端 | 凭据迁移边界清楚，本地/远端身份明确 |

## 5. 性能与体验目标

以下为需要在 M0 确认的测量目标，不是当前性能承诺：

- 在定义好的 Windows 参考机上，接管本地确认延迟 p95 不超过 300 ms；不包含网络上已经发出的动作生效时间。
- 终端持续输出时接管入口仍响应；以 1 MiB/s、持续 30 秒作为初始压力用例，记录 CPU、内存和事件延迟。
- 所有输出队列和模型上下文都有上限；超过上限产生截断/缺口事件，不无限增长。
- 原始输出准确性、按键不串写和错误状态准确性优先于动画效果。

## 6. 计划中的验证命令

技术栈确认后建立这些 TandemSSH 产品级脚本；根目录目前还不能执行它们。已运行的上游命令与实际结果以[M0 报告](11-m0-validation.md)为准：

```text
npm run lint
npm run typecheck
npm run test:unit
npm run test:contracts
npm run test:session-races
npm run test:integration:ssh
npm run test:e2e:windows
npm run audit:dependencies
npm run build:windows
```

首次安装依赖使用已锁定依赖文件。CI 和本机使用同一套入口；如网络导致审计不可完成，应记录未完成，不能显示零漏洞。

## 7. 失败证据格式

每次失败记录：版本/提交、Windows 与服务器环境、相关配置脱敏快照、复现步骤、预期、实际结果、事件序号、远端副作用、影响范围、修复差异和复测结论。

一次成功截图不能证明接管竞态正确。并发问题需要可重放事件顺序与派发记录；原始日志含秘密时仅保存脱敏证据。

## 8. 发布要求

- README 明确 alpha 的适用场景与未完成能力；提供首个连接和协作演示。
- 定义 LICENSE、第三方来源/许可证清单、贡献方式和安全报告渠道。
- 在无开发依赖的 Windows 环境验证安装包；校验摘要与构建版本可追踪。
- 检查源码、安装包、样例配置和截图中没有个人 Key、服务器凭据或私有地址。
- 本机自动更新先做下载验证与人工安装确认；未完成签名体系前不静默执行更新。
- 在发布前确认日志默认值、主机信任行为和人工终端规则边界。
- 发布、上传公共仓库和连接真实服务器需要相应明确授权，不由“先写文档”自动触发。
