# 普通聊天并发与名额控制

## 实现

新增 `backend/ai/chat-admissions.ts`，只管理普通聊天 HTTP 请求的生命周期，不管理 AI 执行任务、SSH 会话或文件传输。

- 同用户同会话只允许一轮活动请求，重复并发返回 409 CHAT_CONVERSATION_BUSY，界面可读中文提示。
- 当前后端进程最多 16 路、每用户最多 4 路普通聊天，达到限制返回 429 CHAT_CONCURRENCY_LIMIT；不排队、不自动重发模型请求。
- 在读取仓储和调用模型之前取得名额；新会话创建后绑定实际 ID。外层 finally 在成功保存、失败或中断记录处理结束后释放。release 幂等，旧请求重复释放不会解锁新请求。
- conversationId 使用安全正整数检查；明确传入但不属于当前用户/不存在的会话返回 404，不再悄悄新建另一个会话。

HTTP 路由负责协议与中文错误，ChatAdmissions 负责并发不变量，仓储不感知资源池。名额内只保存用户/会话引用，无正文或密钥。没有通用共享抽象、数据库迁移、费用授权或任务预算变更。

## 验证

真实 HTTP：第一轮暂停在模型流；第二轮同会话返回 409，只有一次用户写入和一次模型引擎调用。断开第一轮 HTTP 后，以受控屏障延迟中断记录保存，此时第三个请求仍返回 409。保存完成后解除限制，后续请求成功完成。

名额单元测试验证：同会话绑定、跨用户隔离、旧释放不影响新租用、4 路用户上限、16 路总上限及释放后容量恢复。

AI 前后端全组 33 文件、209 项通过；针对性 2 文件、9 项通过；TypeScript、ESLint 通过。首轮 HTTP 测试超时因第三次成功请求错误复用了测试写入屏障，将屏障在请求前撤销后通过，不是产品锁未释放。

## 边界

这是单进程普通聊天资源池。桌面使用本机后台；不声称多进程/分布式互斥，也不把它当作 AI 执行任务、模型发现、磁盘历史容量或全部输出资源的统一上限。中断后的资源在持久化结束才释放，未完成的保存会占用名额，不会为了接受新请求提前破坏顺序。

新错误路径尚未做打包桌面多窗口操作；其他资源上限与分页按钮的打包验证仍需继续。未发布新安装包。
