# 只有已保存历史才进入补全

2026-09-14，继续F03历史隐私边界。

useCommandTracker原先只跳过敏感命令的保存请求，仍对所有命令调用onCommandExecuted，Terminal会把它加入自动补全缓存。因此“不写数据库”并不能保证本次敏感输入不出现在建议中。

修复为仅对未命中既有敏感规则的命令请求保存，且只有服务器返回id>0才通知建议更新。回调在内部重命名为onHistorySaved，以表达真实含义；服务器过滤/全局或主机关闭历史返回id0，以及请求失败时不通知。persist:false的即时本地跟踪仍无历史副作用。

增加历史通知作用域计数，主机、启用状态、持久化模式、后端会话变化或卸载使旧通知失效。已经在旧主机服务器中成功保存的记录不被撤回，但迟到通知不能更新新主机/新会话的建议。

35项相关测试通过，包含三种敏感命令零保存/零通知、id0零通知、失败零通知、成功后一次通知、不同主机和同主机新会话的迟到通知拒绝，以及补全缓存/空格/输入跟踪回归。日志.cache/history-cache-privacy-tests.log。

职责仍在终端输入历史Hook和现有Terminal调用方，无新共享模块、数据库或HTTP协议。既有敏感规则不是完整秘密检测，本轮也不宣称清理了旧数据库中可能存在的历史记录；它解决的是本次输入经保存过滤后仍被缓存的路径。当前尚未新增真实Windows敏感候选菜单验收。
