# SSH 交互认证

状态：终端新协议已实现，并通过真实 SSH 协议、中文桌面与应用回归。对应 B02、A01、A36。终端、SFTP、监控和基础跳板的认证行为都保留在完整目标内，本阶段先收敛终端真实协议与中文桌面入口，再核对其他通道接线。

源码检查发现旧终端表单把密码模式当作最多 8 位数字的验证码；普通回复会 trim；同一轮多个未知提示仅收集一个，其他填空；空回复在 WebSocket 层因 truthy 判断被拒绝。多轮状态和回调还分散在认证管理器与连接闭包。先建立真实 SSH 协议与 UI 复现，不能只依据静态判断宣布修复。

## 模块与契约

- `backend/hosts/keyboard-interactive.ts`：纯认证会话状态机，拥有本轮提示 ID、答案映射、超时/总轮数限制和关闭；不访问数据库、不记录答案、不依赖页面或 SSH 具体实现。
- `types/ssh-interactive-auth.ts`：提示与回复 DTO；最多 16 个提示，文本/答案分别有上限；保留字符串原值和 echo 提示，不按验证码格式限制普通密码。
- `SSHAuthManager`：继续负责凭据及既有厂商认证分流；新版本认证委托状态机，现有 Warpgate 等明确配置维持原适配。状态机可供文件/监控认证入口复用，不能反向导入终端页面。
- `hosts/terminal/index.ts`：绑定当前用户、WebSocket、连接尝试和管理器实例；初始化协商 `keyboardInteractiveVersion:1`，路由带 ID 的回复/取消，连接完成、失败、重连或断开时清理。
- `ui/ssh/dialogs/KeyboardInteractiveDialog.tsx`：中文多字段认证表单、服务器来源/目标信息、原样提交、等待与取消；提示文本按纯文本显示。
- `Terminal.tsx`：发送能力版本、接收当前提示、转交表单事件；业务规则留在认证状态机。旧验证码表单的密码输入和空白处理同时修复，保留旧消息兼容入口。

新消息：`keyboard_interactive_required` 携带 `challenge:{id,name,instructions,prompts,expiresAt}`；`keyboard_interactive_response` 携带 `{id,responses}`；`keyboard_interactive_cancel` 携带 `{id}`。答案数量必须与公开提示匹配，旧 ID、重复回复、超时和关闭后的回复不调用 SSH finish。零提示可直接回答空数组。先清理本轮状态再调用 finish，避免下一轮回调重入覆盖。

已保存的本主机密码只用于可识别的隐藏密码提示；未自动回答的每个提示都交给人。UI 和日志不返回已保存答案；回答只在本次认证内存中使用，不存入配置、审计或 AI 上下文。每轮最多等待 3 分钟，整体认证最多 5 分钟、32 轮，取消或超限关闭本次尝试。

新协议需要客户端显式协商，旧客户端继续走既有消息；不能宣称旧无 ID 协议具备新协议的迟到回复隔离。新 Windows 客户端默认声明支持。主机信任仍在认证前完成，不能为验证交互认证跳过指纹确认。
