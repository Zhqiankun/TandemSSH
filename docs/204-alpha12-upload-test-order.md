# alpha.12 云端失败：上传测试的并发顺序假设

2026-09-12，Release 34682059559 / job 103522379785 在 Validate source 失败：4123 项通过、1 项失败、24 项跳过。失败位于 UploadQueue.test.tsx 的并发准备测试，期望队列第一个文件 failed，实际 checking。安装包与公开发布步骤未执行。失败日志片段保存在 `.cache/alpha12-cloud-failure.txt`。

## 定位和确定性复现

生产上传队列在调用 api.prepare 前先异步计算文件哈希，两个并发文件的哈希可能以不同顺序结束。旧测试按“第一个到达 prepare 的请求”注入失败，却按队列索引 0 检查结果，误将请求到达顺序当成文件添加顺序。

使用公开 UploadSource.slice 接口挂起文件 0 的读取，直到文件 1 到达 prepare 才放行，保留真实哈希计算。正常顺序通过、反转顺序稳定复现云端相同断言失败；日志 `.cache/alpha12-upload-order-reproduction.log`。这不是靠延长等待推断的偶发失败。

## 修复及验证

测试改为按目标路径绑定失败和等待门；显式断言反转场景中首个 prepare 属于文件 1。保留原来的并发峰值 2、第三文件排队、失败后继续、最终 failed/completed/completed 及列表顺序断言。

UploadQueue.test.tsx 全文件 13 项通过；ESLint、TypeScript、diff 检查通过。仅测试与本记录变化，无生产源码修改。
