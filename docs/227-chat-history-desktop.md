# 历史会话真实桌面界面验收

## 有效运行

在包含 226 改动的本地目录包上，独立测试配置完成两次启动及正常退出。有效报告：`.cache/desktop-observation-report-120c6b9d-96d2-43ed-a9e6-6db148e78761`。restore/history-ui-result.json、result.json 为断言结果；restore/interrupted-history.png 和 restore/new-chat.png 均已实际查看。

1. 使用实际聊天后台和本机模拟模型生成完整工具会话及中断片段，保存到桌面加密数据库。
2. 正常退出再启动，打开“人工智能”面板，从真实“历史会话”选择框选中中断会话。可见“本轮回复已中断，以下内容未完成，不会自动重放”和“中断片段”。
3. 选择原完整会话，历史正文出现，中断提示不再显示。在输入框输入“界面续聊验收”并点击发送，实际数据库该会话增加用户及助手消息。
4. 点击“新会话”，旧会话正文消失；输入“界面新会话验收”并发送。新会话 ID 为 3，与原两个会话不同，界面显示实际回复“检查完成”。
5. 完整模型上下文与重启读回验证沿用 225；本轮模拟模型聊天请求共 6 次，没有付费模型。第二次桌面正常退出、后台端口释放，观察脚本退出码 0。

操作通过自建应用的 renderer 调试通道触发真实控件事件，不使用 React 状态注入；后台记录和真实截图共同核对结果。

## 首轮无效界面证据

首轮报告 `6f252c7a-19e4-414c-a036-13ae468017f7` 的 API 结果通过，但截图中欢迎对话框遮挡聊天区域。虽然程序触发了其后的控件事件，这不能视为用户可用的界面证据，已明确排除。

验收脚本先等待的选择器还存在引号错误，后备选择器最终继续了该运行。确认原运行正常结束后，修正选择器，并在重启时关闭欢迎对话框、确认无对话框遮挡，再重新独立运行得到上述有效截图。没有将观察超时视为进程退出，也没有重复启动仍存活的实例。

欢迎页在该夹具重启后再次出现，原因本轮未确定；不把它写成已修复。它不影响完成关闭欢迎页后的历史功能验证。

## 边界和剩余工作

本轮只使用 `--win --dir --publish=never` 验收目录包，没有生成、上传或发布公开安装包。它显示 alpha.12 版本号但包含开发改动，不能当成已发布 alpha.12 的功能证据。

普通聊天历史入口、中文状态、新会话及续聊已完成这条真实桌面链。最近 50 条以外的分页、并发流和全局资源限制仍需实施/验证，完整 AI 产品验收项保持未完成。
