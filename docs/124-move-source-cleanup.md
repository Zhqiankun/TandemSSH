# 移动源清理不得误报成功

2026-09-12。评估复用跨主机传输引擎来恢复跨文件系统移动时，发现不能直接复用的缺陷：deleteSourcePaths 吞掉每项删除失败，随后仍设置 sourceDeleted=true；底层 deletePathSftp 又忽略全部 stat 错误，并跟随目录符号链接递归。

本轮修复：底层使用 lstat，只忽略明确 ENOENT/状态 2，权限与其他失败上抛；非目录直接 unlink，包括断链与目录链接，不扫描其目标。外层不再吞掉源删除失败。SourceDeletionError 阻止直接传输转中继的回退，以及仅因目标完整而判成功的异常补救；错误记录不可直接重试。最终目标完整补救还必须在 moveRequested 时看到 sourceDeleted=true。

前端遇到 SOURCE_DELETE_FAILED 显示中文说明：目标已复制、源清理失败，需核对两端，不直接重复移动。该结果不承诺所有源文件都仍存在，可能已经部分清理。未改动复制完整性验证或用户授权。

初轮文件服务 134 项通过，随后源清理与恢复策略专项 8 项通过；包括权限失败传播、目录链接不遍历、子项失败不删父目录、移动不能仅凭目标完整判成功。最终 ESLint、翻译缺失键检查（0）与 tsc -b 通过。该测试以 SFTP 端口夹具验证，完整跨主机移动整链仍需实机回归。

跨文件系统 moveItem 尚未恢复。已有引擎的目标覆盖与源版本竞态仍需检查，不能因本轮修复就直接接入或标记 B09 完成。目录被外部进程并发替换的防护也不由 lstat 单次检查充分证明。
