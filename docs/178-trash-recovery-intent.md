# 回收站预写恢复意图与中断恢复

2026-09-12。修复旧流程“先移动源文件，再写恢复记录”的风险：记录失败后仅尝试回滚，一旦回滚也失败，原路径消失且缺少可识别记录。

## 最终协议与兼容

trash-service.ts 先将完整 StoredTrashItem 写入 info/<id>.pending，成功后再检查请求有效性、移动源文件到 files/<id>，最后 rename 待完成记录为原有 info/<id>.json。写入失败不移动源文件。移动或记录确认响应丢失时，完整记录位于 pending 或 json，均可由新客户端发现和恢复，不再盲目回滚源文件。

正常记录的 JSON 字段和 .json 路径不变，无需迁移旧记录。旧客户端原逻辑只扫描 .json，因此不会在新移动尚未完成时误清理 .pending；它也无法恢复只剩 .pending 的异常条目，需要新客户端。正常完成后的条目继续兼容旧格式。

读取优先正常记录，仅在明确不存在时读取 pending；权限错误不当作不存在。两种记录执行同一 ID、目标路径和安全源路径校验。列举按 ID 去重，未过期且尚无 payload 的意图保留，以免并发列举删掉在途记录；保留期到期时清理废弃意图，不触碰尚未移动的源文件。恢复/永久删除后清理该 ID 的两种元数据文件。

模块责任仍为文件管理回收站服务，没有新增共享模块或外部依赖。removeMetadata 是该服务私有清理入口，只处理已验证记录 ID 的已知文件名。

## 验证

回收站服务与路由两个文件 64 项通过，使用实际临时文件系统的 SFTP 适配注入故障：
- 恢复意图写入失败：rename 零次，原内容保持。
- 源文件 rename 已应用但响应丢失：pending 可列出并恢复原内容。
- 元数据 rename 已应用但响应丢失：正常记录可恢复。
- 元数据确认在应用前失败：直接使用 pending 恢复。
- 并发列表在意图写入后、源移动前运行：不丢弃在途记录。
- 中止后的废弃意图按保留期清理，原文件不变。
- 正常和 pending 记录均拒绝伪造 trashPath，不删除受保护文件。

既有普通移动、恢复、链接、保留期和请求中止测试继续通过。新增测试初次有对象括号语法错误，修正后上述测试全部通过。

本轮没有真实 SSH 断网/存储断电验证，不把本地适配的故障注入等同于实机断网。B09 与完整原始目标继续保持未全部完成。公开 alpha.8 不包含该协议修复。
