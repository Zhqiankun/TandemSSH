# 实际在线更新验收

本阶段继续用户要求的“版本检测、按钮更新、推送触发 Actions”。主智能体负责实现和验收；沿用第 25 份文档的固定 GitHub 更新源、显式下载与人工安装确认，不增加任意更新源配置。

## 文件责任与验证顺序

`electron/update-service.cjs` 继续拥有版本、下载、校验与安装状态；`update-ipc.cjs` 负责可信主窗口和安装确认；中文 UpdateCenter 负责按钮和状态。测试只通过这些公开入口和真实 electron-updater 契约验证，不把测试传输适配器打进产品。

新增 `scripts/update-download.test.ts` 使用真实 NsisUpdater、GenericProvider 和摘要下载流，仅将固定仓库的 HTTP 请求路由到本机测试服务。测试适配器和临时目录由该文件独立拥有，不新增共享业务模块。验证版本比较、不自动下载、实际文件字节、摘要不匹配拒绝、流式取消后重试，以及普通退出不触发安装。载荷是不可执行测试字节，不安装、不连接公网。这些结果只能证明下载与校验，不能替代 NSIS 跨版本安装。

后续跨版本安装必须在一次性 Windows runner 上构建两个不同版本的真实安装包，通过旧版更新界面完成检查、下载与确认，观察安装进程和新版启动；核对版本、安装目录、注册信息、用户数据库/恢复记录保留及连接资源释放。沿用已有安装验收归属检查，不在用户日常安装目录测试。固定 GitHub 渠道本身仍需发布后的独立验证；不得把本机传输夹具称为 GitHub 正式发布验收。

## 跨版本安装验收实现

2026-09-09，新增实际 NSIS 升级门槛，尚待首次云端实跑结果。主智能体拥有以下脚本及职责：

- `verify-windows-installation.ps1` 继续独占一次性 runner 的安装目录、注册信息、用户配置及卸载。初次安装/中文桌面通过后，调用升级验证；升级后再次核验注册版本与原生依赖，最后卸载并检查用户数据保留。
- `verify-online-update.cjs` 在独立输出目录构建高一个补丁号的测试包，提供回环更新清单/安装包，操作真实中文更新窗口和原生安装确认，验证新版自动启动与数据库/界面数据保留。旧版和新版都使用本次源码；这验证真实更新机制，不代表历史版本数据库迁移矩阵。
- `confirm-upgrade-window.ps1` 仅允许 GitHub 托管 Windows runner，核验精确可执行文件路径和 SHA-256，限定对应进程的原生确认或 NSIS 按钮。先点取消并确认旧版仍运行，再点现在安装；不自动处理其他应用窗口。
- `upgrade-debugger.cjs` 仅负责测试驱动的回环调试连接、超时和关闭，不被产品代码依赖。它属于升级验收的脚本模块，不是业务共享工具层。

测试新版只额外包含观察入口：打开回环调试端口、固定本次临时配置，再加载未修改的 `electron/main.cjs`。该入口只存在于独立 fixture，正式发布包和正式版本清单不包含它。新旧版本号从当前包版本推导，但不改 package.json/锁文件、不推标签、不上传测试安装包至正式渠道。fixture 复用本次正式构建后已匹配的原生模块；原正式构建、Spectre 检查和原生重编译门槛不变。

旧版更新会话只在该测试进程中将固定 GitHub 路径路由到回环服务；清单保留正式格式的固定仓库、版本化 EXE 地址、体积和 SHA-512。没有新增产品更新源设置。验证实际下载文件的 SHA-256 与构建产物一致，取消原生确认不退出或改写旧版，确认后运行实际 assisted NSIS 安装器，默认完成按钮触发新版启动。

新版验证真实 PID、程序路径、版本、安装标记、中文主页和更新窗口；通过 API 读回升级前保存的测试流程，核对持久化界面标记和文件摘要，检查加密数据库仍存在并可用。测试流程只保存、不执行，不建立主机或 SSH 连接。最后正常退出新版，并要求其进程和后端监听端口释放。该检查暂不覆盖全部历史模型配置、所有恢复记录格式或升级期间在途传输的迁移组合。

CI 和 Release 的安装步骤纳入升级检查，任何环节失败均阻止该门槛通过；安装验证超时调整为 20 分钟，报告保留在既有安装证据产物中。PowerShell、Node、工作流语法及专项 lint 已通过；非 runner 拒绝执行与既有更新/真实下载组合 **3 文件 / 11 项通过**，日志 `.cache/online-upgrade-contract-tests.log` 和 `.cache/online-upgrade-lint.log`。正式升级结果以 `upgrade.json`、原生按钮记录、中文截图和实际 Actions 状态为准，不以脚本存在或单元测试通过宣称验收完成。

本机已额外构建仅供打包验证的 0.1.1 NSIS fixture，未启动或安装。读取实际 ASAR 后确认 package.version、观察入口、与源码逐字节一致的产品 main.cjs 及固定 GitHub app-update.yml；EXE 和 blockmap 均已生成。该本机 fixture 的入口会直接拒绝启动，防止误当日常预览版运行。日志 `.cache/online-upgrade-local-build.log`，结构证据 `.cache/online-upgrade-local-build-result.json`。它验证打包方式，不替代云端原生确认和真实升级结果。
