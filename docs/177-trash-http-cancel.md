# 回收站请求中止与已移动文件的恢复记录

2026-09-12。补齐 deleteItem 回收站分支的 HTTP 中止行为。路由绑定请求 aborted 和非正常响应 close，以 Promise.race 结束客户端已离开的等待；底层工作结果仍被消费，不产生未处理拒绝或向已关闭客户端写响应。

路由在获取 SFTP 前后、回收站准备完成后检查请求及原会话身份。trash-service.ts 的 moveToTrash 增加可选 assertActive 回调，在准备前后及实际 rename 前检查；失效请求不再移动目标文件。原调用者默认无需传入回调。

一旦目标 rename 已派发，不再因 HTTP 离开而跳过恢复元数据写入：让已授权的该次移动完成恢复记录，避免文件移走却因客户端取消丢失回收站入口。写入失败仍使用原有失败/回滚机制，不声称一定可恢复。没有关闭共享 SFTP 连接或改写 listTrash 内部既有的保留期清理语义；已进入的准备 I/O 可能继续完成，但在目标 rename 前会再次检查。

## 验证

路由和回收站服务两个文件 57 项通过。新增覆盖：
- 开始时已中止/响应已销毁，不获取 SFTP。
- SFTP 获取、回收站列表或移动过程中中止，HTTP 等待立即结束且不发响应；准备阶段解除延迟后不进入移动。
- 使用实际本地文件系统的 SFTP 适配，在源 lstat 返回时使检查失效，rename 次数为零、内容不变。
- 在 rename 完成后使检查失效，仍能列出完整恢复记录，并恢复原内容。

这证明本次 HTTP 中止和恢复记录边界，不把本地文件系统适配声称为本轮真实 SSH 断网。回收站无事件挂起、网络本身断开导致元数据失败及完整桌面重连仍需继续核验，B09 保持未全部完成。

文件责任：operation-routes.ts 拥有 HTTP 等待和会话身份，trash-service.ts 拥有目标移动与恢复记录一致性；通过可选检查回调单向调用，没有新增共享模块或依赖。公开 alpha.8 不包含本轮开发修复。
最终 tsc -b、ESLint、git diff --check 均通过。
