# CPU 计数与局部采样失败修复

## 依据与缺陷

Linux v6.12 的 account_guest_time 同时累计 user/guest 或 nice/guest_nice，因此不能将 /proc/stat 的 guest、guest_nice 再次加入独立时间总量。[固定版本内核源码](https://github.com/torvalds/linux/blob/v6.12/kernel/sched/cputime.c#L132-L147)。

原解析将所有字段相加，测试样本得到 680 而非 648；还会过滤坏字段后继续算，导致列错位。负数、小数和不安全整数也被接受。采集器把所有读取绑定成一次整体成功，并留下未清理的超时定时器。

## 修改

- 严格验证计数字段，不丢弃坏字段来移动列位置；仅累计前八个独立时间分类，保留 idle+iowait 的现有空闲定义。
- 字段倒退、总差值无效或不一致时返回未知使用率，不夹成假的 0%/100%。包括可能下降的 iowait 样本；该字段本身有限制，见 [proc_stat 手册](https://www.man7.org/linux/man-pages/man5/proc_stat.5.html)。
- CPU 两次读取、核心数及负载的失败分别处理。保留成功的独立数据；非法负载不替成零，核心数必须是安全正整数。
- 在 finally 清理超时定时器，避免成功采样后继续留下定时任务。

公开采样响应字段未改变，只修改 CPU 模块与测试，没有通用共享抽象或新的执行入口。

## 验证

修复前新增解析五项全部失败；修复后计数、各单项读取失败、负载/核心数非法值、计数倒退及计时器清理均通过。完整监控目录 19 文件、149 项通过；TypeScript、ESLint 通过。

采样故障测试使用受控命令端口和虚拟时钟，不等同于真实 Linux 多核负载验收。极大、不安全数值返回未知，不声称任意容量都可精确显示。完整服务器监控矩阵仍需继续。
