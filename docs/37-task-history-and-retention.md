# 任务分页、日志历史与资源归档

2026-09-09，本轮已实现任务摘要/操作分页、本机只读历史和已结束任务归档。重启后可以查看记录；跨重启继续执行仍未实现。

## 契约与责任

- 实时任务列表返回无操作正文的摘要；选中任务单独请求操作分页，页面说明范围、总数和是否截断输出，完整详情可按需读取。旧内部调用默认仍可获得完整 TaskView。
- TaskRuntime 拥有分页和任务状态；OperationGateway 提供不复制动作/输出的轻量状态查询。UI 只负责编排和翻页，不推断执行成功。
- 日志历史读取现有 AuditJournal 的本机脱敏 JSONL，不新建一份无独立留存控制的操作日志。只读历史不能直接重放操作、恢复旧租约或批准命令。
- 历史查询与详情有条数、扫描字节和返回大小限制；游标只能定位当前用户日志目录中的生成文件，损坏/过期记录明确反馈。内容按不可信文本展示。
- 已结束任务归档前先保存摘要、核对无未知/待清理结果，再释放其传输、目录预览和本地授权；失败时保留任务。保留创建请求的去重标记，不能因归档重新执行旧请求。
- 未分配且过期的目录预览可回收；正在运行、暂停占用或结果未知的预览不自动移除。

主智能体负责实现与验证。依赖方向为中文界面 → 任务/历史 HTTP → TaskRuntime 或 AuditJournal → 原有网关、文件能力及受控文件系统；历史读取不反向调用执行器。

## 验收

1. 大任务摘要不携带操作正文；分页能覆盖全部操作，最新结果与当前审批可达。
2. 任务切换或异步响应迟到不混入另一任务；已看旧页时仍可跳回最新记录。
3. 重启后可查询本机脱敏日志，按任务筛选；跨用户和任意文件游标被拒绝。
4. 损坏、截断、轮转和留存删除不会被误报为完整历史；详情与输出有明确分页。
5. 归档释放已结束任务容量，不丢失未知/待清理结果，不重建已归档请求。
6. 自动/协作、人工接管、保存流程、目录与 MCP 既有场景回归通过。

跨重启执行恢复仍需独立的检查点与重新授权设计，不能把只读历史当作已经实现恢复。

## 已实现与使用入口

仪表盘和任务面板都可打开“本机操作历史”，无需重新连接 SSH。默认查看当前用户最新记录，支持按任务 ID 筛选、翻页和查看脱敏详情；详情按纯文本呈现，不能执行或审批其中内容。默认留存 7 天或最多 100 MiB；查询会排除已过期记录，磁盘清理由原有日志写入留存流程完成。

任务完成或取消后，面板提供“归档并释放资源”。操作结果未知、存在日志缺口、临时文件或待清理结果时不能归档。归档保留原始脱敏操作记录和任务/AI 最终摘要，释放任务监听、传输记录、目录预览及本地授权，已经上传/下载的最终文件保持存在。归档后的完整临时 AI 对话不再保留；不能用旧请求在当前进程重新创建任务。请求去重摘要有容量上限，跨重启去重不是本轮实现内容。

实时列表不再携带所有操作正文；选中任务每页最多显示 50 项，操作数组受 1 MiB 限制。长输出先展示前 8,000 字符并标注截断，可按需读取完整操作输出。等待分页计划返回前不会提前初始化授权表单，避免目录任务被错误使用命令任务的默认预算。

## 模块与依赖

- TaskRuntime 负责分页、归档状态和请求去重，OperationGateway 负责判断每个动作能否安全释放。
- task-resources 只协调现有文件服务释放所属任务资源；各文件服务继续拥有自身数据，不新增 common/utils 抽象。
- AuditHistoryReader 只读取当前用户的生成日志分片，AuditJournal 继续拥有写入与留存；历史查询不调用任务执行器。
- use-task-operation-page、TaskHistory 和 task-history-api 分别负责当前任务分页状态、中文历史界面及 HTTP 适配；迟到响应不能进入另一任务或另一账号。
- 新增受现有人工登录认证保护的历史查询/详情、操作详情和归档 HTTP 入口。没有扩展 MCP 权限；现有 34 项 MCP 工具保持原执行入口。

历史查询每次最多 50 条、扫描 8 MiB 或 256 个分片，最多 2 个并发查询。详情每段最多 16,000 字符。游标绑定用户及筛选条件；任意路径、链接、硬链接、重定向目录和异常分片被拒绝。损坏、截断或轮转删除的记录会报告跳过数量，不把缺失数据伪装成完整历史。
