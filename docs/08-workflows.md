# 自定义命令流程

状态：v0.2 设计草案，对应顺序命令流程 R09 和完整文件功能 R10。

## 1. 要解决的事情

用户可将“先执行 A，再执行 B，最后检查 C”保存为一个命令流程。再次使用时选择服务器、填写参数即可运行，也可让 AI 调用已保存的流程。

本稿将“打包命令行配置”理解为保存和导出可复用的流程定义。首版提供 JSON 配置和图形编辑器，不要求用户写 JavaScript；独立 CLI、生成安装包和图形 DAG 调度不属于本次首版范围。

## 2. 首版必须具备

- 命名、描述、版本、分类，以及可以绑定的服务器范围。
- 串行步骤，每一步有名称、命令、工作目录、超时和失败行为。
- 运行参数与默认值；秘密参数只引用凭据，不以明文保存或导出。
- 运行前预览参数展开后的全部步骤、目标、规则结果和潜在副作用。
- 每一步的输入、输出、退出结果、开始/结束时间和实际执行者可查看。
- 暂停、人工接管、取消尚未开始的步骤和明确的恢复选择。
- 无凭据导出、导入预览、schema 校验；导入不会触发执行。
- AI 可以推荐流程、填写参数并请求执行；修改或保存流程定义需要人工确认。

文件工作台接入后，首版流程支持组合上传/下载步骤，例如“上传产物 → 执行部署命令 → 检查服务 → 下载结果”。文件步骤复用传输清单和动作网关，不能在命令模板中暗藏不经授权的本地文件访问。

## 3. 定义与运行分离

WorkflowDefinition 是模板，WorkflowRun 是一次执行。开始运行后冻结模板版本、步骤和参数快照；用户编辑模板只影响下一次运行。

运行绑定一个具体 connectionId、sessionId 和 generation，不随活动标签改变。首版一个会话只允许一个自动执行源，流程运行与 AI 自由发命令不能交叉。

每一步通过动作网关执行，即使用户已经批准整个流程，仍要在真正执行前重新检查当前规则与控制权。整包批准不是跳过每一步的黑白名单。

## 4. 参数方式

| 类型 | 用途 | 校验方式 |
| --- | --- | --- |
| string | 分支名等普通文本 | 长度、格式或允许值 |
| integer | 端口、次数 | 范围 |
| boolean | 开关 | 显式映射为预定义参数，不原样拼接命令 |
| enum | 环境、服务等有限选项 | 枚举 |
| remote-directory | 工作目录 | POSIX 绝对路径、作用范围 |
| secret-ref | 密码或令牌引用 | 凭据用途与权限匹配，不回显值 |

程序名在首版结构化步骤中固定，参数引用以对象表达，不做字符串全局替换。显示预览和实际发送使用同一份动作快照；特殊字符按单个参数编码，不得把 `release; command` 变成第二条命令。

原始多行脚本属于高级步骤：原文预览、单独授权，严格白名单模式默认不允许。不能以“流程打包”为由把无法解析的脚本判定为安全。

## 5. 配置示例

示例：Docker Compose 更新，目标环境需事先安装 Docker、配置镜像访问和一个可访问的健康检查地址。不是所有项目都能直接使用；尤其不能把 `compose up` 返回 0 当作业务健康。

```json
{
  "schemaVersion": 1,
  "id": "compose-update",
  "name": "更新 Compose 服务",
  "version": "1.0.0",
  "description": "验证配置、拉取镜像、更新服务并检查健康接口",
  "parameters": {
    "appDir": {
      "type": "remote-directory",
      "required": true,
      "default": "/srv/myapp"
    },
    "healthUrl": {
      "type": "string",
      "required": true,
      "default": "http://127.0.0.1:8080/health"
    }
  },
  "defaults": {
    "cwd": { "param": "appDir" },
    "onFailure": "stop",
    "timeoutMs": 120000,
    "retry": { "maxAttempts": 1 }
  },
  "steps": [
    {
      "id": "validate",
      "name": "检查 Compose 配置",
      "action": { "type": "command", "program": "docker", "args": ["compose", "config", "--quiet"] }
    },
    {
      "id": "pull",
      "name": "拉取镜像",
      "timeoutMs": 300000,
      "action": { "type": "command", "program": "docker", "args": ["compose", "pull"] }
    },
    {
      "id": "update",
      "name": "更新服务",
      "action": { "type": "command", "program": "docker", "args": ["compose", "up", "-d"] }
    },
    {
      "id": "health",
      "name": "检查健康接口",
      "timeoutMs": 15000,
      "action": { "type": "command", "program": "curl", "args": ["--fail", "--silent", "--show-error", "--max-time", "10", { "param": "healthUrl" }] }
    }
  ]
}
```

此示例失败默认停止，健康检查也不会自动重试；可由用户明确设置仅对健康检查重试。HTTP 成功是否足够应按项目定义，可以后续加入明确的响应断言。

服务器身份和凭据不写进模板。运行时绑定目标并检查 appDir/healthUrl 的实际范围，URL 参数也不能因为名字叫 health 就视为可信。

## 6. 工作目录与环境

每一步携带明确 cwd，默认继承流程 defaults.cwd。不得假设上一步的 `cd` 在另一条独立 exec 调用中继续生效。

如果某流程确实需要持续 Shell 状态，应明确标记 stateful-shell，并绑定同一会话。首版优先支持明确 cwd 的步骤；交互状态未知时暂停，不擅自把后续命令输入编辑器或密码提示中。

环境变量仅允许显式声明的键值或秘密引用，不继承本机全部环境。秘密传递由专用执行适配器处理；首版若无法避免进入命令行、回显或日志，则不支持该秘密用法，提示人工处理。

## 7. 失败、重试与继续

| 情况 | 默认处理 | 用户可做的选择 |
| --- | --- | --- |
| 明确退出码非 0 | 流程失败并停止后续步骤 | 修正后明确重试该步或结束 |
| 单步超时 | 请求中断，结果可能未知 | 核实远端结果后再决定 |
| 断网/应用重启 | needs-reconcile，不自动执行 | 核实当前步骤并重新授权 |
| 命中拒绝规则 | paused-policy | 查看规则；AI 不能改规则自救 |
| 人工接管 | paused-human | 人工处理后选择恢复位置 |
| 传输部分完成 | 标记实际进度/可能的残留 | 明确清理、重试或检查目标文件 |

maxAttempts 默认为 1，即没有自动重试。以后允许配置重试时，必须针对具体步骤标明可重试条件；不因为命令名字相同就认定幂等。

“失败继续”只允许显式指定步骤，并在预览中突出显示。即使后续步骤成功，只要存在未解决失败，整体不能显示全绿成功。

## 8. 接管后的恢复

1. 停止启动后续步骤，正在执行的一步继续显示其真实状态。
2. 接管权转移不自动重跑当前步骤，也不自动中断已送出的命令。
3. 人工操作记录与流程 runId 关联，交还前展示变化。
4. 用户选择从未开始的下一步继续，或明确重试失败步骤；未知结果必须先核实。
5. 重新检查规则、目标、目录、generation 和剩余预算，发出新授权。

如果人工修改了部署目录、身份或文件，旧步骤预览与批准作废。流程恢复后使用新的明确上下文，不依赖过时状态。

## 9. 导入、导出与共享

- 导出定义、参数 schema 和说明，不导出 runId、执行日志、SSH 密码、Key 或秘密值。
- 允许导出独立 JSON，也允许之后增加带说明的 ZIP 格式；首版只要求 JSON。
- 导入校验版本、字段、参数引用、重复步骤 ID、文件大小和允许范围。
- 导入文件不能带入自动信任、自动执行、关闭审批或放宽全局黑名单的效果。
- AI 生成的流程草稿必须经过预览后保存；运行前再次选定目标。
- 不能声称已自动识别所有硬编码秘密。导出前提供检查和警告，不自动上传公共仓库。

## 10. 首版以后再做

条件分支、并行 DAG、多服务器滚动执行、定时任务、复杂输出变量和可编程插件均后置。补偿步骤可后续显式设计，但不能命名为“任意部署自动回滚”。

## 11. 核心验收

- 三条命令严格按顺序执行，每一步能查看结果。
- 第二步失败后，第三步不会发送。
- 参数含空格、引号或 Shell 元字符时不会成为额外命令。
- 在步骤派发边界接管，接管成功后没有后续自动写入。
- 修改模板不改变在途运行快照；修改规则会阻止待执行步骤使用旧批准。
- 导入不执行；导出不含凭据；明确重试不会连带重跑已成功的步骤。
