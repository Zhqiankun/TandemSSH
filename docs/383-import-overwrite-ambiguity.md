# 拒绝覆盖不明确的主机记录

2026-09-14，A22覆盖导入核查发现：同一用户有多条相同地址/端口/用户名的主机时，JSON和SSH配置导入都会由Map覆盖选中最后一条，用户无法知道哪条将被替换。

host-bulk-routes.ts两条导入路径现在将重复匹配标记为歧义，拒绝该条覆盖，返回HOST_IMPORT_TARGET_AMBIGUOUS与中文“多条已有连接匹配此地址、端口和用户名，请整理重复连接后再覆盖导入。”。名称映射仅在本次请求内，不修改其他记录；唯一匹配仍按原ID更新，没有匹配仍新增。

连接匹配键改为JSON编码的地址/端口/用户名三元组，避免直接使用冒号拼接。该变更不新增共享模块，也没有新增对远端资源的调用。仍使用原用户范围查询，不把导入文件中的主机ID视为覆盖授权。

真实HTTP→仓储→SQLite新增两个场景：预建两条同目标不同名称/备注主机，分别通过JSON和SSH配置请求覆盖。修复前两项错误updated=1；修复后failed=1、updated/success=0，完整解密主机快照保持不变。全导入HTTP、批量路由与停用配置共3文件31项通过。日志.cache/import-target-before.log、import-target-final.log。

本轮不实现完整覆盖差异展示，不声明预览与提交间有版本绑定，也未验证覆盖已有运行中连接的资源状态。本轮后端修复尚未打入目录包。A22保持未完全验收，整体60/79。未推送Git或触发Actions。
