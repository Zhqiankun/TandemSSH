# AI/MCP 文件传输与文件流程

状态：实施中。本轮建立二进制传输动作、权限和结果契约、可组合执行器及中文结果显示。生产本地授权已继续接入，详见[任务本地文件授权](29-local-file-grants.md)；AI/MCP 工具和保存流程文件步骤尚未接入；MCP 仍为 24 项工具。本文件不把注入测试端口的核心验证当成可供用户完整操作的自动传输功能。

## 目标与依赖方向

完整目标是用户为任务选择本地来源/目标后，AI/MCP 或保存流程可以组合“上传产物 → 同一会话执行命令 → 检查状态 → 下载结果”。每步有独立操作 ID、权限判断、进度、结果与接管行为。自动模式在本次授权范围内继续；协同模式逐项批准。命令规则、远端文件规则和本地文件授权同时生效，命令白名单不能提供本地文件访问。

文件责任：types/file-transfer.ts 拥有跨模块动作/结果 DTO；collaboration/policies/file-policy.ts 把上传映射为远端 write、下载映射为 read；operations/file-result.ts 校验最终结果；files/automated-transfers.ts 拥有二进制传输用例和有界进度记录。UploadService、DownloadService、UploadSourceStore、DownloadSink 分别继续负责远端上传、远端下载、本地来源与本地提交。不创建第二套分块或覆盖算法。

核心通过 FileExecutorPort 组合进 OperationGateway。TaskLocalTransferPort 是本地授权的公开适配契约；不得由 MCP、模型或 HTTP JSON 对象直接实现。生产原生适配将负责真实来源选择、目标版本、所属用户/任务/会话和撤销；核心只接受已验证的本地授权 ID 与版本。业务用例不依赖页面内部文件，也不通过 renderer 转发传输数据。

## 动作与结果契约

file.upload / file.download 包含远端 path、可选 canonicalPath、localGrantId、localVersion、明确 overwrite 与操作超时。没有 raw localPath 或文件正文。上传匹配远端写范围，下载匹配远端读范围；原路径与规范路径都须通过拒绝优先规则。覆盖标记只是动作意图，不能替代本地授权或远端规则。

准备阶段只验证本地能力的内存元数据，不打开 SSH、不读取本地文件、不产生副作用。真正执行在网关已授权、意图审计完成后开始。每个本地/远端块、读取后的数据交接以及最终提交前都再次检查控制权和本地能力。复用当前已认证 SSH 的 SFTP 通道；生产适配还须绑定当前服务器身份、主机密钥和连接代次。

结果 transfer 只返回方向、能力 ID/版本、传输 ID、确认字节数、总字节数、整体校验、摘要和待清理标记。远端临时路径可以随文件结果显示；本地绝对路径和正文不进入公共操作 DTO。成功必须确认全部字节、提供 SHA-256 且无未处理临时文件。失败/未知不能假报成功，也不能自动重复提交。未知结果与待清理记录不被普通过期回收或清除。

进度记录按用户与任务/会话隔离，最多 128 条、每用户 32 条；无待核实/待清理结果的结束记录闲置 15 分钟后可回收，也提供明确释放入口。当前核心尚未接入用户可用的传输状态工具，后续适配必须负责释放和展示。

## 已实现的执行与控制

AutomatedTransfers 通过受控端口取得本地来源或落盘对象，复用 UploadService / DownloadService 完成分块、摘要、源/目标基线和提交。不把 SFTP 操作写入 PTY。下载提交前先复核远端来源，上传提交前复核本地来源，包括空文件。资源关闭只结束句柄/通道，不删除无法确认的目标或自动重试。

UploadSourceStore 的内部 check/chunk 增加可选授权回调，块内读循环同样检查；DownloadSink 的内部 choose 接收可选授权回调，并在既有 guard 处检查，包括最终 OS 提交之前。现有 renderer IPC 没有开放传入回调的能力，手工传输入口继续使用既有行为。

新增中文 FileTransferResult 显示已确认/总字节数、整体校验和待清理提示，并接入任务操作卡。它不会把部分字节或仅结束状态显示为完整内容校验成功。

联合场景发现：已存在任务授权时，协同模式的一次性命令确认原来没有计入同一个网关预算。现已统一扣减，保持无任务预授权的独立逐项批准行为；旧/过期/耗尽的任务预算不能通过逐项批准变为无限执行。该调整不限制人工直接输入终端的自由接管。

## 生产本地授权与后续步骤

下一阶段使用 Electron 已有 fork 私有 IPC，避免新增网络监听。文件 I/O 在后台任务网关所在进程执行，使本地最终写入与控制权守卫处于同一进程，不依赖异步跨进程撤权消息追赶最后一次提交。

拟定握手：登录人工在任务接口创建短期、单次选择票据；票据绑定用户、任务、会话、当前服务器身份及允许的传输方向。可信主窗口通过受限 preload 调用原生选择器，将真实选择结果经父子私有 IPC 交回后台兑换；后台只消费有效票据并用现有原生文件存储建立能力。MCP 和模型既不能创建人工选择票据，也不能提交任意路径来兑换本地能力。关闭窗口、退出登录、任务结束、票据过期或撤销应拒绝迟到结果。

本地授权界面须显示来源/目标、读写方向、是否允许覆盖和任务范围；下载目录中的目标名称需经过现有 Windows 名称、链接和目标基线检查。文件批次复用目录预览与逐项规则，不因一个文件被允许而隐含整棵目录权限。能力元数据只向所属任务提供需要的显示名称、大小与版本。

随后接入任务文件执行器生产组合、进度/取消/恢复、AI 与 MCP 传输工具，扩展 WorkflowDefinition/编译器和中文流程库，使文件步骤与命令步骤共用顺序、失败停止、恢复位置和任务预算。尚未接入的阶段不暴露可绕过约束的临时工具。
