# 进程监控缺失值与运行状态修复

## 问题

空计数被 Number('') 解析为 0，总进程再减表头得到 -1；运行中计数失败时，已读取的总数也会丢失。旧 grep ' R ' 漏掉 R+、Rs，并可能把命令参数中的 R 误算为进程状态。

## 实现

processes-collector 独立处理进程列表、总数和运行数。合法计数必须为安全非负整数，总数保留表头扣除约定；缺失、负数、小数或不安全值返回 null。单项失败保留其他已知样本。非法 PID/CPU/内存行不再伪装为零占用。

固定采样目录使用 LC_ALL=C 保持表头和数字格式稳定。总数与运行状态使用 awk 流式统计；运行数按 STAT 列以 R 开头判断，无运行进程时成功返回 0，缺少输入/状态表头时返回失败。进程列表输出仍最多表头加 10 行。没有将完整 ps 输出装入 Shell 变量，没有临时远端文件或新的用户命令入口。

## 验证

修复前 8 个采集测试中 6 个失败，直接复现 -1、虚假零值及局部数据丢失。

新增真实 Git Bash 命令测试，ps 使用本次进程内固定夹具：R+/Rs 正确计数，睡眠进程参数中的 R 不计数，零运行数退出成功，20 条输入的列表有界为 11 行，ps 无输出失败不会被管道当成成功。此测试证明真实 Shell/awk 行为，不等同于 Linux 服务器实测。

最终监控目录 19 文件、136 项全部通过，TypeScript 和 ESLint 通过。采集 API 的字段保持不变，既有固定命令审计与监控范围继续生效。

不同采样命令并非原子快照，进程快速创建/退出可能让各项属于略有不同的时刻。完整服务器兼容矩阵及其他监控指标仍需继续验收。所有改动只在本地，未提交、推送或发布。
