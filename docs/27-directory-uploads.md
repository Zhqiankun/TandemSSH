# 目录上传批次

状态：实施中。目标覆盖目录/多文件上传、空目录、改名/跳过/明确合并覆盖、逐项结果、接管、取消、恢复和记录；不会用文件成功代替整个目录成功。

本轮先建立远端预览和目录写入用例，再接入原生来源选择与现有 UploadQueue。UploadTreeService 拥有远端清单、版本、策略和目录结果；UploadService 继续拥有唯一的分块写入和提交校验。SftpFileIO 只提供非递归 mkdir 等底层原语。HTTP 复用人工身份校验；自动/MCP 传输仍需单独接入相同任务网关。

预览只读，不提前创建目录。已有文件保存完整摘要基线；已有目录需明确合并。路径只由根目录、父 ID 与名称构造，拒绝路径穿越和子目录链接。确认绑定版本，目录创建使用文件用例的接管检查、路径提交锁和前后操作记录；不调用 Shell、sudo 或 chmod 777。新目录请求权限 0700，实际属性与结果一并记录。创建后无法核实的结果保留为 unknown，不能自动重试。

文件准备会绑定批次的服务器、路径、父目录及覆盖基线，再交给现有分块服务。SFTP 缺少可移植的目录 inode/CAS，不承诺对服务器外部进程的原子隔离；同路径同属性目录被替换的剩余竞态需如实保留。

来源侧将由原生选择/真实拖拽文件对象建立只读能力，枚举空目录并拒绝跟随链接；读取按块受控。界面只编排预览与队列，不能提供任意本地读取路径。批次文件共用 UploadQueue，并在完成/清除时回收预览，避免大量文件占满旧记录额度。

验收使用真实 SFTP/本地文件，覆盖预览无写入、合并覆盖、目标变化、链接、取消、权限失败、未知结果、API Key/跨用户拒绝、接管及既有上传/协同回归。当前本文件是实现方案，不是全部功能已完成的声明。

## 本轮已实现的核心

新增 types/upload-tree.ts 与 backend/files/upload-tree-service.ts，提供只读目标预览、层级/重名检查、版本确认、目录创建、结果查询、保活、取消与释放。生产入口复用 UploadPorts 的目标解析、beginWrite、共享路径锁和审计。SftpFileIO 增加非递归 mkdir；不引入 Shell/Sudo 路径。

UploadService 增加内部 UploadConstraint，绑定预览中的服务器、路径、已有文件摘要与父目录属性；准备及后续操作重查约束。新增 touch/forget 支持长任务及记录回收，513 次准备/取消/释放后仍可继续使用；释放不会删除最终文件，也不能清除未知或仍有临时文件的记录。

electron/upload-sources.cjs 拥有本地来源选择、受限枚举和块读取；upload-source-ipc.cjs 校验主窗口顶层页面，并在导航/账号重置时撤销能力。preload 使用 Electron webUtils.getPathForFile 转换真实选择的 File 对象，并禁止通用 invoke 直接访问这个保留通道；字符串路径或伪造的 File 不能由该桥接入口获得读取权限。链接和特殊文件排除，读取时核对父目录、文件身份、大小和时间版本。

types/upload-source.ts 和 uploads/native-source.ts 提供异步块来源适配。现有 UploadQueue 继续处理全部分块传输，支持原生异步来源；摘要准备前后及提交前复核来源，空文件同样检查。没有复制第二套文件上传状态机。

真实 SFTP/文件与队列联合回归 15 个文件、120 项通过（.cache/upload-tree-core-final-regression.log），包含目录创建、空目录、明确合并/覆盖、接管、锁冲突、父目录替换、未知结果、HTTP/IPC 身份、来源变化、真实 File 转换边界与既有自动/协同终端。类型和改动模块 lint 通过，中文错误键已补齐。Windows 夹具只模型化 POSIX 所有者属性，不能替代真实 Linux/OpenSSH 权限验收。

## 继续实施的部分

当前尚未把目录上传批次面板接到 FileManager，旧目录拖拽中提前创建目录并忽略异常的分支仍需替换。接下来以原生来源选择和 UploadTreePreview 驱动中文预览；批次只编排目录结果、成员、保活和释放，文件继续共用 UploadQueue 的并发、暂停恢复与校验。取消必须保留未知结果，已完成文件不能重复覆盖，整批跳过不得接管 AI。

仍保留原始完整范围：目录/多文件/空目录与拖拽、AI/MCP 文件传输和文件流程、跨重启检查点、历史草稿与凭据统一、基础认证/隧道/监控、实际跨版本升级及最终验收。本轮核心通过不代表整目录上传界面已完成。
