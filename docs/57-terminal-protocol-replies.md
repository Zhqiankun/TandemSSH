# 终端协议回复与人工接管

真实 Linux 桌面验收发现：Alpine Shell 请求光标位置后，xterm 自动回传 `ESC[24;17R`，原客户端把它作为普通 `input` 发送。服务端因此调用人工输入入口、递增 controlEpoch 并撤销刚授权的自动任务。诊断记录中明确出现 grant → 自动光标回报 → takeover；不是实际人工按键。

边界：`types/terminal-replies.ts` 定义支持的数字型终端回复及匹配规则；后端会话模块跟踪真实 SSH 输出中的查询，队列最多 64 项、10 秒过期，控制接管/断线/关闭清空。OSC/DCS 等控制字符串中的伪查询不算请求。`SessionControl` 验证待回复请求后才允许协议写入，协议回复不改变控制权；普通 input 路径保持先接管再写。

前端通过 xterm 公共 CSI 解析回调识别同步自动回复，判别标记在微任务结束时失效，避免把用户的功能键当作协议回复。新服务端在连接和回放消息中声明能力；旧服务端继续使用原消息格式。历史回放标记为 replay，不回应旧查询。不会根据看起来像 ANSI 的字符串直接绕过人工接管。

新 WebSocket 消息为 `{type:"terminal-reply",data:string}`。服务端要求已注册的可写参与者；有在线所有者时只接受所有者回复，无所有者时允许已有可写参与者回应。只读和未知连接不能使用此通道。仅支持光标位置、设备状态、主/次设备属性的数字型回复；文本、换行、过期、重复及无请求回复均拒绝。回复仍写入原 SSH 流，不创建额外 Shell。

验证须覆盖：真实 Linux 的桌面授权与 MCP 自动/协作继续执行；实际人工输入继续接管；伪造回复不能发命令；分包查询、OSC/DCS、过期、队列上限、重连、只读参与者与历史回放。完整产品验收范围保持不变。

## 验证结果（2026-09-10）

专项测试 4 个文件、50 项通过：查询分类与分包、控制字符串取消、最多 64 项和 10 秒过期、重复/伪造/夹带命令拒绝、重连清理、普通人工输入撤销旧控制租约、会话所有者/只读参与者权限，以及真实 xterm 实例的自动回复、回放和功能键区分。前后端类型检查、构建通过；lint 为 0 个错误、100 个既有警告。真实 Windows 客户端连接 Alpine，经 MCP 完成自动和逐条审批模式，并验证实际人工接管、人工输入后再次交还，详见 [Linux 实机记录](56-linux-ssh-acceptance.md)。

缺陷证据位于本机 `.cache/desktop-observation-report-8ac35053-eeb7-421a-8ea3-db88a41b83c4/websocket-control.jsonl` 和 `tasks-before-cleanup.json`：授权后客户端把自动光标回复作为 `input`，导致任务暂停。修复后的记录为 `.cache/desktop-observation-report-3407fc7f-156d-4338-97a3-1b7b847f9c3a`，同类回复通过 `terminal-reply` 发送且不改变控制租约；人工输入及“立即接管”仍按原规则撤销自动控制。

测试曾使用一个自身会产生 DECRQSS 回复的 DCS 字符串，导致对“无输出”的预期错误；改为不产生该回复的测试输入后复测。产品只支持前文列出的数字回复，其他终端协议未在本批宣称覆盖。

新增公共模块仅承载前后端共有的协议种类与匹配规则，由终端模块维护；不依赖 UI、任务运行时或 SSH 实现。状态和过期由后端会话持有，xterm 生命周期由前端适配器持有，WebSocket 层只路由与校验参与者。无数据库变更、无新授权持久化。

全量回归、Windows PTY 失败与旧实现对照均按事实记录在 [Linux 验收记录](56-linux-ssh-acceptance.md)。本批专项通过不等于完整产品或 Windows 本机伪终端所有用例通过；未解决问题继续纳入原交付目标。
