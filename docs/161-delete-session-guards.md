# 删除批次在会话切换或组件卸载后停止

2026-09-12。复查 119 的批量删除实现发现：sudo 分支已有会话检查，但普通删除及经确认的永久删除后备分支没有逐项检查，旧确认或正在执行的批次可能在连接切换后继续提交下一项。

## 文件责任与契约

file-batch.ts 仍是文件管理功能内部的顺序批处理模块，新增可选 assertCurrent 回调；每项动作前检查，动作确认后先累加完成数再检查。默认回调不改变既有调用者行为，错误仍作为批次结果返回，已派发请求不会被宣称撤销。assertFileSession 增加组件存活条件。

FileManager.tsx 负责将原会话和组件生命周期传入普通删除及永久删除分支。旧确认在任何列表修改或远端请求之前拒绝；ensureSSHConnection 返回后再检查；批次中途变化则停止后续项目。卸载后不更新页面或弹出新提示，只使原目录缓存失效。原 undoMounted 改名 fileManagerMounted，以准确表示组件生命周期，撤销逻辑保持原有检查。

中英文新增 deleteSessionChanged：说明停止原因、已确认数、结果未确认或未执行数，要求刷新原目录核对。没有新增共享抽象、后端 API、权限绕过或自动永久删除行为。

## 验证

两个测试文件 11 项通过：旧确认在会话已切换/组件已卸载时零请求；第一项尚未返回时切换/卸载，确认返回后计数为 1、第二第三项零请求；既有响应丢失不重试、空批次、顺序计数及乐观列表恢复继续通过。翻译缺失键 0。

初次类型检查发现永久删除错误分支未显式缩窄联合类型，已添加 ok === false 条件并重新检查。证据为生产调用点审查加异步批次/列表测试；本轮没有实际连接服务器执行删除，也没有完成桌面删除端到端验收，因此 B09 仍未全部完成。
最终 tsc -b 通过；ESLint 零错误，仅 FileManager 既有 windowId 未使用警告；git diff --check 通过。
