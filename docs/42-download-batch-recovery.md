# 下载批次跨重启恢复

2026-09-09，继续实现人工目录/多选下载批次的加密保存、重启恢复和逐项结果。上传批次已交付，本文不缩减目录下载、AI/MCP/流程恢复及完整验收范围。

## 模块责任与依赖

主智能体负责本轮设计、实现和验证。DownloadTreeService 保存固定来源集合，DownloadService 提供已准备文件的真实主机/版本/摘要检查点；HTTP 只签发人工当前用户的一次性意图，主进程通过私有 IPC 兑换来源数据。页面不能自行提交可信来源检查点。

桌面主进程持有 DownloadDirectoryTargets、DownloadSink 和下载批次加密记录。批次复用现有系统加密接口、原生目录检查点和唯一的分块落盘实现。保存目录之前，成员部分文件必须已持久化交接；成功后再释放旧目录/来源记录。恢复必须重新选择目标根目录、核验目录身份及完成收据、确认原计划及覆盖，新能力先保持暂停。

关闭窗口先拒绝旧作用域的请求，再等待在途文件操作结束、同步已确认字节、持久化新的检查点和释放句柄。未知提交保留独立状态，只能核对，不自动重复提交；取消与清理不递归删除用户目录，已完成文件保留。

依赖方向：中文界面 → 人工票据/主进程批次协调 → 来源/原生目录及文件公开用例 → SSH/SFTP、文件系统和系统加密。页面不读加密文件，原生文件业务不依赖后台私有存储，不增加第二套下载传输实现。

## 验收

1. 保存失败保留原暂停成员，成功交接后旧能力不可继续写入。
2. 真正写入多个文件及空目录，在新实例/新连接恢复未完成成员，已完成文件不重写。
3. 错误用户、窗口、服务器公钥、来源属性/摘要、目标根目录或部分文件变化时拒绝。
4. 关闭/中断时保留已保存部分文件，恢复后用户主动继续前无新文件写入。
5. 未知提交先记录，再核对；单个结果失败不能伪装成整批成功。
6. 类型、模块 lint、相关文件/自动/协作/MCP 回归和真实 Windows 正常重启/强制中断分别取得证据。

使用 app 的既有 tsc、eslint、vitest、构建与 Windows 打包入口。失败记录复现、实际副作用、修复与复测；核心、界面和实际应用验收分别报告。

## 已实现的核心与责任文件

- download-batch-recovery-tickets.ts / download-batch-recovery-bridge.ts 提供人工批次意图、一次性领取、固定来源树恢复、逐项来源证明和窗口关闭释放。票据绑定实际用户和窗口，不能从 HTTP 输入可信检查点；私有进程通道才传递来源快照。
- DownloadTreeService.memberProof 核对文件确实属于原集合、用户和主机，且路径与属性匹配；DownloadService.recoveryMetadata 导出已准备/暂停/验证来源的内部摘要。原单文件 checkpoint 仍要求已暂停，未放宽原入口。
- electron/download-batch-vault.cjs / download-batch-record.cjs 拥有独立的下载批次格式、系统加密接口、用户分区和独占写入/领取。每条最多 32 MiB、每用户 8 条/256 MiB；不回退明文。来源与本地部分文件必须匹配大小、摘要、分块清单和固定目标映射。
- DownloadSink.suspendBatch 持有全部成员至一次持久化回调完成；失败时保留可继续的暂停记录，成功才释放原能力。preserveBatch 先撤销写入、等待在途操作、同步已确认数据，再释放句柄并返回新检查点。
- DownloadDirectoryTargets 在成员被同一保存事务持有时可导出目录检查点，releaseRecovery 只释放由持久化记录接管的内存视图。原目录创建、完整性检查和分块落盘仍由既有用例拥有，没有新增第二套下载器。
- 原生目录检查点补存原计划 action；恢复继续清除旧 action 并要求新的确认，不把历史选择当作授权。新原生记录模块已列入 asarUnpack，包探针会实际加载。

这些是生产接线所需的内部接口，下载批次 HTTP/主进程操作编排及中文入口尚未接入，不能把它们描述成用户已经可以整批重启恢复。

## 下一步生产接线

1. 将来源票据加入人工下载路由，在 starter 注册私有批次桥接；页面只能提交来源/条目 ID，由后台签发实际快照。
2. 主进程批次协调器复用现有下载恢复的窗口 scope，持有用户、目标目录、成员及领取状态。原生目录 file 适配传入后台 sourceId，私有通道核对来源摘要后才记录成员。
3. 初次保存将目录和全部部分文件写入同一记录。恢复后的新文件在传输前持久化本地检查点，最终改名/提交前先记录 committing；未知状态不能重新提交。
4. 批次 reset 必须先于旧 directories.reset / sink.reset：先拒绝旧窗口作用域，再等待成员收敛、保存偏移并释放原生视图，避免旧取消分支删除已保存部分文件。完成回调要支持队列重复确认，不提前释放仍在使用的来源。
5. DownloadQueue / DownloadBatches 增加暂停整批交接、容量预留和恢复后等待继续。中文入口展示原计划，重新选择同一目标根目录并确认覆盖；已完成项与未决项分别核对，不能混成整批成功。
6. 最后执行真实 Windows 正常重启、进程中断、部分文件续传和内容校验，并复验自动/协作/MCP。上述接线尚未实施，不能把本轮核心通过当作界面交付。
