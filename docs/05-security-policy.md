# 策略、凭据与安全边界

状态：v0.2 安全设计。本文描述需要实现和验证的要求，不是当前已经通过的安全审计。

## 1. 威胁与保护目标

| 来源 | 可能的问题 | 设计约束 |
| --- | --- | --- |
| 模型输出或远端日志 | 提示注入、错误命令、请求读取秘密 | 输出视为数据；工具调用经过固定网关、策略和目标授权 |
| 被攻陷的服务器 | 指纹变化、恶意文件名、输出控制序列 | 主机信任校验、路径编码、终端渲染边界 |
| 外部 MCP 客户端 | 伪造身份、越权读取、接管后继续执行 | 配对身份、范围授权、撤销、epoch 校验 |
| 导入的连接/流程/规则 | 隐藏脚本、默认放宽权限、夹带凭据 | 预览、验证、无自动执行、策略独立确认 |
| 本机文件读取者 | 获取连接密码、模型 Key 或敏感历史 | OS 凭据库、脱敏、可清理记录 |
| 崩溃、超时或重试 | 重复部署、误判成功、队列失控 | 有界任务、幂等、unknown 状态、人工核实 |

用户本机管理员或已控制应用主进程的攻击者不在本地凭据加密可抵御的范围内。远端 OS 权限是实际执行边界，客户端规则不能代替服务器账号隔离。

## 2. 黑白名单的适用入口

硬限制覆盖：内置 AI、外部 MCP、命令流程和受控命令输入框。任何入口都不能跳过统一动作网关。

人工直接操作 PTY 的按键流不等同于完整命令。用户已确认保留人工自由接管；首版提供风险提示与记录，不宣称能强制校验 vim、REPL、分段粘贴等所有行为。需要硬规则校验时使用受控命令入口；远端账号权限仍由操作系统执行。

“人工发起的流程”不是自由终端例外，流程的每一步仍经过硬限制。

## 3. 规则类型

| 类型 | 作用 |
| --- | --- |
| deny | 明确阻止，不可用临时批准覆盖 |
| confirm | 允许提出动作，但需要与当前快照绑定的人工批准 |
| allow | 通过该范围的允许集合；仍受工作方式、审批和其他范围限制 |

首版匹配方式：固定命令、程序与参数约束、路径范围；高级完整命令正则作为受限能力。正则使用有界、可预判运行代价的实现，限制长度与支持的语法，不直接运行任意 JavaScript 正则作为安全核心。

“只读”是策略分类，不是单凭程序名得出的事实。例如 shell、解释器、容器工具、编辑器或用户可修改的脚本都可能执行其他程序。

## 4. 作用范围和合并顺序

适用范围：全局 → 所属服务器组 → 服务器 → 客户端/任务授权。服务器属于多个组时，各组约束共同生效。

1. 先验证主体、连接授权、操作类型和输入结构。
2. 任意适用范围命中 deny，最终 deny。
3. 每一层已定义的允许集合均需满足；同层集合内匹配任意一条 allow 即通过该层，多层之间取交集。
4. 文件路径与 sudo 等独立权限同样取交集，不由命令 allow 自动授予。
5. 任意 confirm 规则或协同模式要求确认时，需要有效批准。协同模式逐步确认；自动模式可使用人工预先签发、覆盖本次动作的任务授权，未覆盖则等待批准。
6. 没有明确 allow 时，默认返回 confirm；严格白名单模式返回 deny。
7. 无法可靠解析的脚本/交互输入为 unknown；普通模式等待人工判断，严格白名单模式拒绝。

任务授权只能缩小上级范围，不能覆盖全局拒绝或扩大服务器列表。AI 不能自行编辑规则、签发批准或增加预算。

用户已确认允许本任务内预授权重启服务、覆盖文件等操作。任务授权必须明确任务、目标、命令/参数或文件路径范围、允许的副作用、有效期和次数/预算，不能仅保存“本任务全部允许”。任意 deny 优先；无法可靠判定的 unknown 不被宽泛授权自动放行。接管、重连、策略变更或任务结束使旧授权失效，交还时由人工核对后生成新授权。

## 5. 规则格式示例

以下示例假设程序身份解析已经通过可信执行环境检查；仅展示数据形态。

```json
{
  "schemaVersion": 1,
  "id": "global-automation",
  "revision": 1,
  "scope": { "type": "global" },
  "origins": ["agent", "mcp", "workflow", "command-panel"],
  "defaultDecision": "confirm",
  "strictAllowlist": false,
  "rules": [
    {
      "id": "deny-reboot",
      "effect": "deny",
      "actionType": "terminal.command",
      "match": { "kind": "program", "program": "reboot" },
      "reason": "自动化不允许重启服务器"
    },
    {
      "id": "allow-disk-summary",
      "effect": "allow",
      "actionType": "terminal.command",
      "match": { "kind": "program-args", "program": "df", "args": ["-h"] },
      "reason": "允许查看磁盘用量"
    },
    {
      "id": "confirm-service-update",
      "effect": "confirm",
      "actionType": "terminal.command",
      "match": { "kind": "program-args", "program": "docker", "args": ["compose", "up", "-d"] },
      "reason": "更新服务需人工确认"
    }
  ]
}
```

规则编辑器应从结构化字段生成配置。正则拒绝规则、目录范围和服务器绑定需使用各自明确的 schema，不能把任意 JSON 键默默作为可执行参数。

## 6. 黑白名单不能成为错误的安全承诺

- 不按分号简单切割 Shell；转义、换行、管道、重定向、命令替换与子 Shell 都可能改变语义。
- 固定程序名也可能受 alias、函数、PATH、工作目录和加载配置影响。自动执行前要确认支持的 Shell 环境和命令解析状态；不能确认则返回 unknown。
- 允许 `bash -c`、Python 任意代码、上传脚本后执行等能力，实际上允许了更大的执行范围，UI 必须显示这一点。
- 路径白名单限制 SFTP/API 文件入口，不能阻止已获任意 Shell 权限的命令读取其他路径。
- “白名单脚本路径”若可由同一账号随意修改，就不是固定安全脚本。高要求部署使用远端由独立权限管理的包装器。
- 模型建议的低风险等级不能替代系统规则；黑名单匹配不到不等于安全。

## 7. 执行与接管的安全顺序

动作快照 → 目标与权限检查 → 策略判断 → 取得批准 → 记录意图 → 入队 → 派发前再检查 → 发送 → 记录结果。

接管、重连、规则变更和凭据身份变化使未执行批准失效。对于在途传输/命令，保留可见状态并提供取消或核实入口；不声称取消能撤销远端副作用。

## 8. SSH 凭据和主机信任

- 私钥优先保存本机路径或 SSH agent 引用；密码和口令进入 OS 凭据库。
- 普通连接配置、导出文件和 MCP 结果只含 credentialRef，不含凭据原文。
- OS 安全存储不可用时停止持久化，可选择仅在内存中用于当前会话；不回退明文。
- 首次连接需人工核验指纹；变化后阻断，不设置“自动相信所有主机”。
- 认证挑战、验证码和 sudo 密码通过专用人工输入处理，不由模型索取或代存。
- SSH 数据传输的机密性不代表终端输出可以任意发送到模型端点。

## 9. 模型端点与信息流

模型 Key 存于 OS 凭据库。界面只显示脱敏状态；默认不把 Key 放入命令行、环境导出或流程参数。

远程端点默认要求 HTTPS；本地模型可显式使用回环 HTTP。自定义 CA 是独立信任配置，不能通过全局关闭 TLS 校验解决连接问题。端点切换时不能自动把原端点的 Key 带给新地址。

API 请求只包含获准上下文。秘密输入片段不写日志、不送模型；未知秘密、远端意外回显和用户自行粘贴的凭据无法靠自动脱敏百分百识别。提供上下文预览、暂停发送和手工移除能力，不宣传自动脱敏为绝对保护。

工具响应中的内容始终作为数据，不能修改系统规则、自动授权或诱导访问另一个会话。

## 10. 桌面和本机接口

Renderer 关闭 Node 集成，开启上下文隔离和沙箱；preload 只提供固定公开 API。每个 IPC 调用检查来源、输入 schema 和资源范围，不暴露任意函数名执行、完整环境变量或裸文件读写入口。

若底座现有配置不满足上述要求，作为改造差异记录和测试，不能仅保留新模块安全而让旧入口绕过。文件编辑草稿如需落盘必须加密；保存冲突、临时文件与元数据处理见[文件工作台](09-base-features.md)。

生产包不启用远程调试端口、不加载远程页面作为应用主界面；升级包需要完整性与发布来源验证。

首版 MCP 走 stdio + 已配对本机 IPC，使用 OS 访问权限和每客户端授权。外部客户端退出/被撤销后取消尚未发送的动作。在途远端效果仍可能需要人工核实。

若选定底座已经使用本机 HTTP/WebSocket 接口，首版就必须完成认证、Origin/Host 校验、CSRF、令牌泄露、速率限制与监听地址评审；不会把“仅监听 localhost”当成无需认证的理由。公网服务仍不属于首版范围。

## 11. 日志、录制与导出

- 默认记录操作元数据、规则结果和脱敏输出片段；用户已确认本机保留 7 天/最多 100 MB，任一上限先到即清理最旧记录，上限可配置。
- 不默认落盘原始 PTY 字节流；开启完整录制时展示风险、加密状态和保留策略。
- 审计存储故障时，暂停新的 AI/MCP/流程副作用；人工接管不能因审计失败被锁死，但需持续显示记录不完整。
- 导出前预览，秘密引用不导出其值；规则、流程和普通连接可分别导出。
- 加密数据跨设备迁移需要单独设计密钥迁移；不能直接复制 OS 绑定密文就承诺可恢复。

## 12. 安全验收重点

接管竞态、跨主机错发、参数注入、规则组合绕过、过期审批、重放请求、主机指纹变化、加密失败、路径逃逸、恶意输出、记录缺口、未知执行结果和导入时自动执行，均列入[交付计划](06-delivery.md)。公开发布前的测试必须有版本、复现步骤和实际结果。
